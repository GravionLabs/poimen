# Spaces, layouts, projects and trust

Creating spaces, layouts, templates, the project file, worktrees and trust. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `src-tauri/crates/poimen-server/src/create.rs`: `space.create` with `layout` (the default; `layout: false` is the empty space `Client::create_space` asks for, `Client::create_space_with` sends the rest): `prepare` reads the project files once into `trust::Sources`, the user config of `Config.home` (`~/.config/poimen/config.json`: `trustedProjects`, `spaceTemplates`, `spaces.layout`, `harnesses`, through `poimen_core::space_layout::UserSpaces`) on every request, and runs `trust::gate`: `Ask` answers `trust_required` (root, files, hash, commands, layout) and creates nothing, a fresh `trust` answer is stored through `settings::trust_project` before the first terminal, `Strip` builds without commands and setup. `lib.rs::build_space` builds the tree under the one lock (`build_tabs`: root pane in a new tab, later panes through `Layout::split`, then a `setup` tab) and types the commands once the lock is released (`type_commands`). `repo.ensure` and `worktree.create` (#282, `Client::ensure_repo`/`create_worktree`, `LONG_REQUEST_TIMEOUT`): `poimen_core::repos::ensure` (`reposDir` of the user config, default `~/Source/{owner}/{repo}`; absent path `gh repo clone` through the `repos::Gh` trait, `Server::set_gh` in tests; a clone of that repository `git fetch origin`; anything else `conflict`, never written into) and `poimen_core::worktree::task_worktree` (modes of `tasks::for_dir`); tests `tests/repos.rs` with a bare origin. `worktree.cleanup` (#284, `Client::cleanup_worktrees`): "Clean up merged tasks" in that clone (`repos::locate`: none is `{path: null}`, never cloned) through `poimen_core::worktree::cleanup_merged` (shared with the app's `task_cleanup`: cleanup mode, teardown plan, `cleanup`) with the merged pull requests of the client's `gh`; the server's spaces are the `Spaces` (`ServerSpaces`, closed like `space.close`); tests in `tests/repos.rs` (merged clean, dirty, unpushed, focused, a mode's `cleanup` command, untrusted teardown). `space.apply_layout` (#645, protocol 6, `Client::apply_layout`) runs the same `prepare` (`Wanted::Resolved` or `Wanted::Preset(name)`, a preset of the project file without setup, unknown preset `not_found`) and `build_tabs` into an existing space; tests `tests/space_apply_layout.rs`. `poimen_core::space_layout` (`template_for`, `inputs`, `plan`) is shared with the app's `create_space_with`; the app's poimen backend sends it through `Backend::create_space_with_layout` (#513) and `Backend::apply_layout` (#645). App and server both write `config.json` through `poimen_core::settings::save_with` (read right before the write, one key changed, comments kept, a temp file per writer); `trust_project` reads `trustedProjects` from the text and refuses to overwrite a value it cannot read. Tests: `tests/space_create.rs` (temp home, temp repository, default shell).
- Environment and `setupPolicy` (#992): `project::workspace_env`/`dir_env` build `POIMEN_ROOT_PATH` (`worktree::main_worktree`), `POIMEN_WORKTREE_PATH` and `POIMEN_SPACE`; the server adds them to every terminal in `spawn_terminal` (the client's `env` cannot override them), `ProcessRunner::run` takes an `env` and `run_teardown` passes the same variables plus `POIMEN_BRANCH`. A task adds `POIMEN_ISSUE` and `POIMEN_BRANCH` through `create_space`/`machine_create_space` `env` (`taskEnv` in `core/task-start.ts`, `LayoutRequest.env`, `SpaceCreate.env`). `setupPolicy: "wait"` (`Build.setup_wait`, only with a trusted `setup`): `build_tabs` marks the root `Typing`, wraps the setup command with `marked_setup` (writes `ok`/`fail` into `temp/poimen-setup-<terminal id>`) and `type_after_setup` (a thread, 30 min at most) types the root command on `ok`, else an `echo` notice. Tests: `tests/space_create.rs`.
- `src-tauri/src/project.rs`: the project file `.poimen/config.json` (`layout`, `setup`, `teardown`, `commands[]`, `presets[]`; schema and doc in `docs/project-config.*`); tolerant `load(repo_root)` returning config plus warnings, `project_config` command. Layout precedence lives in `layout::resolve` (project file, deprecated `.agents/herdr-layout.json`, `spaces.layout`, default). `tasks` (modes and `worktreeDir`, merged over the user's in `tasks::for_project`, `get_task_modes(dir)`) is parsed with `settings::parse_tasks`; `start_setup` runs `setup` in a `setup` tab of a new space (only after `trust::gate` allowed it, from `create_space`); `run_teardown`/`teardown_plan` (trust gate, `$SHELL -lc`, 5 min timeout, 1 MB output, `ProcessRunner` faked in tests) run `teardown` before `worktree::cleanup` removes a worktree and from the `project_teardown` command (palette "Project: Run teardown", result dialog `src/app/result-dialog/`); `project_entries`/`project_run` serve the palette entries (`Project: <name>`, `Preset: <name>`; `run_entry` goes through `trust::gate`; an `agent` command is handed back and sent by the frontend `core/project-entries.ts`). `poimen_core::detect` (`Detector` trait, `npm.rs`) lists detected entries (`package.json` scripts) for the palette Scripts tab: commands `detected_entries`/`detected_run` (argv built in `project::run_detected` from a fresh detection, no hash trust, local disk only); a `commands[]` name hides the detected one in `core/command-palette.ts`. `detect/skills.rs` (#1217) lists `.agents/skills`/`.claude/skills` `SKILL.md` front matter as entries with source `skills` and an empty `argv` (`run_detected` never runs one); the frontend `ProjectEntries.runSkill` sends `/<name>` to the space's agents whose harness has `slashSkills` (`harness.rs`, from `get_harnesses`), through the same picker as an agent command.
- `src-tauri/crates/poimen-core/src/worktree.rs` (cleanup wrapper in `src-tauri/src/worktree.rs`): `task_worktree(repo_dir, issue, mode)` creates or reuses the git worktree and branch of an issue (mode's `branch` template, `tasks.worktreeDir` relative to the main worktree, found through `--git-common-dir`). Reuses a worktree that has the branch, adds a worktree for an existing branch, else `git fetch origin` and `-b` from `origin/release/next` or the default branch of `origin`; a path that exists otherwise is an error. Never modifies an existing worktree; git via argv only. The same file holds "Clean up merged tasks" (`task_cleanup(dir, focusedSpace)`, `worktree::cleanup`): candidates are the linked worktrees whose branch is the head of a merged PR (`gh pr list --state merged --json headRefName,number` through `github::Runner`); the first task mode with a `cleanup` command runs it per worktree (expanded and shell-quoted, `{pr}` added to the placeholders, in the repository root) instead of the built-in removal (close the space, `git worktree remove`, then `git branch -d` only when every commit is on a remote branch). Invariants, each tested on temporary repositories: never a dirty (uncommitted or untracked) worktree, the main worktree or the focused space's; never `main`, `master`, `release/*` or the `origin` default branch; never `--force` or `-D`; a space with terminals outside the worktree is not closed. Frontend: `core/task-cleanup.ts` (`TaskCleanup`: on this Mac and every connected machine (#284, `machine_task_cleanup`: merged pull requests from the local `gh`, `worktree.cleanup` on the machine's server, refused unless `Machines::connected_backend`; the focused space only on its own machine), one notice `This Mac <n> removed, <m> left; <machine> ...` (only `<n> removed, <m> left` without machines), log lines `on <machine>`, an untrusted teardown asked once for the machines it concerns), `core/task-log.ts` and the Log tab of the bottom panel list each left worktree with reason and the command to run by hand. Entry points: palette `cleanupTasks` and the space menu (repositories only). `pr_worktree(repo_dir, nr, head_ref)` (command `pr_worktree`) does the same for a pull request: fetches `refs/pull/<nr>/head` from `origin` into local `pr/<nr>` (the head branch itself when it exists on `origin` at that commit), path `../{repo}-pr{nr}`, a branch already checked out in a worktree returns that worktree, a local `pr/<nr>` is only fast-forwarded, a foreign existing path is an error; `worktree_branches(dir)` lists worktrees for the "Open space" / "Check out" buttons of the PR view (`github/pulls.ts`).
- `src-tauri/src/trust.rs`: trust in a project file: `Sources` reads `.poimen/config.json` and `.agents/herdr-layout.json` once (hash, listed commands and layout all come from that read), `gate` decides `Run`/`Strip`/`Ask` against `trustedProjects` of the user config (root to SHA-256). `create_space` (and `space.create`/`space.apply_layout` of poimen-server, `create.rs`) asks before creating anything; any future runner of setup/teardown/commands/presets must go through `gate` and use the same `Sources`. Frontend: `src/app/trust-dialog/`, `SpaceActions.trust`, settings section "Trusted projects".
- Spaces after a server restart (#579): spaces persist with their `cwd`; terminals come back only when their PTY host is adopted (#604), so a space can still be left without terminals. `Space.cwd` comes from the snapshot (`toSnapshot`); `workspaceDirs`/`spaceContaining` use it first, then the pane directories, `spaceRepoDir` falls back to it (`SpaceNode.repo`), `readRepos` asks for it. `rebuild_space(spaceId, decision, confirmed)` (`lib.rs::rebuild_space_with`, shares `layout_inputs`/`plan_layout`/`run_setup` with `create_space`): a space without terminals gets its layout again in its directory (project file > template > `spaces.layout` > default, nothing stored), through `trust::gate` (on the poimen backend the confirmed build and the trust answer go to `space.apply_layout`, which stores the trust); unconfirmed it builds only when no agent pane (`is_agent_command` against the harnesses), no setup and nothing to trust, else `consent` with reasons; `missing` for a directory that is gone; a space with terminals is `not_empty`. Frontend `core/space-rebuild.ts` (`SpaceRebuild`, started in `App`): one check per backend session (`SpacesStore.onSessionStart`: first snapshot at start, after `poimen.disconnected` and after a started server), marks per space shown in the sidebar ("Rebuild" button, "Rebuilding…", "Directory gone", "Not rebuilt"); a confirmed rebuild asks trust through `SpaceActions.askTrust(…, without = true)`. Still app-side on both backends: the poimen server has no request to build a layout into an existing space, so a rebuild creates the root terminal and runs `layout::apply`, whose splits go through `tab.split` there.
- First start: `templates::seeded` (pure: the layout with an agent pane per installed `claude`/`copilot` and a `shell` pane, the default template's agent) and `seed_values`; `settings::seed_defaults` writes `spaces.layout` and `spaceTemplates` only when the config has neither key (`has_seeded_keys`, tolerant of comments); the `seed_space_defaults` command runs once from `app.ts`, the flag `defaultsSeeded` lives in the UI state (`core/ui-state.ts`), never in `config.json`. `default_spaces_layout` returns the seeded layout for the installed agents; the Spaces page's "Default" entry is the template without `match`. An existing installation whose config has neither `spaces.layout` nor `spaceTemplates` gets the seeded layout and default template on the first start of this version, so a new space then uses the seeded layout instead of the built-in default and gets the default template's agent.
- Named layouts (#609, ADR 0011): `poimen_core::layout` holds the tab shape (`TabLayout`, `Tab`, `Node`, `Place`, `NamedLayout`; `Layout::to_tabs` converts `panes[]` on read, `parse_tabs_value` reads both shapes) and `layout::resolve`/`resolve_origin` return it (project file > deprecated file > config > default). `settings::parse_layouts` reads `layouts[]`; `space_layout::inputs(dir, &UserSpaces, ..)` resolves a template's name (`Template.layout_name`) or inline layout, with `spaces.layout` as the layout `default`, and `plan` returns the `TabLayout` the server (`create.rs`, `build_tabs`) and the app (`rebuild_space` consent) use. `TabLayout::pane_tabs`/`panes` flatten each tab back to ordered `panes[]` (unnamed or repeated leaf names get a generated unique one; `cwd` and `place` are not carried yet); the server builds every tab in order, children after their parent, until the parent link of #582 exists. An unknown `split.from` is a parse error in both shapes. Project files (#611): `layout` and `presets[]` take either shape (`project::parse_preset`; trust lists the flattened `panes()`), only the deprecated file stays `panes[]`; the space overview edits both with `settings-view/layout-tabs-editor` (shared with the Layouts page) over the JSON text of the form (`space-overview/layout-config.ts`, a preset changes only when its tabs are edited), `project_edit::apply_patch` validates `layout` and `presets` and `layout_export`/`layout_import` (`layout_file.rs`) move one layout as JSON.
- `src-tauri/src/templates.rs`: space templates (`spaceTemplates[]` of the user config, parsed by `settings::parse_space_templates`): pure `resolve(dir, remote, templates, home)` (precedence: `dir` and `remote` > `remote` only > `dir` only, then the longest path-segment prefix of `match.dir`; case-insensitive paths on Windows and macOS; `remote` is the parsed `origin` from `git::origin_url`). `src-tauri/src/remote.rs`: pure `parse(url)` of GitHub and Azure DevOps remote URLs into `Remote` (reusable) and `agent_command` (harness registry line, error naming the template). `create_space_with` layers layout order project > template > `spaces.layout` > default and passes the agent to `build_layout`; a task's `root_command` wins.
