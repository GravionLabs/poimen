# Backend, server and protocol

poimen-server, its protocol, the client and the PTY host. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- Backend: `poimen-server` only. The herdr backend was removed (#174): no `backend` setting (an old `backend`, `herdr` or `colorSchema: "herdr"` in `config.json` is ignored with a log line by `settings::ignored_herdr_keys`), no `herdr.autoStart`, no `herdr.rs`, `stream.rs` or `watch.rs`. Users who leave herdr remove its agent hooks with `herdr integration uninstall` (README "Requirements", site installation page).
- `src-tauri/src/backend.rs`: the `Backend` trait (spaces, terminals, close/rename, split, input, `close_tab`/`rename_tab` (commands `tab_close`/`tab_rename`), `create_space_with_layout` and `apply_layout` (the server builds the layout and answers `LaidOut` created or trust; the default `None` is the fake's), neutral stream records `reset/resized/controller/closed` (output and the snapshot travel as raw bytes, see `lib.rs::channel_messages`) with `CloseCode::ControllerHeld`, events, `ensure_running`); every command goes through it (`Arc<dyn Backend>`). `PoimenBackend` (`poimen_backend.rs`) is its only implementation and the seam the tests use through `backend_fake.rs`. `agent_session.rs` holds the neutral agent types (`AgentSession`, `TranscriptAgent`, `session_of`, `PromptOutcome`). Start: `poimen_server.rs` (ping the socket, else start a detached `poimen-server` and wait), behind the `ensure_backend` command (always allowed). `gui_path.rs` is the login-shell `PATH` of a GUI app (used to find `gh`, `node` and the server). Tests use a fake `Runner`; never start or stop a server in a test.
- `src-tauri/crates/`: the Cargo workspace next to the app crate (`default-members` cover all, so plain `cargo test` in `src-tauri` runs everything). `poimen-protocol` (client-neutral wire types, socket path, parsing tests; the build-time channel `CHANNEL` (`POIMEN_CHANNEL`: `stable`, or `rc` for pre-release builds) names every path two installations could share (`Channel::named`: socket, `server.json`, `%LOCALAPPDATA%\poimen-server-rc`, `~/.config/poimen-rc`, server binary `poimen-server-rc`, hook marker and Copilot hook file), and `socket_path` ignores a `POIMEN_SOCKET` that is the other channel's default; the protocol and every request/event are documented in `docs/protocol.md`, version `PROTOCOL_VERSION`), `poimen-client` (blocking client: requests over short-lived connections, `subscribe` event stream, `ping_and_subscribe` on one connection, `pipe.rs`: `Connector`/`Pipe` for connections that are not the local socket, such as an ssh process; reused by the app, a later CLI and `poimen attach`; `transport.rs` is the local socket over `interprocess`: a Unix socket, on Windows a named pipe with a marker file and a DACL, no I/O timeouts or `shutdown` there) and `poimen-server` (daemon that runs every terminal in a `poimen-pty-host` of its own (ADR 0009, crate `poimen-pty-host`: owns PTY and child through `portable-pty`, ConPTY on Windows created in pass-through mode by the vendored copy `src-tauri/vendor/portable-pty`, see its `POIMEN.md`; host protocol in `docs/protocol.md`) and reads it as a client (`host.rs`, #603: `PtyHost` in `Config.pty_host`, the binary `poimen-pty-host[-rc]` next to the server through `PtyHost::beside_server`, a missing one is `spawn_failed` on `terminal.create`, never an in-process PTY; endpoint `hosts/<terminal id>` next to the socket; records strictly by `seq`, the last read kept per terminal with the endpoint, a dropped connection attached again after it; `exit` or a vanished host ends the terminal as an exit; input, resize, query answers and `kill` are host lines; tests use `PtyHost::launch(poimen_pty_host::spawn_in_thread)` (the real host in-process) and the scripted fake host of `tests/pty_host.rs`; `poimen-pty-host/tests/server.rs` runs the real binary; the sidecar build, `externalBin` and the per-version `stage` ship the host next to the server; adoption after a restart is #604), one per user on the socket under the runtime dir (Windows: `%LOCALAPPDATA%\poimen-server`, started from a per-version copy there; a Linux AppImage starts a per-version copy under `$XDG_DATA_HOME/poimen-server/bin` and its hooks call the stable link there, `poimen_server::stage_root`/`prepare`), spaces with terminals and per space tabs in order with a split tree each (`tabs.rs`: `Layout`, nodes addressed by a server-assigned `split_id`, `tab.*` requests, `tab.created`/`tab.changed`/`tab.closed`/`space.changed` events under the same lock as the terminal change; a closed or exited terminal leaves its tree, `terminal.create` gives a terminal a tab of its own), spaces, tabs, trees, the id counter and the running terminals persist in `server.json` (`store.rs`, `StoredTerminal`: host endpoint, last `seq`, size, agent status with its `seq`, tokens with TTL end; written on every change and before `server.shutdown` with `keep_terminals`); at start the server adopts the listed PTY hosts (#604, `lib.rs::adopt_terminals`, `host::reach`/`adopt`: ring replayed from `since` 0 as `Chunk::Replay`, whose queries are not answered again, a `gap` is one `gap_marker` line, a host that does not answer is dropped with a stderr line) and `Layout::reconcile` drops the leaves of the rest; never stopped by poimen, except a confirmed restart of an outdated server (`server.shutdown` with `keep_terminals`: list written, hosts and attachments released without events, `stopped` so it never writes again, lock released) and a confirmed "Quit poimen and stop server" (`server.shutdown` without, ends every terminal)). Per terminal it keeps an `alacritty_terminal` grid (`emulator.rs`, scrollback `POIMEN_SCROLLBACK`) fed from the host after a short coalescing (`pty.rs`: `coalesce`, default shell, terminal name, `PtyWriter`); `terminal.attach` (`stream.rs`, `Client::attach`) returns a snapshot (ANSI of screen, scrollback and modes) and then raw bytes with sequence numbers, under one lock per terminal so none is lost or repeated; a client has a bounded queue and is detached on overflow, never blocking the PTY; one controller (explicit take-over), many observers. Terminal queries (OSC 10/11/12/4, DSR, DA1/DA2) are answered from that grid by `TermStream::output` (`Emulator::take_replies`) only while no controller is attached (xterm.js answers otherwise); colors come from `server.set_colors`, sent by the app (`core/terminal-colors.ts`, command `set_terminal_colors`, `terminal_colors.rs` keeps the last scheme and pushes it after `ensure_backend`). `src-tauri/src/poimen_server.rs` starts it detached when absent (`ensure_running`, called by the backend through `ensure_backend`; fake `Runner` in tests). `ping` is classified against the bundled version: older server `Outdated`, other protocol `Incompatible` (reported as `outdated`/`incompatible` in `BackendStatus`, never a second server); `restart`/`stop` (commands `restart_server`, `quit_and_stop_server`) send `server.shutdown` (`restart` with `keep_terminals`) and are called only after the frontend confirmation (`core/server-restart.ts`: a restart names only the terminals without `survives_restart`, `kept` counts the others; `src/app/server-dialog/`); a stream whose server connection ended is `CloseCode::Lost` and `terminal-view` attaches again (`REATTACH_DELAYS_MS`, about 30 s); the `backend` setting and the `Backend` implementation are `poimen_backend.rs` below.
- `src-tauri/crates/poimen-core`: Tauri-free crate with the project-side logic, shared by the app and (later) the server and the console ([ADR 0006](../adr/0006-poimen-console-with-herdr-scope.md)). Holds `project.rs` (parsing, entries, teardown), `trust.rs`, `templates.rs`, `remote.rs`, the pure part of `layout.rs` (`Layout`, `PaneSpec`, `Split`, `SplitDirection`, `parse_layout*`, `resolve`, `resolve_origin`, `default_layout`), what these need (`tasks.rs`, `harness.rs`, `agent_actions.rs`, `gui_path.rs`) and `agent_events.rs` (the agent-events reducer, `LineTail`, `run_of`, fixtures `fixtures/agent-events/`), `settings.rs` (`parse_tasks`, `parse_space_templates`, `parse_trusted_projects`, `resolve_sidebar_rows`, `trust_project`/`revoke_project` and the comment-keeping config editor) and `schemes.rs` (user color schemes: `parse_scheme`, `load`; the app's `schemes.rs` keeps the watcher) and `snapshot.rs` (#586: the backend-neutral `Snapshot` of spaces, tabs and terminals every backend maps onto, the wire shape of the app's `snapshot` command; `AgentStatus` with `most_urgent`). The app crate keeps what needs a `Backend` in thin modules that re-export core (`pub use poimen_core::...`): `layout::apply`, `project::{start_setup, start_tab, run_entry}`; the other moved modules are used as `crate::trust`, `crate::templates` etc. through `use poimen_core::...` in `lib.rs`. Tauri commands stay in the app crate. CI `rust-server` and `windows` jobs list the crate. Also holds `git.rs`, `worktree.rs` (the #190 rules: base detection, branch template, collision rules; callable without Tauri or `Backend`; `cleanup` closes spaces through the `Spaces` trait, which the app implements over its `Backend` in `src/worktree.rs`), `github.rs` (`Client`, `Runner`, `open_issues`, `level_of`; the cache dir of `Client::rest` is a parameter, the app passes its app cache dir; fixture `crates/poimen-core/fixtures/github-open-issues.json`) and `task_start.rs` (`plan`, `space_label`; `start_tab` stays in the app's `src/task_start.rs`). The app crate re-exports them (`pub use poimen_core::...`) so its paths stay.
- `src-tauri/crates/poimen-pty-host/` (#602, ADR 0009): binary `poimen-pty-host`, one per terminal: creates the PTY (`portable-pty`, vendored ConPTY), spawns the child of a `poimen_protocol::host::SpawnSpec` (argv, cwd, env, size) and holds both until the child exits; never interprets output (no emulation, spaces, agent status or tokens). Started with one `HostStart` line on stdin (endpoint, spawn, `orphan_timeout_ms` default 24 h, `ring_bytes` default 1 MiB, `exit_linger_ms`), answers `hello` or `error` on stdout, then serves the host protocol (`docs/protocol.md`, "Host protocol", `host_version` 1, wire types in `poimen_protocol::host`) on its endpoint through `poimen_client::transport`: one client at a time (a new connection replaces the old with `replaced`), `attach {since}` replays the output ring (`ring.rs`, `gap` when it moved past), `input`/`resize`/`kill`, `exit {code}`; `seq` strictly increasing, never reset. Ends with its child, on `kill`, and after the orphan timeout without a client. `tree.rs` (#968) ends the whole tree on `kill`, the orphan timeout and the child's own exit: Unix every process of the child's session (SIGHUP, SIGKILL after `KILL_WAIT`; the only `unsafe` of the crate, `deny` otherwise), Windows a job object (kill on close); `exit` carries `tree` (`ended`/`unconfirmed`, optional), the server logs `unconfirmed`. Small on purpose (it is not updated with the server); not wired into `poimen-server` yet. Shipped as `externalBin` next to the server (`binaries/poimen-pty-host`, `-rc` on rc, built by `scripts/prepare-sidecar.sh`, also in the SSH server archive); `poimen_server::prepare` stages it from the server's directory into the same `<stage_root>/<version>/` (Windows, AppImage) and `prune` removes other versions only when no process runs from them (`/proc`, `ps`, on Windows a rename probe), so a host never loses its binary; macOS and the Linux packages run the installed file (#605). Tests in `tests/host.rs` start the binary with scripted children, among them the ConPTY check of ADR 0009 for the CI `windows` job.
- `src-tauri/src/poimen_backend.rs`: `PoimenBackend`, the one `Backend` (made at start in `lib.rs::make_backend`): server spaces, tabs and terminals become the backend-neutral snapshot (#586: `poimen_core::snapshot::Snapshot`, the wire shape of the `snapshot` and `machine_snapshot` commands: `spaces` with `cwd`, `tabs` with `root` and `active_terminal`, `terminals` with status, agent status and tokens, ids `space_id`/`tab_id`/`terminal_id`; spaces, rebuild and the worktree cleanup (`worktree::Spaces::view`) read it typed). `map_snapshot` over `space.list` and `terminal.list` (#513): tabs in the space's `tabs` order, numbered by it, with `root` (the split tree) and `active_terminal`; each terminal in its tab in leaf order; a terminal without a leaf (exited, or every terminal of a protocol 3 server) a tab of its own with its id, so none is lost; fixture `src/app/core/fixtures/poimen-snapshot-split-tab.json`, checked on both sides; the frontend reads it through `toSnapshot` in `core/snapshot.ts` (the neutral model `Snapshot` of `Space`s, `Tab`s with `Tab.root`/`TabTree` and `Terminal`s and its pure helpers; `core/backend.ts` holds the other backend-neutral wire types: `BackendEvent`, `StreamRecord`, `Mode`, `BackendInfo`, version labels, agent kinds); `tabPanes` orders the panes of a tab by its tree (`buildTree`), `tabTerminal` is the first leaf, `spaceRoot` the root terminal of a new space; until the split view the frontend shows each terminal as its own pane row and editor tab), a split is `tab.split`, `close_tab`/`rename_tab` are `tab.close`/`tab.rename`, renaming the only terminal of a tab renames the tab too, `tab.*` and `space.changed` events reach the frontend as backend events and invalidate the snapshot like every other event; `lib.rs::create_space_with` hands a new space to `space.create` with `layout` (`create_space_with_layout`: label, cwd, task `command`, the trust dialog's answer as `trust`) and maps `trust_required` onto the `trust` of `SpaceOutcome` for `src/app/trust-dialog/`, so the server gates the project file; `rebuild_space_with` and the preset path of `project::run_entry` send `space.apply_layout` (`Backend::apply_layout`: space, cwd, preset, trust answer; `LaidOut::Trust` goes to the same trust dialog, the server stores the trust) (#645; a backend that does not build layouts, only the test fake, is an error), streams are `terminal.attach` connections (`poimen_client::AttachmentWriter` sends input and resize on the attached connection). Records reach the webview through the `tauri::ipc::Channel` of `open_terminal` (`lib.rs::channel_messages`: PTY bytes raw, the rest JSON); there is no global `terminal` event. Agent start, prompt and rename work (see `poimen-client/src/agent.rs`). Never started or stopped by poimen beyond `poimen_server::ensure_running` and the confirmed `restart`/`stop`.
- OSC 7501 child records (#684): `poimen-server/src/records.rs` (`Records`: reports with an `id`, bounded to 256 by least recent update, subtree clear, `app` inherited; lifetime applied from `TerminalEntry::apply_signal` and `terminal_exited`), `Terminal.records`, event `terminal.records_changed`, `StoredTerminal.records`; shown by the app (`sidebar/spaces.ts` `recordRows`, folded above `RECORDS_SHOWN`) and the TUI (`RowKind::Record`).
- `src-tauri/crates/poimen-server/src/report.rs`: the `poimen-server report tokens|clear|agent` CLI (`plan` is pure: args plus `POIMEN_TERMINAL_ID` to a request or `Skip`; `run` never fails the caller, usage errors exit 2). The server keeps tokens per terminal (`terminal.report_tokens`, `terminal.clear_tokens`, the name and TTL rules, owner = last source, a sweeper thread in `serve` expires TTLs, `terminal.tokens_changed` event, `Terminal.tokens`); `poimen_backend.rs` puts them in the pane's `tokens`, which is where the herdr backend's `$<name>` row tokens read them. Tests: `crates/poimen-server/tests/tokens.rs`.
- Logs (#966): `poimen-server/src/log.rs` (`line(log, component, message)`, `append` with rotation at 256 KiB, files 0600; `hook.rs` uses it) writes `server.log` next to `server.json` and stderr; every runtime `eprintln!` of the server goes through it (`Shared::log`), the CLI usage errors stay on stderr. `host::start` opens `hosts/<id>.log` as the host's stderr (also for the in-process test hosts, as an empty file); the host binary writes a start and an end line (`Host::start_line`, `serve` returns the reason); `Reader::run` removes the host log on `exit`, keeps it when the host vanished; `Server::bind` removes host logs older than 7 days. The state-file path and log time stamps are `poimen_protocol::files` (shared with the app); app command `server_log_path` (`src-tauri/src/server_paths.rs`).

- `server.json` durability (#967): `store::save` syncs, keeps `server.json.bak` and syncs the directory; `store::load` falls back to the backup, sets an unreadable file aside as `.damaged-<secs>` (three kept) and refuses a newer `version` (`load_or_refuse`: exit 1, line in `server.log` that `server_paths::describe` shows in the app). Tests: `store_durability_tests.rs`.
- Keep awake (#987): `poimen-server/src/awake.rs` (`Shared::awake_sweep`, run by `serve` every 5 s; tests give the clock and `Server::set_awake_command`). The hold is a helper process on a stdin pipe, so a release or a dead server ends it; the setting is read from the config file each pass. Frontend: `SpacesStore.awake` from `server.awake_changed`, `awake` item of the status bar, switch on the Agents page. Windows uses `SetThreadExecutionState` through PowerShell, not `PowerCreateRequest` (no Windows API crate in the server).

## Compatibility with the last release (#969)

ADR 0009 promises that a server update keeps the terminals, and the app talks to a server that may be one release behind. CI job `previous-release` (runs when `poimen-protocol`, `poimen-pty-host`, `poimen-server`, `poimen-client` or the workspace manifests change; needed by `ci`) builds `poimen-server` and `poimen-pty-host` from the latest stable tag in a second checkout and runs `crates/poimen-server/tests/previous_release.rs` (Unix) with `POIMEN_PREVIOUS_TAG`, `POIMEN_PREVIOUS_RELEASE_DIR` and `POIMEN_REQUIRE_PREVIOUS=1` (without them a local `cargo test` skips the two tests; run them by hand with a worktree of the tag built with `cargo build -p poimen-server -p poimen-pty-host`):

- the server of this tree adopts a host of the last release (`server.shutdown` with `keep_terminals`, a second server on the same state file, output, attach and input through the old host);
- the client of this tree pings the last release's server (`protocol` must equal `PROTOCOL_VERSION`, the condition under which the app's `classify` gives `Answers` or `Outdated`, never `Incompatible`) and attaches to a terminal on it.

A failure names both versions. **When a break is allowed:** only as a protocol version step (`PROTOCOL_VERSION` up) that the app handles through the `Incompatible` path (`poimen_server::classify`: reported as `incompatible`, no second server, the user restarts the server after the confirmation). Then the second test fails on purpose in the same change: adapt its expectation (the `ping` assertion) in that pull request and say so in the PR. Changes to the host protocol (`host_version`) must keep the new server able to adopt the old host; a host protocol break needs a `host_version` step and the server must refuse (not adopt) an older host, with the terminal listed as not surviving (`survives_restart`). The compatibility is not covered for a release more than one behind.
