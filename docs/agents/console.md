# Console (`poimen` TUI and CLI)

`poimen-console`: TUI, CLI, attach and MCP. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `poimen integration install|uninstall|status claude|copilot|gemini [--settings <path>]` (#1173): `cli.rs` parses, `main.rs::integration` finds the hook binary (`POIMEN_HOOK_EXE`, else `poimen-server` next to the console, else `PATH`; the hooks keep calling `poimen-server hook`) and calls `poimen_server::integration::run`, which is also the deprecated `poimen-server integration` (note on stderr). The logic stays in the `poimen-server` lib (the console depends on it) instead of moving to `poimen-core`: the hook mappers share `claude.rs` with the hook runner. `poimen doctor` runs `poimen integration status` of its own binary (`Env.console`); the app still runs the bundled `poimen-server integration`.
- Server start (#1171): `poimen-console/src/server_start.rs`. Every command but `doctor`, `--help` and `--version` calls `ensure_for_console()` first: a server that answers is used; when the ping says none runs, `poimen-server` (`CHANNEL.server_program`) next to the console binary, else on the login-shell `PATH`, is started detached (own process group, no terminal, never waited on, as `poimen-server stdio`) and polled for 10 s. Nothing is started when `POIMEN_SOCKET` is set (a poimen terminal) or the ping fails another way than not running. No program found: the error names the file to install. Tests: `tests/server_start.rs` (fake script, in-process server), `tests/server_start_bin.rs` (the binary: doctor, terminal, help).
- `src-tauri/crates/poimen-console/src/tui/attention.rs` (#518): attention of the TUI, the rules of `core/attention.ts` as pure code (`Attention`: blocked while not viewed rings, done counts as unread, viewing clears; `Log`: the notification list, prefix key `N` (`console.keys.notifications`), Enter focuses the terminal). No system notifications (#676). Status comes from the hook-reported `agent` of the terminals; the run rule of #540 (`host["poimen.terminal"]`) is not applied in the TUI yet.

- Shared session operation (#744, ADR 0016): `poimen_client::agent` (`agent/session.rs`) holds what the MCP write tools, the later `poimen session run` and the host module of a script share. `run_session(client, ctx, request, on_event)` resolves the harness from the user's `config.json` (`harnesses_of`; a project config contributes none, so an untrusted one cannot add templates; only ids in `HOOK_KINDS` run, others are refused as "no hooks"), checks the permission on the space id the server resolved (`authorize_write`, ADR 0012: own space free, any other through `agent.confirm`, refused without app or caller), creates the terminal (`<run id> <title>` tab name, `AGENT_EVENTS_RUN`, `Terminal.run`/`task`), starts the argv per element (`promptArgs`, else the prompt is typed with `prompt_agent` after `SessionStart`) and waits with `watch_agent` (event subscription, no polling; `blocked` does not end it). `SessionEvent` reaches the callback; errors are `SessionError::{StartFailed, Ended, ConnectionLost, PermissionRefused}` for the CLI's exit codes. The MCP `authorize`, `harnesses_of` and `wait_agent` call `authorize_write`, `harnesses_of` and `watch_agent`. No `report_done` preamble in a session. `placement` is passed on, the server keeps none yet. Tests: `poimen-console/tests/session.rs` (in-process server, fake harness script, hooks reported by the test).
- Orchestration tools (#1214, ADR 0018): `create_space`, `list_repositories` (`mcp/space.rs`), `request_grant`, `revoke_grant` (`mcp/grant.rs`), `start_shell` (`mcp/shell.rs`), `stop_terminal` (`mcp/stop.rs`), `wait_any` (`mcp/wait_any.rs`), `record_run`, `read_run` (`mcp/lead.rs`). Each description names its use and its neighbors; when you add or change one, update the tool tables and the "Orchestrating across repositories" section of `site/guide/mcp.md`.
- Lead run record (#1212, ADR 0018): `record_run` and `read_run` (`poimen-console/src/mcp/lead.rs`). The state of a lead run is the agent-events run `lead-<uuidv7>` of the repository of the lead's terminal (shared event directory, `origin`; older ones also from the legacy directory), written by `record_run {event}` (`start`, `plan`, `member`, `member_done`, `dependency`, `grant`, `decision`, `attention`, `resolved`, `note`, `resume`, `finish`). Core events (`run.*`, `task.*`, `attention*`, `progress`) show it in the Runs view; the records of profile `orchestrate@1` (`poimen_protocol::lead::LeadRecord`, types `orchestrate.*`) carry plan, members, dependencies, grant and decisions. The member's repository is `target` (the `repository` argument is where the run lives) and the run id of the member's run is `deliver_run` (`run` is the envelope's). The lead terminal is `host["poimen.terminal"]`, or the newest `orchestrate.resume`; another terminal cannot write before `resume`. `read_run` without `run` reads the caller's open run, else lists the open lead runs. Tests: `tests/mcp_lead.rs`.
- TUI config reload (#1175): `tui::config::watch` (a `notify` watcher on the config directory, recursive, so `config.json` and `themes/`) sends `Msg::ConfigChanged` into the main loop; `reload_config` in `tui/mod.rs` reads `config::try_load` and swaps `app.config`, the palette and the router (`Router::reconfigure` keeps a pending prefix, and messages are handled one at a time, so no key is lost). An invalid file (not JSON, unreadable) keeps the last config and shows `config: …` in the status line; a missing file is the default; a reload that changes nothing is silent. Tests: `tests/tui_reload.rs`.
- Remote machines (#1176, ADR 0008): `poimen --machine <name> [<command>]` (`cli::parse_invocation`, a leading `--machine <name>` or `--machine=<name>`; `mcp` and `doctor` refuse it, `mcp` stays local) uses the server of a `machines[]` entry of the user config through `poimen_client::ssh::SshConnector` (moved out of the app with `ssh/args.rs` and `ssh/mux.rs`, so the ssh options, `serverPath` and the connection sharing are the app's; `poimen_core::machines` holds `MachineConfig`, `parse` and the target checks). `poimen-console/src/remote.rs`: `load`/`find` (unknown name lists the configured ones), `client`, `classify`/`State` and the messages of the app's `machineHint` (missing server, protocol older or newer, key, host key, no route, refused) with the command to copy; poimen only prints it. Before the command runs `main.rs::machine_target` pings once and exits 1 with that message when the server is offline or incompatible; no local server is started and `POIMEN_TERMINAL_ID` is not used (own terminal and caller are none). `poimen machines [--json]` pings every machine in parallel (`name  ssh  connected: server <v>|offline: <ssh error>|incompatible: ...`). Each request is one ssh process (the mux reuses the connection). Tests: `tests/machine.rs` (arguments, commands over an in-process `stdio::bridge` pipe instead of ssh, offline advice), unit in `remote.rs` and `poimen-client/src/ssh.rs`.
- Run tools and the server (#1410, #1417): `list_runs`, `get_events` and the `runs` of `wait_any` are tools of `poimen mcp`, not requests of `poimen-server`: they read the run files themselves (`mcp/run_files.rs`), from the event directory (`AGENT_EVENTS_DIR` of the `poimen mcp` process, which in a poimen terminal is the server's, else the per-user default) and, with a `repository`, its legacy directory. Filtering by `origin`: `repository` keeps the runs whose `origin` names that repository (`origin.worktree`, same git common dir, else `origin.repo`) plus those of its legacy directory; `repo` (`owner/repo`) compares `origin.repo`; without both, every run of the event directory. Only the terminals of `wait_any` come from the server (event subscription and `terminal.list`). `record_run` and `report_done` write to the event directory with `origin`.
