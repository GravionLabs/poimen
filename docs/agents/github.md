# GitHub views

The `gh` client, pull requests, issues, milestones and the task picker. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `src-tauri/crates/poimen-core/src/github.rs`: shared GitHub client over the `gh` CLI ([ADR 0005](../adr/0005-github-views-and-agent-harnesses.md)): `repo_of(dir)` (GitHub `origin` only), `Client::rest` (`gh api --include`, ETag revalidation, body cached 30 s per exact path in the app cache dir) and `Client::graphql` (30 s in-memory cache per query and variables); errors serialize as `GhError` (`gh-missing`, `not-logged-in`, `offline`, `rate-limited`, `not-found`, `other`). `gh` is resolved through `gui_path.rs`; a `Runner` trait fakes the child process in tests (no network). Never logs tokens or headers.
- Writes on pull requests (#338): `Client::mutate(repo, argv)` runs a `gh` command uncached and afterwards clears the GraphQL cache and the REST disk entries of that repository (whatever the outcome; an answer in flight before the write is not cached); `github_pulls::run_action` / command `github_pr_action(root, number, action, body?)` (`PrAction`: approve, request_changes, comment, ready, draft, close, reopen; argv only with `-R owner/name`). Frontend: `availableActions` and `GithubPulls.act`/`choose` in `github/pulls.ts` (hidden without `viewerCanUpdate`, review actions on own PRs; text for request changes and comment, confirmation for close), buttons in `pull-detail/`, palette entries "GitHub: <action> #<nr>" while a detail is open.
- `src-tauri/crates/poimen-core/src/github.rs`: shared `gh` client (argv, login-shell `PATH`, 60 s timeout, REST with ETag disk cache, GraphQL in-memory cache of 30 s, `GhError`). `src-tauri/src/github_pulls.rs`: `github_pulls(dirs)` (one GraphQL query per repository from `git::repo_roots`, `viewer` once; fixture `fixtures/github-pulls.json`). Frontend: `src/app/github/` (`pulls.ts` service with filters and selection signal, `github-view`); tab kind `github` in `core/editor-tabs.ts`. `src-tauri/src/github_issues.rs`: `github_issues(dirs, closed)` (GraphQL `issues` paginated up to 300 per repository with `parent`, `subIssuesSummary` and `closedByPullRequestsReferences`, plus open pull requests matched by branch `<type>/<nr>-`; fixture `fixtures/github-issues.json`); frontend `issues.ts` (levels, tree, filters, service; collapsed nodes per repository in `core/ui-state.ts`) and `issues-section` (the Issues section of the tab). `github_issue_detail(root, number)` (`IssueDetail`: body, state and reason, labels, assignees, milestone, parent, sub-issues, closing pull requests, `viewerCanUpdate`; fixture `fixtures/github-issue-detail.json`); the issues tree has a keyboard cursor (Up/Down, Enter opens, Escape closes) and a bulk selection (#342: `GithubIssues.mark(key, 'toggle'|'range')` by checkbox, Cmd/Ctrl-click, Shift-click or Space, limited to one repository, `markedIssues` is also the input of agent actions; the bulk bar `bulkEdit`/`bulkClose` runs `github_issue_edit`/`github_issue_action` per issue in order, a failure does not stop the rest, one notification lists done and failed numbers) and `issue-detail/` is the pane, sharing the shell stylesheet `detail-pane.css` (overlay under 1100 px) with `pull-detail/`; bodies go through `markdown.ts` (`marked` + DOMPurify, always sanitized). `src-tauri/src/github_milestones.rs`: `github_milestones(dirs)` (REST `repos/{o}/{r}/milestones?state=open` through `github::rest`, ordered by version, `current` = lowest versioned milestone with open issues: legacy `x.y.z` first, then `M<n>` / `M<n> (x.y.z)` by `n`; fixture `fixtures/github-milestones.json`; `github_issues::unique_repos` is shared); frontend `milestones.ts` (service; the selection filters the issue tree of its repository through `IssueFilter.milestone`) and `milestones-section`. The GitHub tab shows one sub-page at a time (`github-view`: left navigation Pull requests / Issues / Milestones with counts, `UiState.githubPage` persisted, palette "GitHub: Pull requests|Issues|Milestones"); the repository filter above the navigation is `github-filter.ts` (`GithubFilter.repo`, read by the three services); one Refresh reloads the active page; selecting a milestone switches to Issues. Pull request detail (#336): `github_pull_detail(root, number)` of `github_pulls.rs` (one GraphQL query: body, branches, mergeable, check contexts, reviews, `closingIssuesReferences`, `viewerCan*` flags; fixture `fixtures/github-pull-detail.json`); frontend `github/pull-detail/` (pane right of the list, overlay under 1100 px, empty action bar for later actions; state in `GithubPulls.openDetail`, a linked issue is selected through `GithubIssues.select`). More pull request writes (#339): `github_pulls.rs` `merge_argv`/`run_merge` (command `github_pr_merge`: re-reads the detail and refuses unless `merge_block` is none, i.e. `mergeStateStatus` CLEAN/UNSTABLE/HAS_HOOKS on an open non-draft, and the method is in `merge_methods` from `squashMergeAllowed`/`mergeCommitAllowed`/`rebaseMergeAllowed`; `--delete-branch` optional), `run_rerun` (`github_pr_rerun`: `poimen_core::github::failed_runs(client, repo, sha)` = REST `actions/runs?head_sha=`, newest run per workflow that failed or timed out, then `gh run rerun <id> --failed`; fixture `crates/poimen-core/fixtures/github-actions-runs.json`), `edit_argv`/`run_edit` (`github_pr_edit`: one `--add-/--remove-reviewer|label|assignee` flag per value, blank or comma values refused) and `github_labels` (REST `labels`); `PullDetail` gained `headSha`, `mergeMethods`, `mergeBlock`, `reviewers`, `labels`, `assignees`, `assignableUsers`. All through `Client::mutate`; frontend `canMerge`/`canRerun`/`canEditPeople` in `pulls.ts` hide them without `viewerCanUpdate`, `GithubPulls.startMerge`/`merge`/`rerun`/`edit`, merge confirmation names method and base branch (delete branch on by default), shared `github/chip-picker/` (`add`/`remove` outputs only, reused by #340). Issue edits (#340): `github_issues.rs` `edit_argv`/`run_edit` (command `github_issue_edit`: `gh issue edit` with `--title`, one flag per label or assignee, `--milestone`/`--remove-milestone`; the body goes as `--body-file -` on stdin through `Client::mutate_input` and `Runner::gh_input`, never argv) and `action_argv`/`run_action` (`github_issue_action`: `gh issue close --reason completed|"not planned"`, `reopen`). Invariant: a body is written only when `Client::read_fresh` (`gh issue view --json body`, uncached) still equals `expectedBody`, the text the pane loaded (line endings ignored), else the answer is `conflict` with the current text and nothing is written, unless the user chose `overwrite`. Frontend: `GithubIssues` (`titleDraft`, `bodyDraft` with its own baseline, `conflict`, `saveBody(overwrite)`, `reloadBody`, `editMeta`, `act`), shown only with `viewerCanUpdate` (`canEditIssue`); `IssueDetail.assignableUsers`; label and milestone options come from `github_labels` and `github_milestones`. Bodies are untrusted: `github/markdown.ts` (`marked` + `DOMPurify`, pinned exactly) is the only Markdown renderer and always sanitizes.
- Creating issues and changing the parent (#341): `github_issues.rs` `create_argv` (`gh issue create --title --body-file - [--label] [--milestone] -R`, body on stdin through `mutate_input`), `run_create` (with `parent`, the new issue's REST id from `gh api repos/{o}/{r}/issues/{n} --jq .id`, then `POST .../issues/{parent}/sub_issues`; a link failure names the created issue), `run_change_parent` (`DELETE .../sub_issue` on the old parent, then `POST` on the new; itself or the same parent refused); commands `github_issue_create`, `github_issue_change_parent`. Frontend: `issues.ts` (`childLevel` Epic to Feature, Feature to PBI, `newIssueForm` presets title prefix and level label, `parentCandidates`), form state in `GithubIssues.form`, `github/issue-form/` (opened by the `+` of a repository group and "Add sub-issue" in the pane; after creation the issue is selected and its pane opens), "Change parent" search in `issue-detail/`.
- `src-tauri/crates/poimen-core/src/github.rs` also holds the task picker's issue source: `open_issues` (REST `repos/{o}/{r}/issues?state=open&per_page=100`, up to 300 over three pages, pull requests dropped; fixture `crates/poimen-core/fixtures/github-open-issues.json`) and `level_of` (label `epic`/`feature`/`pbi`/`bug`, else `[Epic]`... title prefix; shared with the planner views); command `task_issues(dir)`. Frontend `src/app/task-dialog/`: `TaskPicker` (service: `open(dir)` resolves a `TaskChoice` or null, filters, keys, modes from `get_task_modes`; a failed list keeps typing a number usable) and `task-dialog`. It only returns the choice. `src/app/core/task-start.ts` (`TaskStarter`) starts the task: `task_plan` (`crates/poimen-core/src/task_start.rs`: expanded command, space label `#<nr> <title>`, tab name), then for a worktree mode `task_worktree` and `create_space` on the path with `command` (replaces the root pane command of the resolved layout; an existing space is only focused), else `create_space` on the repository and `task_tab`; a failed step is shown through `SpaceActions.notify` naming it. Task on a remote machine (#283): the picker's machine selector (`TaskPicker.machines`: connected machines, remembered per repository directory in `UiState.taskMachine`) puts `machine` in the `TaskChoice`; `TaskStarter.onMachine` then runs on that machine's server through `machine_repo_ensure` (`repo.ensure`, owner/repo from the local `github_repo`), `machine_worktree_create`, `machine_create_space` (`lib.rs::remote_create_space`: an existing space for the path is focused, else `space.create` with the layout; an untrusted project file is an error, no local path check) and, for a mode without a worktree (clone root), `machine_task_tab`; the new space is focused qualified by the machine, a failed step is `remoteStepFailure` (machine and step: clone, worktree, space, tab) and stops. The issue list and `task_plan` stay local. Entry points: palette `startTask`, the space menu of the sidebar and the explorer menu (repositories only), and Cmd+click (macOS) or Ctrl+click on a `https://github.com/<owner>/<repo>/issues/<nr>` link in a terminal (`terminal-view/links.ts`: `parseIssueLink`, `taskLinkHandler`; command `github_repo(dir)` gives the `origin` owner/repo of the pane's directory): when it matches, `TaskStarter.start(dir, nr)` opens the picker with the issue highlighted (`TaskPicker.open(dir, preselect)`), otherwise and on a plain click the link opens in the browser.
- Checks finished (#995): `core/pr-watch.ts` (`PrWatch`, started in `app.ts`) watches `SpacesStore.pulls()` (`branch_pulls`, now with `headSha`, `baseRef`, `isCrossRepository`) for the open pull request of each local space. `finishedChecks` reports a pull request that was pending on a head commit and is final now (nothing pending, passing or failing); a result seen for the first time (app start, a new commit) is not news and each `<url>@<sha>` is reported once. A result is `NotificationCenter.recordChecks` (entry with the pull request and the space, `checks` set; failed ones show "Fix checks", which runs the `fix-checks` agent action through `AgentActions` at the space directory) and `Sounds.notifyResult` (`done` for passed, `blocked` for failed, same settings and 2 s window). The only requests of the watcher: `SpacesStore.refreshPulls()` every 30 s while some watched pull request has a pending check (the `gh` client caches 30 s); nothing without `gh` or a pending check.
- Failed check log (#999): `poimen-core/src/check_log.rs` `check_log` (command `github_check_log(root, url)` in `pull_request.rs`): the check's details URL must be an Actions run of the repository of `root` (`check_ids`, digits only), then `gh run view <run> --log-failed [--job <job>]`, trimmed to the last `LOG_LIMIT_PER_RUN` (200 KB). Frontend: a failing check with an Actions URL (`hasCheckLog`, helpers in `github/check-log.ts`) has "Show log" in `pull-detail/`; `GithubPulls.loadCheckLog` fetches on first expand, caches per `checkLogKey(headSha, url)` (errors are retried), strips ANSI (`stripAnsi`) and keeps the last 200 lines. The check name stays the "Open on GitHub" link.
