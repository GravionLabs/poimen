# Settings and schemes

User settings, import/export, color schemes and sounds. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- Sounds (#724): `core/sounds.ts` (`Sounds`, the only file that touches `AudioContext`; tones generated with Web Audio) plays for the `Attention.observe` transitions that `app.ts` hands it (not for a machine that `Machines.blockedReason` blocks); silent for the first snapshot of a backend session (`SpacesStore.onSessionStart`), one sound per 2 s, blocked wins. `sounds` in the user config is parsed by `settings.rs` (`Sounds`, `SoundSetting`, warnings); the command `sound_file(kind)` (`settings::read_sound_file`) takes the path from the settings, never from the caller, and returns a regular file up to 1 MiB. UI: "Sounds" section of the Appearance page.
- `src-tauri/src/settings.rs`: user settings (`~/.config/poimen/config.json`, `poimen-rc` on rc through `config_dir`, optional Ghostty and Kitty configs; theme and `include` parsing in `terminal_import.rs`, files injected through `TerminalSources`); `get_settings` command plus a polling watcher emitting `settings`. Preferences only, never UI state; frontend side is `core/settings.ts`.
- `src-tauri/src/settings_transfer.rs` (#581): export and import of the user settings. Commands `settings_export(path, template?)` (`config.json` without `PER_MACHINE` = `trustedProjects`, or one space template as `{"spaceTemplates": [..]}`; only a `.json` path), `settings_import_plan(path, mode, scope)` (writes nothing) and `settings_import_apply` (the plan made again inside `save_with` from the text read right before the write). The file (regular, up to 1 MiB, comments allowed) is validated entry by entry with `settings::resolve` (top-level keys, then their keys, arrays item by item; invalid entries listed, never written); `merge` deep-merges objects and `spaceTemplates` by name (a template that adds a loader warning, a second default, is invalid), `replace` drops keys the file lacks; `trustedProjects` is skipped, kept and never written. The diff (dotted paths, `spaceTemplates[<name>]`) is written key by key through `set_path_text`/`remove_path_text`, falling back to the whole top-level key when the result would not parse as expected. Paths come from `tauri-plugin-dialog` (`TauriBridge.pickSaveFile`/`pickJsonFile`, capability `dialog:allow-save`). Frontend `core/settings-transfer.ts` (`SettingsTransfer`: pending plan, mode, apply), `settings-view/settings-import-panel` (the diff and Import/Cancel), page "Export & import" (group General) and Export/Import on the Spaces page.
- `src-tauri/src/schemes.rs`: user color schemes (WezTerm TOML in `~/.config/poimen/themes/`, parsed by `poimen_core::schemes`, which the TUI uses too); `get_color_schemes` command plus a polling watcher emitting `color-schemes`; frontend side is `core/user-schemes.ts`.
- Open in editor (#1002): `src-tauri/src/editor.rs` (`open_in_editor(path, line?, column?)`). `editor` in `config.json` is a preset id (`vscode`, `cursor`, `zed`, `idea`, `webstorm`, `pycharm`, `goland`, `clion`, `rustrover`) or an argv array with `{path}`, `{line}`, `{column}` (a missing position is 1); without it the first preset found on the login-shell `PATH` (`gui_path::child_path`) is used. Run without a shell (each element is one argument), the launcher is reaped on a thread. An editor not found or an invalid `editor` is an error that names the setting; the frontend (`core/external-editor.ts`, `ExternalEditor`) shows it as a notice. Entries: sidebar space menu (`open-in-editor`, local spaces), explorer folder menu, file rows of the Changes view (the line is the last line number clicked in the diff, `DiffEditor.lastLine`) and the "Other findings" rows (finding file and line); palette command "Open in Editor" (directory of the active pane). A space of a machine (#1005, qualified id) opens over ssh: `open_in_editor` with `machine` (`editor::launch_remote`; the machine has to be connected, else its entry is disabled with the reason) runs `code --remote ssh-remote+<ssh> <path>` or `zed ssh://<ssh><path>` (path percent-encoded) with the `ssh` target of the machine; the `editor` setting has to be `vscode` or `zed` (an argv template or another preset is an error that says so), without it the first of the two on the `PATH`. The sidebar asks `open_in_editor` with `probe: true` (`ExternalEditor.refreshRemote`, on each space menu open) and disables the entry of a remote space with the error as the reason. The setting is read from the file at each call, not part of `get_settings`.
- Terminal history (#1196, ADR 0015): `terminalHistory` in the user config, `{ enabled, perTerminalMiB, totalMiB }` (defaults on, 8, 256; whole MiB from 1, an invalid field warns and keeps its default). Parsed by `poimen_core::terminal_history` (shared by the app's `settings::resolve`, which warns for import validation, and the server). The server rereads the file at most every 2 s (`Shared::refresh_history`) and applies it to the writer (`History::configure`) without a restart: off writes nothing (existing logs stay until their terminal closes; the log shows a `Hole` where output was skipped), the limits count from the next write. Closing a terminal (`close_entry`) removes its log; at start `history::sweep_orphans` removes logs whose terminal is not in `server.json`. The app writes it with `set_terminal_history` (`settings::save_terminal_history`, key by key); UI: Settings > Backend > Server, with the privacy note that terminal output is stored on disk. Export/import treat it like any key (`settings_transfer` test). It is a user setting only: there is no project-file key, so `docs/project-config.schema.json` does not list it.
- Snippets (#1007): `snippets[]` in the user config, `{ label, text, enter (default true), target ("terminal" default | "agent") }`. Parsed by `src-tauri/src/snippets.rs` (`parse`: an invalid or repeated-label entry is a warning and skipped; `set_text` rejects any warning), written key by key by `set_snippets` (the settings page "Snippets", `settings-view/snippets-editor`). Frontend model `core/snippets-model.ts` (`parseSnippets`, `offeredFor`: an `agent` snippet is offered for agent panes only), runner `core/snippets.ts` (`SnippetRunner`): `terminal` goes to `terminal_type` (`Backend::send_text`, or `send_input` with Enter; routed to a machine's backend, refused while it is offline), `agent` goes through `AgentPrompts.send` (`agent_prompt`, always submitted, so `enter` is ignored). Entries: palette "Snippet: <label>" (group Snippets, for the active pane; `CommandPalette.activePane`) and a "Snippets" group in the sidebar pane menu (`sidebar/snippet-menu.ts`); the tab-bar and split-leaf menus have none. The project file's `commands[]` are separate and unchanged. Export/import treat `snippets` like any key. Tauri commands that write one list key live in `settings_write.rs` (`set_layouts`, `set_space_templates`); the template save tests are in `settings_templates_tests.rs`, both moved out of `lib.rs`/`settings.rs` for the line ratchet.
- Keyboard page (#1009): `settings-view/shortcuts-editor` lists every action (groups of `SHORTCUT_GROUPS`) with its shortcut. Record installs a capture-phase `keydown` listener on `window` (so the app's own shortcuts do not fire), `core/shortcut-record.ts` (`recordAccelerator`) turns the event into an accelerator (primary modifier spelled `CmdOrCtrl`, letters and punctuation from `event.code`; Cmd, Ctrl or Alt or a function key is needed, as in the loader) and `shortcutConflict` names another action with the same accelerator before Save is enabled; Escape cancels. Writes go through `set_shortcut(action, accelerator)` (`settings_write.rs`, `settings_shortcuts::set_shortcut_text`): `null` removes `shortcuts.<action>` (Reset), `""` unbinds (Clear), other text is normalized and refused when invalid or used by another action; only that entry is written (`set_path_text`). `SettingsStore.write` is public for this editor.
