# Remote machines

Machines over SSH and actions on remote spaces. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `src-tauri/src/machines.rs` (#279, ADR 0008): remote machines. `parse` reads `machines[]` of the user config (`name` unique, `ssh` one target that is not an option, `reposDir` with `{owner}`/`{repo}`, default `~/Source/{owner}/{repo}`; invalid entries are settings warnings, `Settings.machines`). `Machines` (managed, `sync` from the settings watcher: an unchanged machine keeps its connection) holds one `Machine` per entry: a supervisor thread (`supervise` over a `Link`, faked in tests with a `Pause` that does not sleep) holds one connection (`Client::ping_and_subscribe_with`, `run_events` set) and reports `State` `connecting`/`connected`/`offline` (ssh's stderr as the error, `SshOutput`)/`incompatible` (other protocol: no subscription, no further requests, retried only on demand); a drop is retried with `Backoff` (1 s doubling to 60 s) or at once by `reconnect`, which `src-tauri/src/machines/wake.rs` (#1011) also calls for every machine that is not connected on a resume from sleep (a gap in the 3 s wall-clock ticks) and when the default route appears or changes (UDP `connect` to a TEST-NET address, nothing is sent); the loop only ends when the machine is removed, and a half-open connection ends with ssh's keep-alive (15 s x 3). Tests in `machines/wake/tests.rs`. Every connection is one ssh process (`SshConnector`: `ssh -T -o BatchMode=yes -o ConnectTimeout=10 -o ServerAliveInterval=15 -- <target> poimen-server[-rc] stdio`, `ssh` from `gui_path`) through `poimen_client::pipe::Connector` (`Client::with_connector`); the machine's `PoimenBackend::remote` (never starts or stops that server) goes through `Gated`: no connection while not `connected`, reads and writes of an earlier session fail (nothing replayed), and a drop closes poimen's own connections only, never a remote terminal. Commands `list_machines`, `reconnect_machine`, `machine_snapshot`; event `machine:state_changed` (Tauri event names allow no `.`). The subscription's events are forwarded as `machine:event` (`{machine, kind, data}`, `backend_event`), except `run.events` (#692): `remote_runs.rs` (`RemoteRuns`, managed; `apply` folds them per machine, root and run with the core reducer, which drops a `seq` it folded already, so the replay of a reconnect adds only the new events; pid check off, age rule only; `retain` drops removed machines in `sync_machines`) emits them as `deliver {root, machine, read}`; and `open_terminal` takes `machine`: the stream opens on that machine's backend and gets an id from `RemoteStreams` (from `REMOTE_STREAM_BASE` up, so `terminal_input`/`resize`/`scroll`/`mouse`/`close_terminal` route by id). Frontend (#280) `core/machines.ts` (`Machines`, `parseMachineStatus`), `Machine` in `core/settings.ts`, `core/remote-spaces.ts` (`RemoteSpaces`: `machine_snapshot` on connect and after events, last snapshot kept offline with status `unknown`; `qualifyId`/`splitId`/`qualifySnapshot`/`mergeSnapshots` in `core/snapshot.ts` give remote ids `<machine>::<id>` and set `machine` on spaces, tabs and terminals). `SpacesStore.all` = this Mac plus the machines: `panes`, `waiting`, `nextWaiting`, hence `Attention`, notifications, dock badge and the tab bar include remote agents (titles through `withMachine`), while `snapshot`, `tree` and `spaces` and every space command stay local; `remoteTree(machine)` feeds `sidebar/machines-section/` (state, incompatible version message, greyed and inert when not connected, context menu Reconnect and Check: `Machines.check` runs `machine.check`, the result is one line under the machine). SSH config hosts (#863): `poimen_core::ssh_config::hosts(home)` reads only the `Host` names of `~/.ssh/config` (`Include` followed, patterns left out, missing file is empty), command `ssh_config_hosts` (`machines::ssh_hosts`, configured ones marked) feeds the suggestions of `MachineForm`. Not done yet: actions on remote spaces (rename, close, new terminal, #693). Install or update the server (#865, ADR 0013): `src-tauri/src/server_install.rs` (`prepare`: read-only `uname -sm`/`command -v` probe and, here, the download of `poimen-server-<version>-<target>.tar.gz` and `SHA256SUMS` with the check; `run` after the confirmation: `mkdir` staging, `tar -xzf -` from stdin, `--version` of the staged binaries (version and protocol), `mv`, `command -v`; a failed step removes the staging dir and keeps the old files; `Remote`/`Fetch` traits faked in tests, `Ssh`/`Curl` real; commands `machine_install_plan`/`machine_install_run`/`machine_install_cancel`, event `machine:install_step`; a server not on the non-interactive `PATH` is recorded as `serverPath` in the machine's entry (`machines::set_server_path`, kept by `save_machine`) which `SshConnector` runs). Frontend `core/server-install.ts` (`ServerInstall`, `serverInstallOffer` in `core/machines.ts`) and `machines-page/server-install-dialog.ts` (Cancel default, nothing runs before "Install/Update on <machine>"). Connection sharing (#1012): `src-tauri/src/machines/ssh_mux.rs` adds `ControlMaster=auto`, `ControlPersist=600` and `ControlPath=/tmp/poimen-ssh-<uid>/%C` to every ssh call of `SshConnector` and `server_install::Ssh` (`server_install/ssh.rs`; the ssh arguments are in `machines/ssh_args.rs`) (the directory is created `700`, owner and mode checked before use, a wrong one turns the reuse off with a warning; the uid is read from a probe file because the code base forbids `unsafe`). A `ControlMaster` (other than `no`) or `ControlPath` the user's config sets for the host (`ssh -G`) wins and nothing is added; Windows gets nothing. A stale socket (`ssh -O check` fails) is removed before a connect, and an install step that fails with a stale-socket error removes it and runs once more. Tests never run ssh.
- Actions on remote spaces (#693): ids of a machine are qualified `<machine>::<id>` (`qualifyId`/`splitId` in `core/snapshot.ts`); the Tauri commands for rename, close, new terminal, split, tab, agent start/rename/prompt and `subagents_watch` route by that machine part (`lib.rs::on_routed`, `machines::route_id`, never the local backend for a machine's id) and qualify the ids they return. The frontend disables the actions of a machine that is not connected with the reason (`machineBlock`, `Machines.blockedReason`; sidebar menu entries `disabled`; `PaneActions`/`SpaceActions`/`AgentPrompts` refuse without sending). Transcripts (Flow, Output) of a remote pane are not read yet: the files are on the machine and the server has no request for them, so `subagents_watch` watches nothing for them.
