# CI, Renovate, security and signing

The CI workflow, Renovate, security features and macOS signing. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `.github/workflows/ci.yml`: the `changes` job outputs `frontend` (`src/`, Node/Angular config), `rust` (`src-tauri/`, `rust-toolchain.toml`) and `app` (either, because the app crate embeds the built frontend); a change of `ci.yml` sets all. Jobs of an untouched area are skipped: `frontend` (check, lint, format, test, build), `rust-server` (fmt of the workspace, clippy and test of `poimen-protocol`, `poimen-client`, `poimen-server`, `poimen-core`, `poimen-console`, `poimen-pty-host`; no Tauri libraries, no frontend build), and on `app` the `rust` job (app crate `poimen-app`: clippy and test with the Tauri Linux libraries and the built frontend) and `windows` (tests of the server crates, clippy of the app crate), all through GravionLabs/ci `@v1`. Its always-running `ci` gate job (needs every job; green when the checks passed or were skipped) and `pr-checks / PR checks` (`pr-checks.yml`: readiness, Conventional Commit title) are the checks required on `main` and `release/**`.
- cargo-deny (#1021): the `cargo-deny` job of `ci.yml` (area `rust`, needed by the `ci` gate) runs `cargo deny --locked check` through `EmbarkStudios/cargo-deny-action` (pinned to a SHA) with `src-tauri/deny.toml`: advisories (yanked crates denied), licenses (an allow list of the licenses in the graph; a new license is a decision, add it with the reason in the pull request), sources (crates.io only). An exception (advisory `ignore`, `[[licenses.exceptions]]`) needs a `reason` containing `expires YYYY-MM-DD`; the fixed ratchet `deny-exceptions` fails without both and after the date. Locally: `cd src-tauri && cargo deny --locked check`.
- Renovate (#729): `.github/renovate.json5`, run by `.github/workflows/renovate.yml` (weekly, Monday 03:00-04:00 UTC, and `workflow_dispatch` with a dry run) with a token of the GravionLabs CI app (`CI_APP_ID`, `CI_APP_PRIVATE_KEY`), so its pull requests start CI; `renovate-config.yml` validates the file on pull requests. It updates `npm` (root and `site/`), `cargo` (`src-tauri`, `vendor/` ignored) and `github-actions` on the default branch, before 6am on Monday (`Europe/Zurich`), as `chore(deps)` pull requests in groups (angular, tauri, xterm, codemirror, rust patch/minor); exactly pinned packages stay pinned; the preset `github>GravionLabs/ci` holds a release back for 7 days (security fixes and `GravionLabs/ci` itself exempt) and pins actions to commit SHAs; vulnerability alerts (label `security`) come at once, all in one pull request (`groupName: security`); its pull requests target the default branch, not `release/next`, which is for the work of a milestone (owner decision 2026-11-18, #911; #1243 reversed this by mistake, #1253 undid it); `.agents/` (skills and templates for other repositories) is not scanned; the readiness check needs no `Closes #n` (GravionLabs/ci#273, since v1.19.0); the dashboard is the issue `[PBI] chore: Dependency Dashboard`. No automerge: a person reviews and squash-merges like any work PR; a change of only a lockfile still runs its area's CI job (`pnpm-lock.yaml` frontend, `src-tauri/Cargo.lock` rust, `site/` the Pages dry run).
- Security features (#729): CodeQL (`codeql.yml`, advanced setup: `javascript-typescript`, `rust`, `actions`, on pushes and pull requests to `release/next` and `main` and weekly; not a required check, `ci` stays the only one), Dependabot alerts (alerts only, security updates off, Renovate opens the pull requests), secret scanning with push protection and private vulnerability reporting (`SECURITY.md`); these are repository settings, not files.
- macOS signing (#45): `release.yml` signs and notarizes the arm64 app and its sidecars from the `APPLE_*` secrets (`scripts/macos-signing.sh plan|verify`, tested by `macos-signing.test.sh`; docs/releasing.md). A stable release without them fails, rc/beta/fork builds are unsigned with a warning.
- Path rules (#1022): `scripts/changed-paths.json` (`frontend`, `rust`, `rustAll` regexes) is read by the `changes` job (`node scripts/check-changed.mjs --github-output <base sha>`) and by `pnpm check:changed [base]` (default `origin/release/next`; changes since the merge base, uncommitted and untracked files included). It runs ratchets, the frontend steps when `frontend` matches, and `cargo fmt --check`, clippy and test of the changed crates plus their dependents (path dependencies in `Cargo.toml`; `rustAll` paths select every crate), and prints what it ran and skipped. `--dry-run` prints the plan only. Tests: `scripts/check-changed.test.mjs` (in the `ratchets` job).
- Ratchets (#947): the `ratchets` job of `ci.yml` (always runs, no dependencies) runs `node --test scripts/ratchets/core.test.mjs` and `node scripts/ratchets/run.mjs`; the `ci` gate needs it. GravionLabs/ci workflows and actions are pinned to a commit SHA with the version as a comment (the `@v1` above predates that; `AGENTS.md` has the current rule).
- Issue forms (#1023, #1145): `.github/ISSUE_TEMPLATE/bug_report.yml` is for users (version, OS and package, steps, `poimen doctor`); `bug_internal.yml` is for bugs the team finds itself and renders the body of a PBI (Overview, Repro, Acceptance Criteria, Technical Notes, then the `Tier:` and `Size:` lines and `## Definition of Done` that `planner refine` reads). A form cannot set a milestone: `github-milestone assign` after creating the issue.
