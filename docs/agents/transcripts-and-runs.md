# Transcripts, token totals and agent runs

Transcripts, the Flow tab, token totals, `run.events` and the Runs view. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `src-tauri/crates/poimen-core/src/transcripts.rs` (moved from the app crate in #698, with `copilot.rs` and its fixture; the app uses it through `use poimen_core::{copilot, transcripts}`): read-only Claude Code transcripts (`~/.claude/projects`): path resolution, tolerant JSONL parsing (unknown entry types and fields are skipped), running/done detection, a `Tailer` per file and a `notify` watch (`watch_dir`) emitting `subagents` events; `subagents_watch`/`subagents_unwatch` commands (agent, session and cwd come from `agent_session::session_of`). `copilot.rs` (same crate) is the second transcript source: GitHub Copilot CLI's `~/.copilot/session-state/<session>/events.jsonl` (main session and subagents in one file, fixture `fixtures/copilot-events.jsonl`) mapped onto the same wire types (`task` as `Agent`, `skill` as `Skill`), so the frontend has no Copilot-specific code; which agents are followed is `supportsFlow`/`flowSession` in `core/snapshot.ts`. Remote panes (#698): `transcripts::open`/`Follow` is what `poimen-server` runs for `agent.transcript` (a reader per terminal and follower, files of the server's own home, docs/protocol.md "Agent transcripts"); the app's `subagents_watch` routes a `<machine>::<id>` pane through `Machines::route_connected` (an offline machine is an error, never the local files) and `remote_transcripts.rs` polls the request every 1.5 s, emitting the same `subagents` events; the views show the machine's block as the empty text (`machineBlock`). Frontend side: `core/transcripts.ts` (wire types, `transcriptItems` model reusable by other panel tabs, `Subagents` service) and `src/app/bottom-panel/` (tabs, subagent dropdown, Output tab; state in `core/ui-state.ts`). The Flow tab: the tracker also emits a `main` update (Skill/Agent calls of the main transcript with results, count of other tool calls); `core/flow-graph.ts` (pure: nodes and edges from agents, their entries and the main snapshot; nesting by tool use id, else `spawnDepth`) and `core/flow-layout.ts` (`@dagrejs/dagre`) feed `bottom-panel/flow-view.ts` (`@foblex/flow`, lazy via `@defer`). Both libraries are pinned exactly. Token usage: `transcripts::parse_usage` reads `message.usage` (missing or malformed is `None`, never an error); `Entry` carries `usage`/`model`/`message_id`, `MainCall.context` the context fill of the calling message, and `Update::Main.usage` one `UsageSample` per main assistant message id (the last line of a message wins); `flow-graph.ts` sums per node (skill: owner's messages between call and result; subagent: its own file) and the Copilot log has none, so its token row is hidden. Events tab (#481): `bottom-panel/run-events.ts` (pure: `runsOfSpace` newest first by start, `selectRun`: the pick while `pickHolds` (dropped when a run starts after it, it is gone or the repository changes), else the running non-stale run of `host["poimen.terminal"]` with the latest `updated`, else its latest run, else the latest run of the repository; `toneStyle`) lists `Run.events` of `progress_events.rs` (one row per known event, plus `host`) from the `Deliver` cards, no second watcher. Watches are keyed by follower (`subagents_watch { key, terminalId }`, events carry the `key`): the root `Subagents` follows the panel's pane, a flow editor tab (`poimen:flow:<paneId>`, `src/app/flow-tab/`) provides its own instance for its pane and stops the watch when it is destroyed.
- Token totals (#895): `poimen_core::transcripts::{UsageReader, UsageSum, Totals, watch_claude_usage}` and `copilot::{parse_usage_line, watch_usage}` read only usage (message ids counted once, subagent files included); command `tokens_watch(terminal_id)`/`tokens_unwatch` (`lib.rs`, one watch per agent pane, a machine's pane through `remote_transcripts::start` folded by `UsageSum::apply_json`), event `tokens {terminal_id, totals}`; frontend `core/token-totals.ts` (`TokenTotalsService`, fed by `App` from `SpacesStore.panes`), shown by the sidebar (agent row tooltip, space row sum). Tokens per run (#896): the `tokens` event also carries `samples` (`Sample`: message time and counts, `UsageSum::add_at`); `TokenTotalsService.samples` keeps them per terminal (kept when a watch fails, so an offline machine keeps its last ones) and `Deliver.tokensOf` sums the ones of `host["poimen.terminal"]` (no `paneOf` fallback) between the run's start and its last event (`now` while it runs), shown on the timeline line and in Running now of `deliver-view`.
- `src-tauri/crates/poimen-server/src/runs.rs` (#692): `run.events` for subscriptions with `run_events` (`EventsSubscribe.run_events`, additive, protocol 6; `docs/protocol.md` "Runs"). `Runs::scan` reads the run files (`poimen_core::agent_events::{run_of, LineTail}`) of the repositories of the space and running terminal cwds (`Repos::resolve` over `poimen_core::git::roots`, cached 30 s per directory, one per common dir) and returns each new complete JSON object line unchanged (chunks of 500; truncation reads again; removed files and repositories are dropped; a file older than 25 h is followed only while its subject, from its first line, is the subject of a file changed within 25 h, and not older than 14 days (#783); `deliver::recent` applies the exact rule to the remote runs in `remote_runs.rs`); it keeps the events read so far for `replay`. `Shared::follow_runs` runs every `POLL` (500 ms) in a `serve` thread only while a subscriber has `runs`, else it clears the state; `add_subscriber` sends the replay under the `runs` lock before listing the subscriber (lock order `runs` then `subscribers`), so a (re)connect gets the runs from the start and then every event once. Tests: unit tests in `runs.rs`, `tests/runs.rs` (temp git repository, in-process server).
- `src-tauri/src/deliver.rs` and `src-tauri/crates/poimen-core/src/agent_events.rs`: read-only view of agent runs (#480, #544). poimen depends on the agent-events **core** only (GravionLabs/agent-events ADR 0001: displays are core readers, a profile is never required; profiles and unknown types and fields are ignored). Primary source: `<common-dir>/.agents/events/<run>.jsonl` of the repository (`git rev-parse --git-common-dir`, `git::common_dir`; file names must be a run id of the jsonl-file binding). `agent_events::Reducer` (pure, clock and pid check are parameters) folds the events into the core run state (`run-state.schema.json`: `status`, `subject`, `progress`, open `tasks` with last `step`, `finished` per outcome, `attentions`, `needsYou`, `links`, `gaps`) plus `tone` (of `run.finished`, else of the last event), `host`, `agent` and one `events` row per known event; it passes every reader fixture `fixtures/state/*.jsonl` with its `<case>.state.json` (`src-tauri/crates/poimen-core/fixtures/agent-events/`; the pinned tag is the `tag:` line of its `SOURCE.txt`, the one place it is recorded; to update copy `fixtures/state/*` of the new tag and change that line). Events of another `v` are skipped and reported (`Read::Events.unknownVersion`); `abandoned` = no `run.finished` and the last event older than an hour, or `host["jsonl-file.pid"]` gone. `Tailer` replays each file from the start and then follows it from its offset up to the last complete line (`agent_events::LineTail`, shared with the server) (a half-written last line waits; truncation replays; only regular files up to 16 MiB; files and finished runs older than 24 h are left out, at most 12 runs; #783: `agent_events::RECENT_SECS` 24 h, `MAX_RUNS` 12 per repository, `SUBJECT_KEEP_SECS` 14 days, `MAX_SUBJECT_RUNS` 50: a subject is shown when one of its runs is inside the 24 h/12 limits, then every run of it with a last event at most 14 days old is kept, the newest 50 per subject, not counted in the 12; the subject of a file older than 25 h comes from its first line only (`agent_events::first_subject`) and the file is replayed only when the subject is shown; files unchanged for 14 days are not opened; the backend does not know whether a milestone is open, the frontend leaves out the closed ones). `read_all(root, events_dir, tailer)` gives `Read::Events` when there are runs (or an unknown `v`), else falls back to the legacy `<repo>/.agents/deliver-loop/status.json` (`read(root)` as `Read` missing/ok/unsupported/invalid: regular file, 1 MiB cap, other `schemaVersion` is `unsupported`; to be removed in a follow-up). `watch(root, emit)` follows both with `notify` (non-recursive on the deepest existing directory of each path, re-armed when directories appear; no polling) and emits only changes; command `deliver_watch(dirs)` watches one root per repository (`git::repo_roots`, worktrees share the events), `plan` diffs the watched set, events `deliver { root, read }`. Frontend `src/app/deliver/`: `deliver-status.ts` (pure: tolerant `parseStatus` of a core run, `fromLegacy` maps the legacy status file onto the same shape, `cardsOf` = one card per run, `runState`/stale rule `STALE_MS` (abandoned = stale), `barSummary` for the status bar with its warning from the tone; the Runs view model of #584: `groupRuns` (key = repository qualified by machine + `subject.kind` + `subject.id`, a run without subject a group of its own, runs newest first by start), `runSections` (Running now = a `running` run that is not stale, else History, each by last update), `needsYouItems` (`needsYou` attentions of all runs, once per group, task and reason), `leftOpen` (open tasks of a finished, abandoned or stale run; step `merge` is waiting for merge with its pull request; a task whose subject a later run of the group started or finished is hidden), `timelineLine` (`spanText`, outcome with `text ?? reason` (`outcomeText`, #622), pull requests, skipped/left open/waiting counts, the `success`/`info` attentions as notes), `attentionTone`/`isAlert` (an attention's own `tone`, else the tone of the `attention` events of its task when they agree, else `warning`; Attention lists only needs-you and warning/danger)), `deliver.ts` (`Deliver` service: cards keyed by root and run (`cardKey`, qualified by `machine` for a remote card, #692: `cardsOf(root, read, machine)` sets `machine` and qualifies `host["poimen.terminal"]` like `qualifySnapshot`; `cards` = `withMachines` over the `Machines` states: a remote card only while its machine is configured, `offline` while it is not connected, last state kept; the view shows the machine and `offline`, the footer `<machine>:<root>`, no Start loop for a remote run; the Events tab's `runsOfSpace(cards, dir, machine)` takes only the active pane's machine and `runLabel` puts `<machine>: ` in front), watch from the pane directories in `App`, `paneOf` = `host["poimen.terminal"]` else an agent pane in the repository, `startLoop` through `TaskStarter` with the task mode `deliver-loop`, only for a run whose subject kind is `github.milestone`) and `deliver-view`, the Runs view (#584; tab `poimen:deliver` titled "Runs", `DELIVER_TAB` in `core/editor-tabs.ts`, palette "Open Runs"): sections Running now (subject, current task with step bar and text, age, "Focus terminal"), Needs you (hidden when empty) and History (groups collapsed by default); each group head shows its newest run, expanded a timeline of its runs (one line each, expanded: open or left-open tasks, attentions, finished tasks, links, events through `toneStyle`/`eventTime` of `bottom-panel/run-events.ts`); "Start loop" once per local milestone group without a running run; expanded groups and lines persist in `UiState.expandedRunGroups`/`expandedRuns` (newest `EXPANDED_RUNS_LIMIT`); keys Up/Down over group heads and lines, Enter toggles, Escape collapses (`navRows`); `Deliver.reveal(root, machine?)` opens the tab with that repository's newest group expanded under the cursor (#806: `Deliver.apply` records one notification-center entry per `needsYou`/warning/danger attention through `NotificationCenter.recordRuns`, once per machine, repository, run and attention id, the first read of a repository only sets the baseline; the entry carries `deliver {root, machine?}` and a click in `src/app/notifications/` calls `reveal`); colors from `tone` only through the `--h-*` tokens, never from `outcome`; fixture `fixtures/runs-milestone.json` (four runs of one milestone); The Events tab of the bottom panel (#481): `bottom-panel/run-events.ts` (pure: `runsOfSpace` newest first by start, `selectRun`: the pick while `pickHolds`, else the running non-stale run of `host["poimen.terminal"]`, else its latest run, else the latest run of the repository; `toneStyle`) lists `Run.events` from the `Deliver` cards, no second watcher. Milestone overview (#585): `deliver/milestone-overview.ts` (pure: `issueState` = done, needs-you (labels `needs-decision`/`interactive`/`release-test` or a needs-you attention of a running run), in-progress (a running run's open task, an open pull request or an assignee), blocked (open `blockedBy` of `github_issues`), else next, ordered by number; `milestoneIssues` Features with their sub-issues; `subjectMatches` run subject to milestone by `subject.url`, else the `M<n>` of id or title; `buildOverview` falls back to the run subjects when GitHub fails; `taskTitle` gives a bare `#<nr>` its issue title) and `deliver/overview.ts` (`Overview` service: `github_milestones` plus open and closed `github_issues`, read on every card change and every 5 minutes while the view is open, a failure keeps the last state with a hint); the section "Milestones" at the top of the Runs view, expanded milestones in `UiState.expandedMilestones`, and the head of a milestone group shows GitHub's `closed/total` (`Overview.progressOf`), the run's own progress without GitHub. Pane status (#540): `deliver/pane-status.ts` `effectiveStatus(hook, runs, now)` combines the hook status with the runs linked to a pane only through `host["poimen.terminal"]` (not the `paneOf` fallback): a `running` (not stale) run keeps the pane `working` after Stop, `blocked` when the hook is blocked or the run `needsYou` with no open task left (#752: a gate for the human does not block the session while the run still works); stale, abandoned or finished runs leave the hook status, `gone` wins. `Deliver.paneStatus` is applied by `SpacesStore.snapshot` (`setStatusOf`, wired in `App`), so `Attention`, sidebar, tab bar, dock badge and notification center show the same status; `map_hook` is unchanged (harness independent). Remote runs reach the panel through `run.events` of the machine's server (#692, `runs.rs`, `remote_runs.rs`); the pane status rule is not applied to remote terminals, and the TUI (#518) follows later.
- Started agents in the Flow (#1088): `core/flow-graph.ts` `startedTerminals` (terminals whose `started_by`, through `starterId`, is the pane; token totals from `TokenTotalsService`; a terminal gone from the snapshot stays as `closed` with what was last seen) and `withStartedTerminals` (a `terminal` node per started terminal, edge from the main node, no transcript reading); `FlowView` keeps the last seen list and emits `paneChosen` on a click (App opens the pane; a closed node does nothing). Both the Flow editor tab and the panel tab show it, also for a remote pane. A nested Flow of the started agent is not drawn.
