# Changes view and git sync

The Changes tab, line comments, findings and fetch/pull. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `src-tauri/src/changes.rs`: read-only backend of the Changes view: `changes_list(dir, scope)` (`base`: working tree against `git merge-base HEAD <base>`; `uncommitted`: against `HEAD`; files with status, rename source, counts from `--numstat -z`, binary flag, untracked from `ls-files --others`) and `changes_file(dir, scope, path)` (old and new text for the merge view; `binary` / `too_large` over 1 MB without content). `git::base_ref(dir)` (`origin/release/next`, else `origin/HEAD`, never fetches) is shared with `worktree.rs`; without a base the comparison is against `HEAD`. `dir` is validated like `create_space` (`spaces::resolve_dir`, inside a repository).
- `src-tauri/src/git_sync.rs`: fetch and pull from the explorer menu: `git_fetch` (`git fetch --prune`), `git_pull` (fetch, then `pull_refusal` refuses a dirty tree, detached HEAD, no upstream or a diverged branch with the reason, else `git pull --ff-only`) and `git_fetch_all(dir)` (`discover`: `.git` directories up to `MAX_DEPTH`, skips `node_modules` and `.claude/worktrees`, linked worktrees not listed; `PARALLEL` threads; `git-sync-progress` events; `Summary` of updated/current/failed with reasons). Runs through `changes_git::run_git` (`GIT_TERMINAL_PROMPT=0`, timeout). Frontend `src/app/explorer/git-sync.ts` (`GitSync`: status bar lines through `SpaceActions.notify`, then `SpacesStore.refreshRepos` for the ahead/behind badges); menu: Fetch/Pull on a repository, Fetch all on other directories. Reusable for source roots (#318).
- `src/app/changes/`: the Changes editor tab (`changes:<dir>`, kind `changes` in `core/editor-tabs.ts`; "Show changes" in the context menus of a space and of an explorer root, palette "Show Changes"). `changes.ts` (service per tab: `changes_list`/`changes_file` of `src-tauri/src/changes.rs`, scope `base`/`uncommitted`, selection; refreshes on open, on the refresh button and when `Attention.lastChanges` reports a `done` agent whose pane is inside the directory; never polls), `changes-view.ts` (header, file list, keys: Up/Down in the list, `n`/`p` next/previous change; under 900 px always inline) and `diff-editor.ts`, the only file that imports `@codemirror/merge`, `@codemirror/view` and `@codemirror/state` (pinned exactly, lazy via `@defer`): `unifiedMergeView` or `MergeView`, read-only, `collapseUnchanged`, theme from the `--term-*` color tokens through CSS variables so schemes and light/dark need no rebuild. Syntax highlighting lives in the sibling `diff-language.ts` (also the only other CodeMirror importer, with `@codemirror/language`, `@codemirror/language-data` and `@lezer/highlight`, pinned exactly): `languageFor`/`loadLanguage` use `LanguageDescription.matchFilename` and load a language only when a file of it is opened (unknown extension: plain text), `highlightRules` maps lezer tags onto the ANSI palette via `var(--term-ansi-N)`. The inline/side-by-side choice is `changesLayout` in `core/ui-state.ts`. Line comments (#245): `comment-extension.ts` (also a CodeMirror importer: line number gutter click, Shift extends a range on the same side; saved comments and the draft box are block widgets), `diff-editor.ts` keeps the draft and emits `commentAdded`, `line-comments.ts` (service per tab: pending/sent comments per worktree in `UiState.lineComments`, target agent = agent panes inside the directory with a picker for several, `send()` through `AgentPrompts` (`agent_prompt`): comments move to sent only after a `started` outcome, else they stay pending with the error), `comment-prompt.ts` (pure prompt: intro line, per comment `path:start-end`, quoted lines in a fence longer than any backtick run, the comment; over 4 000 characters the body goes through `changes_write_comments` to `<worktree>/.agents/state/comments-<unix seconds>.md` of `changes.rs`, which refuses symlinked `.agents`/`state`, never overwrites and adds `.agents/state/` once to `git rev-parse --git-path info/exclude`) and `comments-panel.ts`. Review findings (#246, `docs/findings.md`, schema `docs/findings.schema.json`): `changes_findings(dir)` of `changes.rs` reads `<worktree>/.agents/state/findings.json` (real directories and a regular file only, 1 MiB cap, serde with `deny_unknown_fields` plus semantic checks, `FindingsResult` none/ok with `stale` = `sha` not a prefix match of `HEAD`/invalid with the error; the diff never fails because of it); `findings.ts` (pure `mapFindings`: located findings per changed file, the rest "other"; `Findings` service per tab, re-read whenever the change list is) feeds read-only finding boxes in `comment-extension.ts`/`diff-editor.ts` (new side) and `findings-panel.ts` ("Other findings"); "Send to agent" on a finding adds a pending comment through `findingComment` (start 0 = no line, path `(general)` = no file). Components here use decorator `@Input`s because the specs run without Angular's compiler transform (signal inputs and queries need it). Optional actions (scope `uncommitted`): a stage checkbox per file (`ChangedFile.staged`), a commit message box and Push in the header, output or error in `.result`; backend `src-tauri/src/changes_git.rs` (`changes_stage`, `changes_commit`, `changes_push`: argv only, paths after `--` and never outside the repo, push never forced and refused on `main`, `release/*` and a detached HEAD, `-u origin <branch>` without upstream, `GIT_TERMINAL_PROMPT=0`, 120 s timeout, URL credentials redacted; commit is allowed on any branch).
