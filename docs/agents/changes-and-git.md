# Changes view and git sync

The Changes tab, line comments, findings and fetch/pull. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `src-tauri/src/changes.rs`: read-only backend of the Changes view: `changes_list(dir, scope)` (`base`: working tree against `git merge-base HEAD <base>`; `uncommitted`: against `HEAD`; files with status, rename source, counts from `--numstat -z`, binary flag, untracked from `ls-files --others`) and `changes_file(dir, scope, path)` (old and new text for the merge view; `binary`; `large` above the soft limit (more than 5 000 changed lines or 256 KiB, constants `LARGE_*`) with only the counts until `force` is passed ("Load diff", #1037); `too_large` over the hard limit (120 000 changed lines or 1 MiB) never offered; both are checked on the numstat numbers and the file size before content is read). `git::base_ref(dir)` (`origin/release/next`, else `origin/HEAD`, never fetches) is shared with `worktree.rs`; without a base the comparison is against `HEAD`. `dir` is validated like `create_space` (`spaces::resolve_dir`, inside a repository).
- `src-tauri/src/git_sync.rs`: fetch and pull from the explorer menu: `git_fetch` (`git fetch --prune`), `git_pull` (fetch, then `pull_refusal` refuses a dirty tree, detached HEAD, no upstream or a diverged branch with the reason, else `git pull --ff-only`) and `git_fetch_all(dir)` (`discover`: `.git` directories up to `MAX_DEPTH`, skips `node_modules` and `.claude/worktrees`, linked worktrees not listed; `PARALLEL` threads; `git-sync-progress` events; `Summary` of updated/current/failed with reasons). Runs through `changes_git::run_git` (`GIT_TERMINAL_PROMPT=0`, timeout). Frontend `src/app/explorer/git-sync.ts` (`GitSync`: status bar lines through `SpaceActions.notify`, then `SpacesStore.refreshRepos` for the ahead/behind badges); menu: Fetch/Pull on a repository, Fetch all on other directories. Reusable for source roots (#318).
- `src/app/changes/`: the Changes editor tab (`changes:<dir>`, kind `changes` in `core/editor-tabs.ts`; "Show changes" in the context menus of a space and of an explorer root, palette "Show Changes"). `changes.ts` (service per tab: `changes_list`/`changes_file` of `src-tauri/src/changes.rs`, scope `base`/`uncommitted`, selection; refreshes on open, on the refresh button and when `Attention.lastChanges` reports a `done` agent whose pane is inside the directory; never polls), `changes-view.ts` (header, file list, keys: Up/Down in the list, `n`/`p` next/previous change; under 900 px always inline) and `diff-editor.ts`, the only file that imports `@codemirror/merge`, `@codemirror/view` and `@codemirror/state` (pinned exactly, lazy via `@defer`): `unifiedMergeView` or `MergeView`, read-only, `collapseUnchanged`, theme from the `--term-*` color tokens through CSS variables so schemes and light/dark need no rebuild. Syntax highlighting lives in the sibling `diff-language.ts` (also the only other CodeMirror importer, with `@codemirror/language`, `@codemirror/language-data` and `@lezer/highlight`, pinned exactly): `languageFor`/`loadLanguage` use `LanguageDescription.matchFilename` and load a language only when a file of it is opened (unknown extension: plain text), `highlightRules` maps lezer tags onto the ANSI palette via `var(--term-ansi-N)`. The inline/side-by-side choice is `changesLayout` in `core/ui-state.ts`. Line comments (#245): `comment-extension.ts` (also a CodeMirror importer: line number gutter click, Shift extends a range on the same side; saved comments and the draft box are block widgets), `diff-editor.ts` keeps the draft and emits `commentAdded`, `line-comments.ts` (service per tab: pending/sent comments per worktree in `UiState.lineComments`, target agent = agent panes inside the directory with a picker for several, `send()` through `AgentPrompts` (`agent_prompt`): comments move to sent only after a `started` outcome, else they stay pending with the error), `comment-prompt.ts` (pure prompt: intro line, per comment `path:start-end`, quoted lines in a fence longer than any backtick run, the comment; over 4 000 characters the body goes through `changes_write_comments` to `<worktree>/.agents/state/comments-<unix seconds>.md` of `changes.rs`, which refuses symlinked `.agents`/`state`, never overwrites and adds `.agents/state/` once to `git rev-parse --git-path info/exclude`) and `comments-panel.ts`. Review findings (#246, `docs/findings.md`, schema `docs/findings.schema.json`): `changes_findings(dir)` of `changes.rs` reads `<worktree>/.agents/state/findings.json` (real directories and a regular file only, 1 MiB cap, serde with `deny_unknown_fields` plus semantic checks, `FindingsResult` none/ok with `stale` = `sha` not a prefix match of `HEAD`/invalid with the error; the diff never fails because of it); `findings.ts` (pure `mapFindings`: located findings per changed file, the rest "other"; `Findings` service per tab, re-read whenever the change list is) feeds read-only finding boxes in `comment-extension.ts`/`diff-editor.ts` (new side) and `findings-panel.ts` ("Other findings"); "Send to agent" on a finding adds a pending comment through `findingComment` (start 0 = no line, path `(general)` = no file). Components here use decorator `@Input`s because the specs run without Angular's compiler transform (signal inputs and queries need it). Optional actions (scope `uncommitted`, #1036): the list has the sections Conflicts (`ChangedFile.conflicted`, unmerged), Staged (`staged`) and Changes (`change-sections.ts`: `sectionsOf`, empty ones hidden, collapsible, Stage all/Unstage all per header; the base scope keeps the flat list); a row shows name, muted directory (cut off first), status and +/−, and on hover/focus Stage/Unstage and Discard (confirmation dialog naming the file; `changes_discard` in `changes_git.rs`; the comment and CI log writers live in `changes_files.rs`: tracked files back to `HEAD`, new-to-index files removed, untracked deleted, not undoable); Shift-click picks a range (`Changes.picked`), Escape clears it, the actions apply to the picked rows; a commit message box and Push in the header, output or error in `.result`; backend `src-tauri/src/changes_git.rs` (`changes_stage`, `changes_discard`, `changes_commit`, `changes_push`: argv only, paths after `--` and never outside the repo, push never forced and refused on `main`, `release/*` and a detached HEAD, `-u origin <branch>` without upstream, `GIT_TERMINAL_PROMPT=0`, 120 s timeout, URL credentials redacted; commit is allowed on any branch).
- Generate a commit message (#997): the "Generate" button next to the commit box (scope `uncommitted`, something staged) calls `changes_generate_message(dir, harness, id)` of `src-tauri/src/commit_message.rs`: `git diff --cached`, over `DIFF_LIMIT` (60 000 bytes) shortened to the file list plus the largest hunks (each cut to 4 000 bytes), a Conventional Commit prompt, then a headless call of the harness (`harness::build_print_argv`: `command` + `printArgs`, `{prompt}` one argv element, no shell, 120 s deadline, a code fence in the reply is stripped). It only fills the box, never commits. While it runs the button reads "Generating… Cancel" (`changes_generate_cancel(id)` kills the process); an error or a cancel leaves the box as it was (error in `.result`). `Changes.messageHarness` is the first harness of `get_harnesses` that is available and has `printArgs`; none hides the button.
- Create a pull request (#996): "Create pull request..." in the Changes header when `changes_pr_state(dir)` of `src-tauri/src/pull_request.rs` says the branch is pushed (`refs/remotes/origin/<branch>`), has no open pull request (`gh pr list --head`, read fresh) and is not the base (`git::base_ref` without `origin/`); read with every list, an error hides the button. The dialog (`changes/pull-request-dialog.ts`, state in the per-tab `CreatePullRequest` service) has base, title, description and a Draft checkbox. "Draft with agent" (`changes_draft_pull_request(dir, harness, base, id)`) uses the same harness call as the commit message (`commit_message::run`, `tracked`, cancel through `changes_generate_cancel`): `git log` and the shortened `git diff origin/<base>...HEAD` in a prompt; the first line of the reply is the title, the rest the body. Create (`changes_create_pull_request`) runs `gh pr create --base --head --title --body-file - [--draft]` with the body on stdin through `Client::mutate_input`, never pushes or forces, then opens the GitHub tab on the detail of the new pull request. A `gh` error stays in the dialog with every field.
- File preview tab (#1004): `preview:<absolute path>` (kind `preview` in `core/editor-tabs.ts`: `previewTab`, `previewPath`, `EditorTabs.openPreview`, at most one pinned tab per file; icon `preview`). Entry points: the Changes header button "Preview" and the file menu entry (`changes-view.ts`; a deleted file has none), the file path link menu of a terminal (`terminal-view/file-link-actions.ts`: Open in editor, Preview, and Show in Changes for a changed file; the menu now opens for every existing file, a plain click still opens nothing new) and the palette entry "Preview File" (the file `Changes` reports in `EditorTabs.changesSelection` for the active Changes tab). `src-tauri/src/file_preview.rs`: `preview_read(path)` (absolute regular file; `text`, `binary` = NUL in the first 8 KiB or not UTF-8, `too_large` over 1 MiB, never read), `preview_watch`/`preview_unwatch` (notify on the parent directory so a replace through rename is seen; a `file-preview` event `{ path }` after each change, bursts coalesced). `file-preview/file-preview.ts` reads on open and on every event for its path; Markdown goes through `renderMarkdown` (`github/markdown.ts`, DOMPurify) with a Rendered/Source toggle, links open in the browser only for `http(s)`; other text and the Markdown source use `file-preview/source-view.ts` (read-only CodeMirror with `diffThemeRules`, `diffHighlight` and `loadLanguage` of the diff editor; a new text replaces the document in place so the scroll stays). "Open in editor" is `ExternalEditor.open`. Local files only (no machine paths).
