# Frontend shell

Angular app structure, tab layout, terminal search and sidebar order. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `src/app/tab-layout/` (#514): the editor tab of a split tab (poimen backend, `Tab.root` a split) renders one `terminal-view` per leaf through nested `app-split-pane`s (direction and ratio from the tree; decorator `@Input`s for the specs). A divider drag emits `ratioChange` with the `split_id`; `PaneActions.resizeSplit` sends `tab_resize_split` (`Backend::resize_split`, `tab.resize_split`; only the latest ratio per split while a request is in flight). Focus: click, or Alt+arrows (`cycleFocus`, tree order), kept in `App.leafFocus` and sent as `tab_focus` (`Backend::focus_tab`, `tab.focus`); only the focused leaf gets the wanted mode, the others observe. Context menu of a leaf: split right/down, close pane (through `PaneActions`). Each leaf keeps its own stream and size.
- Hidden terminal views (#978): `terminal-view/hidden-views.ts` (`HiddenViews`) decides which pane views of a group stay mounted. `app.html` renders one `app-terminal-view` (or `app-tab-layout` for a split tab) per `viewIds(group)`, tracked by pane id so the instance survives a switch, and `[hidden]` (`display: none` in `app.css`) when it is not the active tab. A view hidden by a tab switch keeps its xterm and stream for `HIDDEN_VIEW_MS` (30 s), at most `HIDDEN_VIEW_LIMIT` (3) hidden at once over all groups, the one hidden longest ago first; coming back shows it without a new attach. After that it is destroyed as before (stream closed, xterm disposed). A hidden view still holds its controller until it expires.
- File path links (#1003): `terminal-view/file-links.ts` (`findPaths`: `path`, `path:line`, `path:line:column`, quoted paths with spaces, `~/` and Windows paths, no URLs; `fileLinkProvider`, an xterm link provider for one buffer line, so a path wrapped over two lines is not found) asks the `resolve_file_links` command (`editor.rs`: relative to the pane's `foreground_cwd || cwd`, only existing files, plus the git root and the path in it) and links only what exists. Cmd+click (macOS) or Ctrl+click opens the external editor (`ExternalEditor`) at the position; a file that is changed against the base (`changes_list`) opens an `app-context-menu` instead with "Open in editor" and "Show in Changes" (`EditorTabs.openChanges(root, file)` sets `changesFocus`, which the `Changes` service of that tab selects). No links on a pane of a remote machine (`offersFileLinks`). `FileLinkActions` holds the actions.
- Recent tabs (#1006): `recent-tabs/` (`app-recent-tabs`, mounted in `app.html`) keeps a most-recently-used order of `EditorTabs.activeId` (not changed while switching) and listens on `window` for `recentTab`/`recentTabBack` (default `Ctrl+Tab`/`Ctrl+Shift+Tab`, literal Ctrl also on macOS). The first press opens a list of the tabs of all groups and selects the next; further presses step (wrapping); releasing the modifier of the chord activates it, Escape or a window blur cancels. These two actions are in `TERMINAL_KEYS` (`core/shortcuts.ts`), so a focused terminal yields them like a Cmd shortcut and xterm does not forward the Tab. `nextTab`/`previousTab` stay positional. Pure helpers in `recent-order.ts`.
- Terminal search (#714): `src/app/terminal-view/search.ts` (decoration colors from the `--term-*` tokens, match label, `TerminalSearch` hub that opens the bar of the terminal view that last had the focus and forgets a destroyed one, so the Settings view keeps its own Cmd/Ctrl+F); `terminal-view` loads `@xterm/addon-search` (pinned) and shows the bar per view; shortcut `find` (`CmdOrCtrl+Shift+F`; macOS through the Edit menu item, elsewhere the view's key handler) and palette "Terminal: Find". xterm searches what it holds: the attach snapshot plus later output.
- Tab order in the sidebar: `UiState.tabOrder` (`tab_id`s per `space_id`, `core/ui-state.ts`) is the user's order of the tabs of a space; `orderTabs` (ids of the order first, new tabs by number) is applied in `buildTree`/`buildSpaces` of `core/snapshot.ts`, the only places that list tabs of a space, so pane rows follow it; `SpaceActions.reorderTabs` writes it from a drag in `sidebar`; `spaces-store.ts` prunes closed tabs and spaces on every snapshot read; drag is disabled while a filter is active.
- `src/`: Angular 22 (standalone components, signals) on helix-ui, built with `@angular/build` (`angular.json`), tested with Vitest. `src/app/core/` is the Tauri bridge and state: `tauri.ts` (the only `invoke`/`listen` caller), `snapshot.ts` (the neutral model of spaces, tabs and terminals, pure helpers), `backend.ts` (events, stream records, version labels, agent kinds), `spaces-store.ts` (`SpacesStore`: snapshot signals, debounced re-read), `terminal-stream.ts` (opens a stream with a `Channel`; streams deliver PTY bytes as `bytes` records, no early-frame buffering). `src/app/terminal-view/` wraps xterm.js for the active editor tab (`core/editor-tabs.ts` holds tabs, preview/pinned and mode; `src/app/ui/helix-candidates/tab-bar/` is the generic tab bar, a helix-ui candidate); `src/app/sidebar/` shows the spaces as cards (`app-space-card`; `src-tauri/src/git.rs` answers the read-only `repo_info` command with branch and worktree per directory); the view rail is `hx-activity-bar` of helix-desktop fed by `core/activity-items.ts` (`ACTIVITY_ENTRIES`, `activityItems`, `tabOf`; SVG templates in `app.html`); `src/app/notifications/` is the notification center view over `core/notification-center.ts` (in-memory list fed by `Attention` status changes); `core/ui-state.ts` holds persisted UI state (sidebar width/collapsed), never pane state. Space order: `UiState.spaceOrder` (`space_id`s) is applied by `orderSpaces` in `core/snapshot.ts` (stored ids first, new spaces by number, closed ones pruned on snapshot reads); `SpacesStore.tree`/`spaces`/`orderedSpaces`, `neighbourSpace` and the sidebar all read it, `SpaceActions.reorder`/`shift` change it (drag and drop in the sidebar, off while a filter is active; palette "Move Space Up/Down"). Pins (#710): `UiState.pinnedSpaces` (`space_id`s, pruned with `pruneSpaceOrder`) is the fourth argument of `orderSpaces`, which puts pinned spaces first in every sort mode (a pinned worktree head brings its members, a pinned member is first among its siblings); `SpaceActions.setPinned`, space menu "Pin space"/"Unpin space" (local spaces only) and palette "Pin Space"/"Unpin Space". `core/attention.ts` keeps in-memory UI marks derived from agent statuses: a pane that turns blocked while not viewed rings on its tab and sidebar row, one that turns done while not viewed counts as unread (workspace rows sum their panes); viewing the tab (active tab of a group) clears both. Viewed (#1030) also needs `core/presence.ts` `Presence.present` (window visible and focused, pointer, key (capture phase, xterm stops keydown) or wheel input within `PRESENCE_MS` = 60 s): an agent that finishes in an on-screen tab while the user is away is unread, and the marks clear on the first input after the return, not on focus.

- App shell (#930): `app.html` is one `hx-app-shell` of helix-desktop (slots `toolbar`, `activity`, `sidebar`, `status`; the editor area and the bottom panel are the default slot,). The shell owns the splitter (limits `SIDEBAR_MIN_WIDTH`/`SIDEBAR_MAX_WIDTH`, step 10, Shift 40) and reports through `sidebarChange` to `App.onSidebarChange`, which persists via `UiState`; the activity bar still goes through `UiState.selectView`, so the shell's own `activeId` is unused. The sidebar view sits inside `@if (!ui.sidebarCollapsed())` because the shell only hides its slot. `app-toolbar` is a wrapper (`display: contents`) around `hx-app-toolbar` (26 px, `windowButtonsInset` off) with the Output and theme buttons in `slot="end"`.

## Status bar (#931)

`app-status-bar` renders `hx-status-bar` (helix-desktop) in the `status` slot of the shell; every entry is an `hx-status-item` (`kind="button"` for actions, `tone` for warnings and errors, no CSS classes of poimen for them). The bar is not a live region: only items whose value changes by itself set `[announce]="true"` (connection, run summary, limits, waiting, notices, update progress). An `@if` block projects only with a single root element, so every item has its own `@if`, and the update switch sits in `<ng-container ngProjectAs="[slot=end]">`. A boolean input needs a binding (`[announce]="true"`): the bare attribute is the empty string. The update details stay a `position: fixed` section until the updater PBI moves them into the item popover.

## Sidebar cards (#934, #1111)

The sidebar renders `app-space-card` (`src/app/sidebar/space-card.*`) per node of `spaceNodes`; it is the only layout (#1111): the tree, the `split` layout with its Agents section and the `sidebar.layout`/`sidebar.agents` settings are gone, and an old value of either key in a config is ignored without a warning. The `⋯` button and a right click ask `Sidebar` for the context menu of the space or pane. Collapsed cards are `UiState.collapsedCards`, pruned in `SpacesStore.refresh`. The component uses decorator inputs because the specs run without the compiler transform, and specs that override the `Sidebar` template call `inlineSpaceCard()` (`space-card.mock.ts`). The console TUI has its own tree and is not part of this. Card states (#935): the card reads the signals of `Sidebar` (attention, unread, rebuild marks). It rings as a whole (`.card.attention`, text on the tint uses the `-on-active` tokens, checked in `sidebar-contrast.spec.ts`) while a pane of the space is in `Attention.attention`; the header carries the pin mark, unread count, the longest silent mark, the rebuild marks (`SpaceRebuild.marks`, only for a space without terminals) and "Closing…"; the status dot is the aggregate, so a collapsed card shows the most urgent one. Double click on a space or terminal name renames inline (`SpaceActions.rename`, `PaneActions.rename`; Enter saves, Escape cancels, a failure keeps the input). Organization (#936): the card list is `nodes()`, so grouping (`sidebar.groupWorktrees`), pins, sort and filter come from `orderSpaces`/`filterSpaces` and the card never sorts; a linked worktree's card has `.member` (indented). A filter shows a card expanded without touching `collapsedCards`. Drag and drop reuses the `Sidebar` handlers (`dragStart`/`drop`, `tabDragStart`/`tabDrop`): the card forwards the DOM events and gets `spaceDraggable`/`tabDraggable`/`dragMark`/`tabMarks`; off outside `manual` sort and while a filter is active. Pin/Unpin is in the shared `⋯` menu. Keyboard and ARIA (#937): `.cards` is a `tree`; the card header (`.title`) and each row are `treeitem`s (`aria-level` 1 and 2+depth, `aria-expanded` on headers, `aria-selected`) carrying `data-nav` (space id or terminal id); `card-nav.ts` is the pure part (`cardItems` in display order, `cardNav` key to target, `tabStop`), `Sidebar.onCardKey` applies it (Up/Down/Home/End, Right/Left expand/collapse or step in/out, Enter opens a row or toggles a header; keys with a modifier, buttons and inputs are left alone so the window shortcuts work). Remote machines (#938): the machines section renders each space of `SpacesStore.remoteSpaces(machine)` (`remoteTree` with pane rows) as an `app-space-card` built by `Sidebar.remoteNodes` (`spaceNodes`). A card gets `blocked` = `Machines.blockedReason` of its machine: greyed (`.offline`), `+`, close and `⋯` disabled with the reason as tooltip, rename and menu inert; a remote card has no configure button, no overview on header click, no pin and no drag; ids are qualified (`<machine>::<id>`), so the fold state in `collapsedCards` is under the qualified id (pruned with the local and remote space ids; `keptCardIds` keeps the marks of a machine that lists no space yet). Origin (#1074): `SpaceCard.origin` puts an `.origin-mark` svg (`role=img`, `aria-label` `This computer` / `Machine <name>`, tooltip adds the `blocked` reason, muted on an `.offline` card, not a button) in the header and the label into the card's accessible name; a machine card also gets a 3px stripe (`.card.origin::before`, inside the border so the `.member` indent stays) in `--origin-<n>` (`styles.css`, six tokens, `n = originColor(name)` a hash of the machine name; 3:1 checked in `sidebar-contrast.spec.ts`). No machine configured: no symbol on any card. Roving tabindex: only `Sidebar.cardStop` has `tabindex=0`; the action buttons of a header and the buttons in a row are tabbable only while their header/row is the stop, the fold button never (the header's `aria-expanded` covers it).

## Component templates (#1051)

Every component under `src/` (outside `*.spec.ts`) has its template in a sibling `.html` file (`templateUrl`), so the ESLint template and accessibility rules see all of them; inline `styles` are fine. oxlint fails on an inline `template:` in a `@Component` outside spec files (`poimen/no-inline-template` of `scripts/lint/oxlint-plugin-poimen.mjs`, proved by `src/testing/lint-probe.spec.ts`); test hosts in spec files keep inline templates. Specs run with JIT and without the Angular resource transform, so `vitest.config.mts` inlines a `templateUrl` as `template` when Vitest loads a component (`styleUrl` is not inlined: specs still override it).

## Lint and format (#1052)

`pnpm format` and `pnpm format:check` run oxfmt (`.oxfmtrc.json`; `src/app/**/*.html` as Angular templates). `pnpm lint` runs oxlint on the TypeScript (`.oxlintrc.json`, migrated from the former ESLint rules, the Angular class rules through `@angular-eslint/eslint-plugin` as an oxlint JS plugin, poimen's own rules from `scripts/lint/`; type-aware through `oxlint-tsgolint`: floating and misused promises and `await` of non-promises are errors, `restrict-template-expressions` and `no-base-to-string` warnings) and then ESLint on the `.html` templates only (`eslint.config.mjs`), because oxlint cannot parse Angular templates. Suppress a TypeScript finding with `// oxlint-disable-next-line <rule>`, a template finding with `<!-- eslint-disable-next-line <rule> -->`. JS plugins are alpha: oxlint, oxfmt and the plugin are pinned to exact versions, and `src/testing/lint-probe.spec.ts` lints the deliberate violations of `src/testing/lint-probe/` (left out of `pnpm lint` and the build) and expects every rule id. Not covered by oxlint: `no-octal` (a syntax error in TypeScript modules anyway) and `no-useless-assignment` (nursery in oxlint, reports a false positive on a class field initializer). The reformat commit of the switch is listed in `.git-blame-ignore-revs` (`git config blame.ignoreRevsFile .git-blame-ignore-revs`).

## Space card header (#1075)

The state word is shown only for `blocked` and `error`. Gear, close, pin, copy path, details and the sort entries are entries of the `…` menu (`sidebar/card-menu.ts`).

## Component fixtures and screenshots (#1020)

Look at a presentational component without Tauri: `pnpm fixtures:list` prints the fixture ids (`<component>/<state>`), `pnpm fixtures:shot <id>` (or `--all`) writes `tmp/shots/<id>.light.png` and `.dark.png` through headless Chromium against the `fixtures` dev server (`ng run poimen:fixtures`, port 1421, entry `src/fixtures/main.ts`; a server that already answers is reused). Use it after you change the markup or CSS of a component that has fixtures, and read the PNGs, before you start the Tauri app; it is not a test and checks nothing.

- A fixture file sits next to its component, `<component>.fixtures.ts`, exports `Fixture[]` (`src/fixtures/fixture.ts`: id, title, component or a host with projected content, inputs, providers, viewport) and is added to `src/fixtures/registry.ts`. Names are states ("danger", "overflow"). Fixtures use fixed inputs and stub the services (`space-card.fixtures.ts`); a component that needs the backend does not get one. Inline templates and any selector are fine in a fixture host (lint exempts `*.fixtures.ts` like specs).
- Start: dialog shell, context menu, space card (header), tab bar, status bar.
- The Playwright setup is shared in `scripts/browser/playwright.mjs` (`withBrowser(target, fn)`: Chromium install, dev server start, light/dark through `prefers-color-scheme`, `outDir()`). Whole-app shots (#1109) use it with `TARGETS.app` instead of a second setup.

- Unread mark (#1031): `--status-unread` is derived in `deriveTokens` (`unreadColor`): of ANSI magenta, cyan and their bright variants the one farthest from working, blocked, done and error, moved to 3:1 on the background; `status-colors.spec.ts` checks both in every bundled scheme. The dot (tabs, cards, all-tabs menu) and the count badge use it; the name of an unread terminal or space is semibold (`.unread-name`, tab `.unread-label`) and carries a global `.sr-only` "Unread: " text.

- Tab strip (#1032): `ui/helix-candidates/tab-bar/tab-bar-rules.ts`: `tabWidth` shares the strip between 144 and 320 px (set as `--tab-width`; the strip scrolls only when all tabs are at the minimum), `dropSide` picks the edge of the 2px insertion bar (`::before`/`::after`, tabs never move during a drag). The active tab is `position: sticky` left and right. A tab is activated on `pointerup` (button 0; a keyboard click has `detail` 0), so a drag never switches tabs. A tab opened in the background is revealed after `pointerleave` of the strip.

- Icons (#1033): all icons live in `src/app/ui/icon/icon.ts`. The tab kinds (GitHub, Runs, Space overview, Changes, Flow, Settings, read-only, input) are outline icons from Lucide (ISC license, <https://lucide.dev>), 24×24, 2px stroke, shown at 16 px; new ones come from Lucide too. `app-icon` is decorative unless it has a `label` (accessible name and tooltip). `TabBarItem.icon` and `MenuEntry.icon` carry the icon into the tab, the "All tabs" menu and (as `JumpEntry.icon`) the jump palette. An agent tab keeps its status dot.

- Status bar density (#1034): `status-bar/status-density.ts` (`nextLevel`, `densityFlags`) is the pure part; `StatusBar` measures the sum of its `hx-status-item` widths against the bar (`ResizeObserver`, no breakpoints), remembers the width needed at each level and steps down one level on overflow, back up only when the measured wider level fits. Order: 1 the limits show the tightest window (`LimitsItem.text`, the full list is `full`), 2 the Runs summary shows mark and count (`shortRuns`, from the `barSummary` text), 3 the Output button, the mode button and `awake` show the icon only (title/aria-label keep the text). The connection and "N waiting" never change. The bar is `overflow-x: clip; overflow-y: visible; white-space: nowrap` with items `flex: none`. Nothing in the status bar clips on the block axis (#1168): the popover of an `hx-status-item` is `position: absolute` above the item, so `overflow: hidden` on the bar hides it; `e2e/status-bar.spec.ts` pins it in a real browser.

- Inline terminal rename (#1035): `PaneActions.renaming` (the terminal id being edited), `renameBusy`, `askRename`, `cancelRename`; the rename dialog of `app-pane-dialog` is gone. Double click on the name, F2 on the focused row (`paneEdit.onKey` on the `.cards` tree) and "Rename" in the row or tab menu (`paneAction` -> `askRename`) all set it; the card row (`.edit`) renders the field. Enter and blur save, Escape cancels; an Enter with `isComposing` or keyCode 229 (`sidebar/rename-keys.ts`) saves nothing. The field is disabled while the call runs; a failure shows `PaneActions.error` inline, keeps the text and refocuses the field.
- Jump palette rows (#1038): a row shows the time since `Attention.changedAt` of its pane ("3m", `shortAge`) and, when the filter matched outside the name, a second line with the field (branch, directory, pull request) and the matched text highlighted (`matchContext` in `core/jump-palette.ts`). `JumpPalette.announcement` feeds an `aria-live` status region with the result count.
- Tooltips (#1039): `hx-tooltip` (helix-ui 22.6) replaces `title` on icon-only controls: sidebar header, terminal search, tab labels (`hxTooltipWhenTruncated` when the tab has no own `title`), the awake item. `shortcutKeys` (`core/shortcuts.ts`) splits an accelerator into keys and `Keymap.keys(action)` feeds `[hxTooltipShortcut]`, so a config.json override shows. Labeled controls (Output, theme button) lost their `title`. `ui/title-usage.spec.ts` holds the per-file count of `title` attributes (it includes dialog `title` inputs); lower it when you convert.

## UI end-to-end tests (#1156)

`pnpm e2e` (`playwright.config.ts`, tests in `e2e/`) runs the app in headless Chromium against the demo build (`webServer` starts `ng run poimen:serve:demo`, port 1422; a server that already answers is reused locally) in two projects, `light` and `dark`, with a fixed clock (`page.clock.setFixedTime`, same `TIME` as the screenshots), reduced motion and a 1280×800 window. It sees what Vitest cannot: real layout, focus, keys, dialogs. CI runs it on pull requests (job `e2e`, Chromium only, advisory; the HTML report and traces are an artifact on failure).

- **Demo variant** (`openDemo`): the fixed, rich data of `src/demo/poimen/`. Use it for smoke tests of whole views (the app starts, sidebar, Runs, palette, settings open) and for the screenshots. A test ends with `expectNoFailures(page)` (no entry in `window.__demoFailures`) and `expect(errors()).toEqual([])` (no `pageerror`, no `console.error`).
- **Fake variant** (`openFake(page, answers)`, `createFakeBackend` in `src/demo/kit/fake.ts`): answers only the fixed values the test gives (`e2e/fake-base.ts` has `startup()`, what the app calls at start, and a one-terminal `SNAPSHOT`), fails any other command by name, and logs every call. Use it for interaction tests: click, then assert the call (`calls(page)` returns `{ command, args }` in order, `clearCalls(page)` forgets them). Replace an answer or push an event at runtime with `page.evaluate(() => window.__demo!.set("snapshot", …))` and `window.__demo!.emit(event, payload)`. It never talks to a real `poimen-server`.
- **Variant per test, one build**: `src/demo/tauri.demo.ts` reads `?backend=fake` and then builds the fake from `window.__demoFake`, which `openFake` sets with `addInitScript` before the app starts; without the parameter it is the demo. Every `DemoBackend` keeps `calls[]` (`window.__demoCalls`) and `window.__demo`.
- **Add a test**: put it in `e2e/<area>.spec.ts`, open with `openDemo` or `openFake`, use the step helpers of `scripts/screenshots/views.mjs` (`ready`, `openPane`, `terminalShows`, `button`; re-exported by `e2e/support.ts`, shared with the screenshots, never copied), wait on conditions (`expect(...).toBeVisible()`, `expect.poll`, `page.waitForFunction`), never on time (`pnpm ratchets` forbids `waitForTimeout`). A dialog test follows `ui/dialog-shell/dialog-contract.ts`: focus inside on open, Escape closes, the focus returns to the opener. A command the fake lacks fails with its name: add its answer to the test.
- Out of scope: a real `poimen-server` or the built Tauri app (#961), screenshot comparison, other browsers.

## Buttons: colors and usage (#844, moved from AGENTS.md)

Colors come from the tokens only. `src/styles.css` maps helix's button tokens onto the derived chrome (`--app-action*`, `--app-danger-text` from `deriveTokens`); `src/app/ui/button-contrast.spec.ts` checks every variant and state in every bundled scheme. `src/app/ui/button-usage.spec.ts` fails on a new `<button>` without `hx-button`; the tab bar, the context menu and palette items are allow-listed, other files have a legacy count that only goes down (lower it when you convert). Reference surfaces: settings Appearance and the hooks dialog.

## Toasts (#1040)

- One `app-toasts` (`ui/toasts/`, mounted in `app.html`) holds the single `<hx-toast position="bottom-right">`; `app.config.ts` provides `HxMessageService`, and `core/toast.ts` (`MESSAGES`, `injectMessages`, `TOAST_MS`, `TOAST_ERROR_MS`) is how services reach it (a spec without the provider gets its own instance; `src/testing/toasts.ts` has `lastToast` and `testMessages` to read it).
- The stack sits in a `popover="manual"` layer, so it is in the top layer like a modal `<dialog>` and readable above one; every change of the message list shows the popover again, which moves it in front of a dialog opened since.
- `SpaceActions.notify(message, severity)` and `fail(message)` (error, stays 10 s instead of 5 s) are the one entry for results. They no longer touch the status bar `warning`, which is left for layout warnings and "Opened the existing space". The restored-tab notice of the editor area is a toast too.
- A failed settings write (`SettingsStore.write`, the theme, color scheme and sidebar writers, a rejected value, a settings import or export) sets the inline `writeError` and shows an error toast with the reason; nothing is only logged. Export and import results are success toasts.
- Not toasts: lasting states (disconnected, read-only) stay inline or in the status bar; agent events (waiting, done, failed) stay in the notification center (`core/notification-center.ts`). "Fetch all" no longer shows progress lines (a toast per step would pile up), only the summary.

## Loading states (#1041)

- `ui/loading/delayed.ts`: `delayed(source, ms)` (a signal that turns true after `source` was true for `ms`, false at once), `delayedSkeleton` (`SKELETON_DELAY_MS` 200) and `delayedBusy` (`BUSY_DELAY_MS` 1000). Views never time a placeholder by hand. `app-loading-rows` (`ui/loading/`) renders `hx-skeleton` rows after 200 ms and announces the state (`role="status"`); it replaces the "Loading…" text of Changes, the GitHub inbox, pull requests, issues, milestones and the detail panes, the task picker, Runs and the Explorer.
- A control that starts an action is disabled at once; its changed label ("Creating…", "Refreshing…") shows after 1 s (`delayedBusy`: space dialog, GitHub and Runs refresh).
- `TaskStarter.steps` (`core/task-steps.ts`, shown by `app-task-progress` in the status bar component) lists create worktree, run setup and start agent with the current one marked while a task creates a space with a worktree. Setup and the agent start run in one `create_space` call, so they are marked together.
- `prefers-reduced-motion: reduce` (`styles.css`): the working dot is a static ring instead of the pulse and `transition-property` leaves out `transform` (`ui/reduced-motion.spec.ts`).
- New pane (#1049): "New pane" (sidebar menu, palette `newTerminal`, `CmdOrCtrl+T`) opens the `new` dialog of `app-pane-dialog`: a radio choice of Terminal (default) and one entry per installed harness of `get_harnesses` (`available`), no directory (`terminal_create` with `cwd: null`: the server uses the space directory). `PaneActions.confirmNew(agent?)` creates the pane and then calls `agent_start`; a failed start keeps the shell pane and sets `error`.

Silent tab (#1149): the editor tab shows no text for a silent agent.
