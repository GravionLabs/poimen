# Frontend shell

Angular app structure, tab layout, terminal search and sidebar order. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- `src/app/tab-layout/` (#514): the editor tab of a split tab (poimen backend, `Tab.root` a split) renders one `terminal-view` per leaf through nested `app-split-pane`s (direction and ratio from the tree; decorator `@Input`s for the specs). A divider drag emits `ratioChange` with the `split_id`; `PaneActions.resizeSplit` sends `tab_resize_split` (`Backend::resize_split`, `tab.resize_split`; only the latest ratio per split while a request is in flight). Focus: click, or Alt+arrows (`cycleFocus`, tree order), kept in `App.leafFocus` and sent as `tab_focus` (`Backend::focus_tab`, `tab.focus`); only the focused leaf gets the wanted mode, the others observe. Context menu of a leaf: split right/down, close pane (through `PaneActions`). Each leaf keeps its own stream and size.
- File path links (#1003): `terminal-view/file-links.ts` (`findPaths`: `path`, `path:line`, `path:line:column`, quoted paths with spaces, `~/` and Windows paths, no URLs; `fileLinkProvider`, an xterm link provider for one buffer line, so a path wrapped over two lines is not found) asks the `resolve_file_links` command (`editor.rs`: relative to the pane's `foreground_cwd || cwd`, only existing files, plus the git root and the path in it) and links only what exists. Cmd+click (macOS) or Ctrl+click opens the external editor (`ExternalEditor`) at the position; a file that is changed against the base (`changes_list`) opens an `app-context-menu` instead with "Open in editor" and "Show in Changes" (`EditorTabs.openChanges(root, file)` sets `changesFocus`, which the `Changes` service of that tab selects). No links on a pane of a remote machine (`offersFileLinks`). `FileLinkActions` holds the actions.
- Recent tabs (#1006): `recent-tabs/` (`app-recent-tabs`, mounted in `app.html`) keeps a most-recently-used order of `EditorTabs.activeId` (not changed while switching) and listens on `window` for `recentTab`/`recentTabBack` (default `Ctrl+Tab`/`Ctrl+Shift+Tab`, literal Ctrl also on macOS). The first press opens a list of the tabs of all groups and selects the next; further presses step (wrapping); releasing the modifier of the chord activates it, Escape or a window blur cancels. These two actions are in `TERMINAL_KEYS` (`core/shortcuts.ts`), so a focused terminal yields them like a Cmd shortcut and xterm does not forward the Tab. `nextTab`/`previousTab` stay positional. Pure helpers in `recent-order.ts`.
- Terminal search (#714): `src/app/terminal-view/search.ts` (decoration colors from the `--term-*` tokens, match label, `TerminalSearch` hub that opens the bar of the terminal view that last had the focus and forgets a destroyed one, so the Settings view keeps its own Cmd/Ctrl+F); `terminal-view` loads `@xterm/addon-search` (pinned) and shows the bar per view; shortcut `find` (`CmdOrCtrl+Shift+F`; macOS through the Edit menu item, elsewhere the view's key handler) and palette "Terminal: Find". xterm searches what it holds: the attach snapshot plus later output.
- Tab order in the sidebar: `UiState.tabOrder` (`tab_id`s per `space_id`, `core/ui-state.ts`) is the user's order of the tabs of a space; `orderTabs` (ids of the order first, new tabs by number) is applied in `buildTree`/`buildSpaces` of `core/snapshot.ts`, the only places that list tabs of a space, so pane rows follow it; `SpaceActions.reorderTabs` writes it from a drag in `sidebar`; `spaces-store.ts` prunes closed tabs and spaces on every snapshot read; drag is disabled while a filter is active.
- `src/`: Angular 22 (standalone components, signals) on helix-ui, built with `@angular/build` (`angular.json`), tested with Vitest. `src/app/core/` is the Tauri bridge and state: `tauri.ts` (the only `invoke`/`listen` caller), `snapshot.ts` (the neutral model of spaces, tabs and terminals, pure helpers), `backend.ts` (events, stream records, version labels, agent kinds), `spaces-store.ts` (`SpacesStore`: snapshot signals, debounced re-read), `terminal-stream.ts` (opens a stream with a `Channel`; streams deliver PTY bytes as `bytes` records, no early-frame buffering). `src/app/terminal-view/` wraps xterm.js for the active editor tab (`core/editor-tabs.ts` holds tabs, preview/pinned and mode; `src/app/ui/helix-candidates/tab-bar/` is the generic tab bar, a helix-ui candidate); `src/app/sidebar/` shows the spaces tree (`hx-tree`; `src-tauri/src/git.rs` answers the read-only `repo_info` command with branch and worktree per directory); the view rail is `hx-activity-bar` of helix-desktop fed by `core/activity-items.ts` (`ACTIVITY_ENTRIES`, `activityItems`, `tabOf`; SVG templates in `app.html`); `src/app/notifications/` is the notification center view over `core/notification-center.ts` (in-memory list fed by `Attention` status changes); `core/ui-state.ts` holds persisted UI state (sidebar width/collapsed), never pane state. Space order: `UiState.spaceOrder` (`space_id`s) is applied by `orderSpaces` in `core/snapshot.ts` (stored ids first, new spaces by number, closed ones pruned on snapshot reads); `SpacesStore.tree`/`spaces`/`orderedSpaces`, `neighbourSpace` and the sidebar all read it, `SpaceActions.reorder`/`shift` change it (drag and drop in the sidebar, off while a filter is active; palette "Move Space Up/Down"). Pins (#710): `UiState.pinnedSpaces` (`space_id`s, pruned with `pruneSpaceOrder`) is the fourth argument of `orderSpaces`, which puts pinned spaces first in every sort mode (a pinned worktree head brings its members, a pinned member is first among its siblings); `SpaceActions.setPinned`, space menu "Pin space"/"Unpin space" (local spaces only) and palette "Pin Space"/"Unpin Space". `core/attention.ts` keeps in-memory UI marks derived from agent statuses: a pane that turns blocked while not viewed rings on its tab and sidebar row, one that turns done while not viewed counts as unread (workspace rows sum their panes); viewing the tab (active tab of a group) clears both.

- App shell (#930): `app.html` is one `hx-app-shell` of helix-desktop (slots `toolbar`, `activity`, `sidebar`, `status`; the editor area and the bottom panel are the default slot,). The shell owns the splitter (limits `SIDEBAR_MIN_WIDTH`/`SIDEBAR_MAX_WIDTH`, step 10, Shift 40) and reports through `sidebarChange` to `App.onSidebarChange`, which persists via `UiState`; the activity bar still goes through `UiState.selectView`, so the shell's own `activeId` is unused. The sidebar view sits inside `@if (!ui.sidebarCollapsed())` because the shell only hides its slot. `app-toolbar` is a wrapper (`display: contents`) around `hx-app-toolbar` (26 px, `windowButtonsInset` off) with the Output and theme buttons in `slot="end"`.

## Status bar (#931)

`app-status-bar` renders `hx-status-bar` (helix-desktop) in the `status` slot of the shell; every entry is an `hx-status-item` (`kind="button"` for actions, `tone` for warnings and errors, no CSS classes of poimen for them). The bar is not a live region: only items whose value changes by itself set `[announce]="true"` (connection, run summary, limits, waiting, notices, update progress). An `@if` block projects only with a single root element, so every item has its own `@if`, and the update switch sits in `<ng-container ngProjectAs="[slot=end]">`. A boolean input needs a binding (`[announce]="true"`): the bare attribute is the empty string. The update details stay a `position: fixed` section until the updater PBI moves them into the item popover.

## Sidebar cards layout (#934)

`sidebar.layout: "cards"` renders `app-space-card` (`src/app/sidebar/space-card.*`) per node of `spaceNodes`, the same row model as the tree; the card takes `headerOnly` so another layout can reuse the header. The `⋯` button and a right click ask `Sidebar` for the same context menu as the tree row. Collapsed cards are `UiState.collapsedCards`, pruned in `SpacesStore.refresh`. The component uses decorator inputs because the specs run without the compiler transform, and specs that override the `Sidebar` template call `inlineSpaceCard()` (`space-card.mock.ts`). The TUI ignores `cards`. Card states (#935): the card reads the signals of the tree row. It rings as a whole (`.card.attention`, text on the tint uses the `-on-active` tokens, checked in `sidebar-contrast.spec.ts`) while a pane of the space is in `Attention.attention`; the header carries the pin mark, unread count, the longest silent mark, the rebuild marks (`SpaceRebuild.marks`, only for a space without terminals) and "Closing…"; the status dot is the aggregate, so a collapsed card shows the most urgent one. Double click on a space or terminal name renames inline (`SpaceActions.rename`, `PaneActions.rename`; Enter saves, Escape cancels, a failure keeps the input). Organization (#936): the card list is `nodes()`, so grouping (`sidebar.groupWorktrees`), pins, sort and filter come from `orderSpaces`/`filterSpaces` and the card never sorts; a linked worktree's card has `.member` (indented). A filter shows a card expanded without touching `collapsedCards`. Drag and drop reuses the `Sidebar` handlers (`dragStart`/`drop`, `tabDragStart`/`tabDrop`): the card forwards the DOM events and gets `spaceDraggable`/`tabDraggable`/`dragMark`/`tabMarks`; off outside `manual` sort and while a filter is active. Pin/Unpin is in the shared `⋯` menu. Keyboard and ARIA (#937): `.cards` is a `tree`; the card header (`.title`) and each row are `treeitem`s (`aria-level` 1 and 2+depth, `aria-expanded` on headers, `aria-selected`) carrying `data-nav` (space id or terminal id); `card-nav.ts` is the pure part (`cardItems` in display order, `cardNav` key to target, `tabStop`), `Sidebar.onCardKey` applies it (Up/Down/Home/End, Right/Left expand/collapse or step in/out, Enter opens a row or toggles a header; keys with a modifier, buttons and inputs are left alone so the window shortcuts work). Remote machines (#938): in `cards` the machines section renders each space of `SpacesStore.remoteSpaces(machine)` (`remoteTree` with pane rows) as an `app-space-card` built by `Sidebar.remoteNodes` (`spaceNodes`); `tree` and `split` keep the plain rows. A card gets `blocked` = `Machines.blockedReason` of its machine: greyed (`.offline`), `+`, close and `⋯` disabled with the reason as tooltip, rename and menu inert; a remote card has no configure button, no overview on header click, no pin and no drag; ids are qualified (`<machine>::<id>`), so the fold state in `collapsedCards` is under the qualified id (pruned with the local and remote space ids; `keptCardIds` keeps the marks of a machine that lists no space yet). Origin (#1074): `SpaceCard.origin` puts an `.origin-mark` svg (`role=img`, `aria-label` `This computer` / `Machine <name>`, tooltip adds the `blocked` reason, muted on an `.offline` card, not a button) in the header and the label into the card's accessible name; a machine card also gets a 3px stripe (`.card.origin::before`, inside the border so the `.member` indent stays) in `--origin-<n>` (`styles.css`, six tokens, `n = originColor(name)` a hash of the machine name; 3:1 checked in `sidebar-contrast.spec.ts`). No machine configured: no symbol on any card. Roving tabindex: only `Sidebar.cardStop` has `tabindex=0`; the action buttons of a header and the buttons in a row are tabbable only while their header/row is the stop, the fold button never (the header's `aria-expanded` covers it).

## Component templates (#1051)

Every component under `src/` (outside `*.spec.ts`) has its template in a sibling `.html` file (`templateUrl`), so the ESLint template and accessibility rules see all of them; inline `styles` are fine. oxlint fails on an inline `template:` in a `@Component` outside spec files (`poimen/no-inline-template` of `scripts/lint/oxlint-plugin-poimen.mjs`, proved by `src/testing/lint-probe.spec.ts`); test hosts in spec files keep inline templates. Specs run with JIT and without the Angular resource transform, so `vitest.config.mts` inlines a `templateUrl` as `template` when Vitest loads a component (`styleUrl` is not inlined: specs still override it).

## Lint and format (#1052)

`pnpm format` and `pnpm format:check` run oxfmt (`.oxfmtrc.json`; `src/app/**/*.html` as Angular templates). `pnpm lint` runs oxlint on the TypeScript (`.oxlintrc.json`, migrated from the former ESLint rules, the Angular class rules through `@angular-eslint/eslint-plugin` as an oxlint JS plugin, poimen's own rules from `scripts/lint/`; type-aware through `oxlint-tsgolint`: floating and misused promises and `await` of non-promises are errors, `restrict-template-expressions` and `no-base-to-string` warnings) and then ESLint on the `.html` templates only (`eslint.config.mjs`), because oxlint cannot parse Angular templates. Suppress a TypeScript finding with `// oxlint-disable-next-line <rule>`, a template finding with `<!-- eslint-disable-next-line <rule> -->`. JS plugins are alpha: oxlint, oxfmt and the plugin are pinned to exact versions, and `src/testing/lint-probe.spec.ts` lints the deliberate violations of `src/testing/lint-probe/` (left out of `pnpm lint` and the build) and expects every rule id. Not covered by oxlint: `no-octal` (a syntax error in TypeScript modules anyway) and `no-useless-assignment` (nursery in oxlint, reports a false positive on a class field initializer). The reformat commit of the switch is listed in `.git-blame-ignore-revs` (`git config blame.ignoreRevsFile .git-blame-ignore-revs`).

## Space card header (#1075)

- Line 1 of a card: origin symbol, status dot (`role="img"`, tooltip and `aria-label` carry the state), name, badge, and the actions `+` and `…` (shown on hover, focus inside the card and on the card of the open terminal). The state word is shown only for `blocked` and `error`. Gear, close, pin, copy path, details and the sort entries are entries of the `…` menu (`sidebar/card-menu.ts`).
- Line 2 (details): chevron, branch (cut in the middle: `middleParts`), directory (only when its last segment differs from the name, cut before the branch), chips right-aligned. The chevron and the menu entry hide it per card (`UiState.hiddenDetails`, pruned with closed spaces). Hidden, a stub with only the chevron stays so the line can be shown again.
- The cards layout has its own workspace lines (`DEFAULT_CARD_ROWS`); the tree default `DEFAULT_SIDEBAR_ROWS` is unchanged, and a user's own `sidebar.rows.workspace` wins (`cardRows`).
