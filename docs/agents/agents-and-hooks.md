# Agents, hooks and harnesses

Agent status hooks, integrations, harnesses and agent actions. Read before you touch these areas. Notes on a change go here, not in `AGENTS.md`.

- Settings › Backend › Server (#845): a table Agent / CLI / Hooks / MCP / Action (`settings-view.html`, case `server`); states are `hx-tag`s with tone and a glyph (`stateTag`), the action is named by `installAction` (Repair, Install hooks, Add MCP server, Install hooks and MCP; none for `unknown` or an agent whose CLI `get_harnesses` does not report), progress and errors per agent in `HooksOffer.installing`/`errors`; above it the server version, state, socket (`server_socket_path`) and "Restart server…" (`ServerRestart.askRestart`).
- `src-tauri/src/hooks.rs`: agent hooks of the poimen backend: `hooks_status` / `hooks_install` run the bundled `poimen-server integration status|install claude|copilot` through an `Exec` trait (faked in tests; tests never run the binary or touch real settings). Frontend `core/hooks-offer.ts` (offer once the backend runs, "Not now" in `core/ui-state.ts`) and `src/app/hooks-dialog/`.
- `src-tauri/crates/poimen-server/src/claude.rs`: Claude Code integration of poimen-server: `map_hook` (hook payload to status; subagent events ignored), `run_hook` (`poimen-server hook claude`, run by `hook.rs`: silent outside a poimen terminal, first JSON value of stdin without waiting for EOF, 1.5 s cap, always exit 0; a report that does not get through is a line in `hooks.log` next to `server.json` and on stderr; tests in `tests/hooks.rs`) and `install`/`uninstall`/`status` of `~/.claude/settings.json` (path is a parameter; entries marked `# poimen-agent-hook`, `# poimen-rc-agent-hook` on rc, so both channels coexist and each manages only its own; the hook is silent in a terminal of the other channel (`HookEnv.foreign`); tests use temp dirs only, never the real home). The server stores hook-reported status per terminal (`terminal.report_agent`, stale `seq` dropped, `agent.status_changed`); `poimen_backend.rs` maps it onto `agent_status` of panes, tabs and workspaces and the backend-neutral `terminal.agent_status_changed` event (`backend::AGENT_STATUS_CHANGED`, data keyed by `terminal_id`). See `docs/protocol.md`.
- Permission requests and failed turns (#984): `claude::LATER_EVENTS` is the table of event and first CLI version (`events_for(cli)`, `parse_version`), the version comes from `claude --version` through the `CliVersion` trait (`SystemCli`; `check::Env::cli_version` for the machine check; tests fake it) and `Kind.cli`/`Kind::cli_version` pass it to `install`/`status` (`HookStatus {installed, missing}`). `error` is waiting everywhere through `needsAttention`/`Attention`/`tui/attention.rs` (already so for OSC 7501). `TerminalReportAgent.message_fallback` marks the tool text of a `PermissionRequest`, which `terminal_report_agent` does not let replace a notification text. The tests of `claude.rs` are in `claude_tests.rs` (line-count ratchet). Copilot has no version gate (unverified for older versions).
- Failed turn reset (#1110): `agent_state::reset_error_on_input` (called by `terminal.input`) sets an `error` status to `idle` when the input holds Enter (a prompt, `clear`); the server owns it, clients show the snapshot. A program with its own OSC 7501 status is left alone; a new turn is reported `working` by the hooks anyway.
- `src-tauri/crates/poimen-server/src/integration.rs` (#731): `KINDS`, the one table of agent kinds with hooks (`hook <kind>` and `integration install|uninstall|status <kind>` dispatch through it); `gemini.rs` is the third kind (Gemini CLI, `~/.gemini/settings.json`, status only, no transcripts) and reuses `claude::install_events`/`status_events`. Frontend side: `HOOK_AGENTS` in `core/backend.ts` (kinds, names, transcripts; `agentName`, `hasTranscripts`, `agentSupport`, `supportsFlow` derive from it); `hooks.rs::AGENTS` lists the kinds for the app.
- `src-tauri/crates/poimen-server/src/copilot.rs`: Copilot CLI integration, same pattern as `claude.rs`: `map_hook` accepts camelCase and PascalCase/snake_case payloads (event from the payload or the command line, `poimen-server hook copilot <event>`), the installer owns `~/.copilot/hooks/poimen-agent-state.json` (`poimen-rc-agent-state.json` on rc).
- `src-tauri/crates/poimen-client/src/agent.rs`: `Client::start_agent` (types the quoted command line, resolves on the `SessionStart` report, 30 s) and `prompt_agent` (types text and Enter, refused while the agent is working or blocked); `PoimenBackend::agent_start`/`agent_prompt`/`agent_rename` use them (agent name = terminal name). Tested end to end with a fake agent script that reports through `poimen-server hook claude` (`crates/poimen-server/tests/agent.rs`).
- `src-tauri/src/harness.rs`: agent harness registry (`harnesses` in `config.json`, defaults `claude` and `copilot`): argv templates (`{model}`, `{prompt}`; `printArgs` for a headless one-shot call, default `-p {prompt}` for claude and copilot, empty hides the commit message button of the Changes view) expand per element, never through a shell; `get_harnesses` adds availability (`resolve_program` on `child_path()`). `agent_start` takes `args: Vec<String>`. Frontend: the "Agents" section of `src/app/settings-view/`.
- `src-tauri/src/agent_actions.rs`: `github.agentActions[]` (ADR 0005): prompt templates per action (`id`, `label`, `on` issue/pr/milestone, `when`, `prompt`, `run`, `harness`, `model`, `batch`) so poimen starts agents without knowing a skill. Neutral defaults (Plan, Refine, Review, Fix checks, Resolve conflicts (#998: `when.conflicting`, `Pull.mergeable == CONFLICTING`; `run: worktree`, prompt merges `{base}`; off for a fork like Fix checks, `pushesToHead`), Address review comments), merged by `id` defaults, user (`Settings.agent_actions`, `settings::resolve_github`), project (`project.rs`, only when trusted, listed by `trust.rs`); `disabled: true` removes. Invalid entries warn and are skipped; `expand` fills `{nr}`, `{nrs}`, `{title}`, `{url}`, `{repo}`, `{branch}`, `{base}` in one pass into one argv element through `harness::build_argv`. `{log}` (#238, `on: "pr"` only; `Item.log`) is the file of the failed check logs: the default `fix-checks` is `run: worktree`, and after the PR worktree exists `AgentActions` calls `github_pr_ci_log` (`github::failed_logs`: failed runs of the head SHA, `gh run view <id> --log-failed`, last 200 KB per run; `changes::write_ci_log` writes `<worktree>/.agents/state/ci-failed-<nr>.log`, `.agents/state/` excluded once) and plans again with the path; a PR from a fork is offered disabled with the reason. Command `get_agent_actions(root)`; the Agents page of the settings lists them read-only with their source. Config file only. Running them (#346): command `agent_action_plan(root, id, repo, items, harness, model)` (`agent_actions::plan`: `expand` with the dialog's harness/model, split into `kind` and `args` for `agent_start`); frontend `github/agent-actions.ts` (`AgentActions`: pure `matches` of `when` against issue/PR rows, `offered`; `run: worktree` (#347) = `task_worktree`/`pr_worktree` per target, then `create_space` on it (label `#<nr> <title>` / `PR #<nr> <title>`, agent in the root pane, an existing space gets a new tab), errors name the step; `run: ask` always opens the dialog with a root/worktree choice, `run` = `create_space` on the root, then per launch in parallel `terminal_create` + `agent_start` named `<label> #<nr>`, summary notice of started and failed; `batch: once` is one agent), buttons in `issue-detail/` and `pull-detail/`, the `⋯`/context popup `agent-action-menu/`, the Shift+click dialog `agent-action-dialog/` (harnesses from `get_harnesses`) and palette entries "GitHub: <label> #<nr>" for the selection or open detail. Review (#237): the default `review` is `run: ask`; for it the dialog adds mode `worktree`/`diff only` (diff only = tab `review #<nr>` at the root) and "Post review on GitHub"; the fixed suffixes (`reviewSuffix`: `gh pr diff {nr}`, `gh pr review {nr} --comment`) go to `agent_action_plan` as `suffix` and are appended to the prompt by `agent_actions::plan`.
- Agent run badges (#348): `src/app/github/agent-runs.ts` (`AgentRuns`, root service, in memory): `AgentActions` records `paneId` to repo, numbers and action when an agent starts; `App` feeds it the pane statuses next to `Attention`; `working` shows `<label> running`, `blocked` `<label> waiting` (click focuses the pane) on list rows and detail panes; `done` or a closed pane removes the entry and reloads pulls and issues once (`advance` is the pure transition).
- Who started whom (#982): `start_agent` of `poimen mcp` sets `TerminalCreate.started_by` (the caller's `POIMEN_TERMINAL_ID`); `Terminal.started_by` is stored in `server.json` and goes into the snapshot (`started_by`). App sidebar: `nestTabs` (`sidebar/space-nodes.ts`) nests such a row below its starter's row in one space (not a start cycle, not a missing starter); a starter in another space is named by the row token `started_by` (`↳ name (space)`, `PaneRow.startedBy` from `starterOf` in `core/snapshot.ts`, in the default agent and terminal lines). Runs view: `Deliver.starterOf(card)` shows `started by …` for the terminal in `host["poimen.terminal"]`. TUI: the same token shows `↳ name` (rows are not nested there).

- Silent (#1119): the sweeper (`SharedState::mark_silent`) marks a `working` terminal silent when `reported_at` is older than `agents.silentAfter`. The only sign of life is a repeated OSC 7501 report (`output_signals` moves `reported_at` without an event) or a hook; terminal output does not count. A long-running program without a hook-capable agent (a loop waiting for CI) repeats its `working` report within `silentAfter`. Tests: `tests/agent_silent.rs`.

- Resume session (#986): "Resume session..." in the menu of a local space (new tab), of a shell pane (the pane at its prompt), the tab menu and the palette (`resumeSession`, the active pane). `poimen_core::agent_sessions::list(home, cwd, agents)` reads the earlier sessions of a directory: Claude Code from `~/.claude/projects/<dir name>/<session>.jsonl` (start from the first timestamp, last activity from the tail, first prompt = first typed user message or slash command; a file whose recorded `cwd` differs is skipped, directory names collide), Copilot CLI from `~/.copilot/session-state/<session>/` (`workspace.yaml` `cwd`, `created_at`, `updated_at`; a directory without `events.jsonl` is not listed). Command `list_agent_sessions(dir)` scans only harnesses with `resumeArgs`, newest 50. Frontend `core/session-resume.ts` (`SessionResume`, `resumeCommand` expands `{session}` per element, a hook kind runs under its id like the New pane dialog) and `resume-dialog/`; a harness without `resumeArgs` or not installed is not offered. Remote machines are not supported: the entry is disabled with `RESUME_REMOTE_REASON` (`resumeUnavailable`).
