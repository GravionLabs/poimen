# AGENTS.md

Guidance for humans and coding agents working in this repository. Generated text (docs, issues, commits, code) is written in US English.

## Architecture

- Default backend: `poimen-server` (`backend` setting, default `poimen`); herdr stays the alternative (`backend: "herdr"`) until it is removed. The next bullets on `herdr.rs`, `backend.rs` and `watch.rs` describe that alternative.
- `src-tauri/src/herdr.rs`: socket API client (NDJSON over the Unix socket); `SUPPORTED_PROTOCOL` (the protocol poimen is written for) lives here. Requests use short-lived connections; subscriptions keep theirs.
- `src-tauri/src/backend.rs`: the `Backend` trait (spaces, terminals, create/close/rename, split, input, neutral stream records `reset/output/resized/controller/closed` with `emulated` per stream and `CloseCode::ControllerHeld`, events, `ensure_running`); every command goes through it (`Arc<dyn Backend>`), `backend_fake.rs` is the test fake. `HerdrBackend` implements it over `herdr.rs`, `stream.rs` (`FrameMapper` maps herdr frames) and `watch.rs`; start: ping the socket, else start a detached `herdr server` (own process group, stdio null, never waited on, never stopped by poimen) and wait for the socket and the supported protocol; behind the `herdr.autoStart` setting and the `ensure_backend` command. `gui_path.rs` is the login-shell `PATH` of a GUI app (used to find and start `herdr`). Tests use a fake `Runner`; never start or stop a server in a test.
- `src-tauri/crates/`: the Cargo workspace next to the app crate (`default-members` cover all, so plain `cargo test` in `src-tauri` runs everything). `poimen-protocol` (client-neutral wire types, socket path, parsing tests; the protocol and every request/event are documented in `docs/protocol.md`, version `PROTOCOL_VERSION`), `poimen-client` (blocking client: requests over short-lived connections, `subscribe` event stream; reused by the app, a later CLI and `poimen attach`; `transport.rs` is the local socket over `interprocess`: a Unix socket, on Windows a named pipe with a marker file and a DACL, no I/O timeouts or `shutdown` there) and `poimen-server` (daemon that owns the PTYs through `portable-pty` (ConPTY on Windows), one per user on the socket under the runtime dir (Windows: `%LOCALAPPDATA%\poimen-server`, started from a per-version copy there; a Linux AppImage starts a per-version copy under `$XDG_DATA_HOME/poimen-server/bin` and its hooks call the stable link there, `poimen_server::stage_root`/`prepare`), flat model of spaces and terminals, spaces persist in `server.json`, terminals do not; never stopped by poimen). Per terminal it keeps an `alacritty_terminal` grid (`emulator.rs`, scrollback `POIMEN_SCROLLBACK`) fed from the PTY after a short coalescing (`pty.rs`); `terminal.attach` (`stream.rs`, `Client::attach`) returns a snapshot (ANSI of screen, scrollback and modes) and then raw bytes with sequence numbers, under one lock per terminal so none is lost or repeated; a client has a bounded queue and is detached on overflow, never blocking the PTY; one controller (explicit take-over), many observers. Terminal queries (OSC 10/11/12/4, DSR, DA1/DA2) are answered from that grid by `TermStream::output` (`Emulator::take_replies`) only while no controller is attached (xterm.js answers otherwise); colors come from `server.set_colors`, sent by the app (`core/terminal-colors.ts`, command `set_terminal_colors`, `terminal_colors.rs` keeps the last scheme and pushes it after `ensure_backend`). `src-tauri/src/poimen_server.rs` starts it detached when absent (`ensure_running`, called by the backend through `ensure_backend`; fake `Runner` in tests); the `backend` setting and the `Backend` implementation are `poimen_backend.rs` below.
- `src-tauri/src/hooks.rs`: agent hooks of the poimen backend: `hooks_status` / `hooks_install` run the bundled `poimen-server integration status|install claude|copilot` through an `Exec` trait (faked in tests; tests never run the binary or touch real settings). Frontend `core/hooks-offer.ts` (offer once the backend runs, "Not now" in `core/ui-state.ts`) and `src/app/hooks-dialog/`.
- `src-tauri/src/poimen_backend.rs`: `PoimenBackend`, the default `Backend` (setting `backend`, default `poimen`, read at start in `lib.rs::make_backend`, command `backend_kind`): server spaces become workspaces, each terminal a tab with one pane (`map_snapshot`; the herdr tree wire shape is kept; the frontend reads it through `toSnapshot` in `core/herdr.ts` into the backend-neutral `Snapshot` of `Terminal`s identified by `terminal_id`), splits are new terminals of the same space, streams are `terminal.attach` connections (`poimen_client::AttachmentWriter` sends input and resize on the attached connection; `Backend::emulated` is true). Records reach the webview through the `tauri::ipc::Channel` of `open_terminal` (`lib.rs::channel_messages`: PTY bytes raw, the rest JSON), for both backends; there is no global `terminal` event. Agent start, prompt and rename work (see `poimen-client/src/agent.rs`). Never started or stopped by poimen beyond `poimen_server::ensure_running`.
- `src-tauri/crates/poimen-server/src/claude.rs`: Claude Code integration of poimen-server: `map_hook` (hook payload to status; subagent events ignored), `run_hook` (`poimen-server hook claude`: silent outside a poimen terminal, 1.5 s cap, always exit 0) and `install`/`uninstall`/`status` of `~/.claude/settings.json` (path is a parameter; entries marked `# poimen-agent-hook`; tests use temp dirs only, never the real home). The server stores hook-reported status per terminal (`terminal.report_agent`, stale `seq` dropped, `agent.status_changed`); `poimen_backend.rs` maps it onto `agent_status` of panes, tabs and workspaces and the `pane.agent_status_changed` event. See `docs/protocol.md`.
- `src-tauri/crates/poimen-server/src/copilot.rs`: Copilot CLI integration, same pattern as `claude.rs`: `map_hook` accepts camelCase and PascalCase/snake_case payloads (event from the payload or the command line, `poimen-server hook copilot <event>`), the installer owns `~/.copilot/hooks/poimen-agent-state.json`.
- `src-tauri/src/watch.rs`: one long-lived `events.subscribe`. `pane.agent_status_changed` needs a `pane_id`, and herdr rejects the whole subscription when a referenced pane is gone, so the watcher resubscribes on pane-set changes.
- `src-tauri/crates/poimen-client/src/agent.rs`: `Client::start_agent` (types the quoted command line, resolves on the `SessionStart` report, 30 s) and `prompt_agent` (types text and Enter, refused while the agent is working or blocked); `PoimenBackend::agent_start`/`agent_prompt`/`agent_rename` use them (agent name = terminal name). Tested end to end with a fake agent script that reports through `poimen-server hook claude` (`crates/poimen-server/tests/agent.rs`).
- `src-tauri/src/project.rs`: the project file `.poimen/config.json` (`layout`, `setup`, `teardown`, `commands[]`, `presets[]`; schema and doc in `docs/project-config.*`); tolerant `load(repo_root)` returning config plus warnings, `project_config` command. Layout precedence lives in `layout::resolve` (project file, deprecated `.agents/herdr-layout.json`, `spaces.layout`, default). `tasks` (modes and `worktreeDir`, merged over the user's in `tasks::for_project`, `get_task_modes(dir)`) is parsed with `settings::parse_tasks`; `start_setup` runs `setup` in a `setup` tab of a new space (only after `trust::gate` allowed it, from `create_space`); `run_teardown`/`teardown_plan` (trust gate, `$SHELL -lc`, 5 min timeout, 1 MB output, `ProcessRunner` faked in tests) run `teardown` before `worktree::cleanup` removes a worktree and from the `project_teardown` command (palette "Project: Run teardown", result dialog `src/app/result-dialog/`); `project_entries`/`project_run` serve the palette entries (`Project: <name>`, `Preset: <name>`; `run_entry` goes through `trust::gate`; an `agent` command is handed back and sent by the frontend `core/project-entries.ts`).
- `src-tauri/src/worktree.rs`: `task_worktree(repo_dir, issue, mode)` creates or reuses the git worktree and branch of an issue (mode's `branch` template, `tasks.worktreeDir` relative to the main worktree, found through `--git-common-dir`). Reuses a worktree that has the branch, adds a worktree for an existing branch, else `git fetch origin` and `-b` from `origin/release/next` or the default branch of `origin`; a path that exists otherwise is an error. Never modifies an existing worktree; git via argv only; no herdr call. The same file holds "Clean up merged tasks" (`task_cleanup(dir, focusedSpace)`, `worktree::cleanup`): candidates are the linked worktrees whose branch is the head of a merged PR (`gh pr list --state merged --json headRefName,number` through `github::Runner`); the first task mode with a `cleanup` command runs it per worktree (expanded and shell-quoted, `{pr}` added to the placeholders, in the repository root) instead of the built-in removal (close the space, `git worktree remove`, then `git branch -d` only when every commit is on a remote branch). Invariants, each tested on temporary repositories: never a dirty (uncommitted or untracked) worktree, the main worktree or the focused space's; never `main`, `master`, `release/*` or the `origin` default branch; never `--force` or `-D`; a space with terminals outside the worktree is not closed. Frontend: `core/task-cleanup.ts` (`TaskCleanup`: notice `<n> removed, <m> left`), `core/task-log.ts` and the Log tab of the bottom panel list each left worktree with reason and the command to run by hand. Entry points: palette `cleanupTasks` and the space menu (repositories only). `pr_worktree(repo_dir, nr, head_ref)` (command `pr_worktree`) does the same for a pull request: fetches `refs/pull/<nr>/head` from `origin` into local `pr/<nr>` (the head branch itself when it exists on `origin` at that commit), path `../{repo}-pr{nr}`, a branch already checked out in a worktree returns that worktree, a local `pr/<nr>` is only fast-forwarded, a foreign existing path is an error; `worktree_branches(dir)` lists worktrees for the "Open space" / "Check out" buttons of the PR view (`github/pulls.ts`).
- `src-tauri/src/changes.rs`: read-only backend of the Changes view: `changes_list(dir, scope)` (`base`: working tree against `git merge-base HEAD <base>`; `uncommitted`: against `HEAD`; files with status, rename source, counts from `--numstat -z`, binary flag, untracked from `ls-files --others`) and `changes_file(dir, scope, path)` (old and new text for the merge view; `binary` / `too_large` over 1 MB without content). `git::base_ref(dir)` (`origin/release/next`, else `origin/HEAD`, never fetches) is shared with `worktree.rs`; without a base the comparison is against `HEAD`. `dir` is validated like `create_space` (`spaces::resolve_dir`, inside a repository).
- `src-tauri/src/trust.rs`: trust in a project file: `Sources` reads `.poimen/config.json` and `.agents/herdr-layout.json` once (hash, listed commands and layout all come from that read), `gate` decides `Run`/`Strip`/`Ask` against `trustedProjects` of the user config (root to SHA-256). `create_space` asks before creating anything; any future runner of setup/teardown/commands/presets must go through `gate` and use the same `Sources`. Frontend: `src/app/trust-dialog/`, `SpaceActions.trust`, settings section "Trusted projects".
- `src-tauri/src/settings.rs`: user settings (`~/.config/poimen/config.json`, optional Ghostty config); `get_settings` command plus a polling watcher emitting `settings`. Preferences only, never UI state; frontend side is `core/settings.ts`.
- `src-tauri/src/harness.rs`: agent harness registry (`harnesses` in `config.json`, defaults `claude` and `copilot`): argv templates (`{model}`, `{prompt}`) expand per element, never through a shell; `get_harnesses` adds availability (`resolve_program` on `child_path()`). `agent_start` takes `args: Vec<String>`. Frontend: the "Agents" section of `src/app/settings-view/`.
- `src-tauri/src/schemes.rs`: user color schemes (WezTerm TOML in `~/.config/poimen/themes/`); `get_color_schemes` command plus a polling watcher emitting `color-schemes`; frontend side is `core/user-schemes.ts`.
- `src-tauri/src/github.rs`: shared GitHub client over the `gh` CLI ([ADR 0005](docs/adr/0005-github-views-and-agent-harnesses.md)): `repo_of(dir)` (GitHub `origin` only), `Client::rest` (`gh api --include`, ETag revalidation, body cached 30 s per exact path in the app cache dir) and `Client::graphql` (30 s in-memory cache per query and variables); errors serialize as `GhError` (`gh-missing`, `not-logged-in`, `offline`, `rate-limited`, `not-found`, `other`). `gh` is resolved through `gui_path.rs`; a `Runner` trait fakes the child process in tests (no network). ## Rules

- **The backend owns state** (`poimen-server`, or herdr on the alternative backend). poimen never stores pane state of its own; snapshots from the backend are authoritative and events only invalidate them.
- **Non-destructive.** Closing a view or the app releases controllers and kills only the CLI child processes, never herdr panes. Taking over a controller requires an explicit user action.
- **Tests stay read-only.** Live tests (`#[ignore]`) may list and observe, never control, send input or create panes in the user's session.
- **Protocol drift.** herdr's API protocol is versioned (22 at the time of the spike). Keep all wire shapes in `herdr.rs`, `stream.rs` and the `poimen-protocol` crate, each with a parsing test.

## Decisions

- Frontend stack: Angular 22 and helix-ui, and when a component goes to helix-ui ([ADR 0001](docs/adr/0001-frontend-stack.md)).
- Color schemes: bundled and imported schemes, a derived chrome and the `colorSchema` setting ([ADR 0002](docs/adr/0002-color-schemes.md)).
- Own terminal backend `poimen-server`, the default; herdr is the alternative until removed; agent status from Claude Code and Copilot hooks (proposed, [ADR 0003](docs/adr/0003-own-terminal-backend-without-herdr.md)).
- GitHub views and agent harnesses native in poimen; the herdr plugin integration (ADR 0004) is removed (accepted, [ADR 0005](docs/adr/0005-github-views-and-agent-harnesses.md)).

## CI and releases

- `.github/workflows/ci.yml`: the `changes` job outputs `frontend` (`src/`, Node/Angular config), `rust` (`src-tauri/`, `rust-toolchain.toml`) and `app` (either, because the app crate embeds the built frontend); a change of `ci.yml` sets all. Jobs of an untouched area are skipped: `frontend` (check, lint, format, test, build), `rust-server` (fmt of the workspace, clippy and test of `poimen-protocol`, `poimen-client`, `poimen-server`; no Tauri libraries, no frontend build), and on `app` the `rust` job (app crate `poimen`: clippy and test with the Tauri Linux libraries and the built frontend) and `windows` (tests of the server crates, clippy of the app crate), all through GravionLabs/ci `@v1`. Its always-running `ci` gate job (needs every job; green when the checks passed or were skipped) and `pr-checks / PR checks` (`pr-checks.yml`: readiness, Conventional Commit title) are the checks required on `main` and `release/**`.
- Reusable workflows and actions of GravionLabs/ci are referenced at `@v1`, never `@main` or a SHA.
- Manual acceptance: [`docs/manual-acceptance.md`](docs/manual-acceptance.md) is the checklist per OS and package (macOS `.dmg`; Windows `-setup.exe` and `.msi`; Linux `.deb`, `.rpm` and `.AppImage`) that CI cannot run. Every release is checked with it on the published build, the results go to the release's manual-check issue, and the release PR links it.
- Work is integrated on `release/next`: every PBI branch is cut from it and its PR targets it (squash); `main` only receives the release PR (merge commit). `release.yml` versions with GitVersion, writes `CHANGELOG.md` with git-cliff and tags `v<version>`. README "Releases" has the rules.
- Release flow: release review -> pre-release (`release.yml` dispatched on `release/next` with `prerelease: true`: `v<version>-rc.<n>`, GitHub pre-release, installers without MSI, no commit, no changelog, no issue closing) -> manual acceptance (`docs/manual-acceptance.md`) -> gaps as bugs and a new pre-release -> `github-release finish` -> release PR merge. GitVersion (`tag-prefix`) and git-cliff (`tag_pattern`) ignore `-rc` tags; `releases/latest` ignores pre-releases (`docs/updater.md`).
