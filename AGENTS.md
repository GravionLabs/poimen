# AGENTS.md

Guidance for humans and coding agents working in this repository. Generated text (docs, issues, commits, code) is written in US English.

## Architecture

- `src-tauri/src/herdr.rs`: socket API client (NDJSON over the Unix socket); `SUPPORTED_PROTOCOL` (the protocol poimen is written for) lives here. Requests use short-lived connections; subscriptions keep theirs.
- `src-tauri/src/backend.rs`: the `Backend` trait (spaces, terminals, create/close/rename, split, input, neutral stream records `reset/output/resized/controller/closed` with `emulated` per stream and `CloseCode::ControllerHeld`, events, `ensure_running`); every command goes through it (`Arc<dyn Backend>`), `backend_fake.rs` is the test fake. `HerdrBackend` implements it over `herdr.rs`, `stream.rs` (`FrameMapper` maps herdr frames) and `watch.rs`; start: ping the socket, else start a detached `herdr server` (own process group, stdio null, never waited on, never stopped by poimen) and wait for the socket and the supported protocol; behind the `herdr.autoStart` setting and the `ensure_backend` command. `gui_path.rs` is the login-shell `PATH` of a GUI app (used to find and start `herdr`). Tests use a fake `Runner`; never start or stop a server in a test.
- `src-tauri/crates/`: the Cargo workspace next to the app crate (`default-members` cover all, so plain `cargo test` in `src-tauri` runs everything). `poimen-protocol` (client-neutral wire types, socket path, parsing tests; the protocol and every request/event are documented in `docs/protocol.md`, version `PROTOCOL_VERSION`), `poimen-client` (blocking client: requests over short-lived connections, `subscribe` event stream; reused by the app, a later CLI and `poimen attach`) and `poimen-server` (daemon that owns the PTYs through `portable-pty`, one per user on the socket under the runtime dir, flat model of spaces and terminals, spaces persist in `server.json`, terminals do not; never stopped by poimen). Per terminal it keeps an `alacritty_terminal` grid (`emulator.rs`, scrollback `POIMEN_SCROLLBACK`) fed from the PTY after a short coalescing (`pty.rs`); `terminal.attach` (`stream.rs`, `Client::attach`) returns a snapshot (ANSI of screen, scrollback and modes) and then raw bytes with sequence numbers, under one lock per terminal so none is lost or repeated; a client has a bounded queue and is detached on overflow, never blocking the PTY; one controller (explicit take-over), many observers. `src-tauri/src/poimen_server.rs` starts it detached when absent (`ensure_poimen_server` command, fake `Runner` in tests); the `backend` setting and the `Backend` implementation come with #153.
- `src-tauri/src/poimen_backend.rs`: `PoimenBackend`, the second `Backend` (setting `backend: "poimen"`, read at start in `lib.rs::make_backend`, command `backend_kind`): server spaces become workspaces, each terminal a tab with one pane (`map_snapshot`; wire shape of the herdr tree is kept, so the frontend types did not move yet), splits are new terminals of the same space, streams are `terminal.attach` connections (`poimen_client::AttachmentWriter` sends input and resize on the attached connection; `Backend::emulated` is true). Records reach the webview through the `tauri::ipc::Channel` of `open_terminal` (`lib.rs::channel_messages`: PTY bytes raw, the rest JSON), for both backends; there is no global `terminal` event. Agents and status are not reported yet. Never started or stopped by poimen beyond `poimen_server::ensure_running`.
- `src-tauri/crates/poimen-server/src/claude.rs`: Claude Code integration of poimen-server: `map_hook` (hook payload to status; subagent events ignored), `run_hook` (`poimen-server hook claude`: silent outside a poimen terminal, 1.5 s cap, always exit 0) and `install`/`uninstall`/`status` of `~/.claude/settings.json` (path is a parameter; entries marked `# poimen-agent-hook`; tests use temp dirs only, never the real home). The server stores hook-reported status per terminal (`terminal.report_agent`, stale `seq` dropped, `agent.status_changed`); `poimen_backend.rs` maps it onto `agent_status` of panes, tabs and workspaces and the `pane.agent_status_changed` event. See `docs/protocol.md`.
- `src-tauri/crates/poimen-server/src/copilot.rs`: Copilot CLI integration, same pattern as `claude.rs`: `map_hook` accepts camelCase and PascalCase/snake_case payloads (event from the payload or the command line, `poimen-server hook copilot <event>`), the installer owns `~/.copilot/hooks/poimen-agent-state.json`.
- `src-tauri/src/watch.rs`: one long-lived `events.subscribe`. `pane.agent_status_changed` needs a `pane_id`, and herdr rejects the whole subscription when a referenced pane is gone, so the watcher resubscribes on pane-set changes.
- `src-tauri/src/project.rs`: the project file `.poimen/config.json` (`layout`, `setup`, `teardown`, `commands[]`, `presets[]`; schema and doc in `docs/project-config.*`); tolerant `load(repo_root)` returning config plus warnings, `project_config` command. Layout precedence lives in `layout::resolve` (project file, deprecated `.agents/herdr-layout.json`, `spaces.layout`, default). `tasks` (modes and `worktreeDir`, merged over the user's in `tasks::for_project`, `get_task_modes(dir)`) is parsed with `settings::parse_tasks`; `start_setup` runs `setup` in a `setup` tab of a new space (only after `trust::gate` allowed it, from `create_space`); nothing else in it runs a command yet.
- `src-tauri/src/trust.rs`: trust in a project file: `Sources` reads `.poimen/config.json` and `.agents/herdr-layout.json` once (hash, listed commands and layout all come from that read), `gate` decides `Run`/`Strip`/`Ask` against `trustedProjects` of the user config (root to SHA-256). `create_space` asks before creating anything; any future runner of setup/teardown/commands/presets must go through `gate` and use the same `Sources`. Frontend: `src/app/trust-dialog/`, `SpaceActions.trust`, settings section "Trusted projects".
- `src-tauri/src/settings.rs`: user settings (`~/.config/poimen/config.json`, optional Ghostty config); `get_settings` command plus a polling watcher emitting `settings`. Preferences only, never UI state; frontend side is `core/settings.ts`.
- `src-tauri/src/harness.rs`: agent harness registry (`harnesses` in `config.json`, defaults `claude` and `copilot`): argv templates (`{model}`, `{prompt}`) expand per element, never through a shell; `get_harnesses` adds availability (`resolve_program` on `child_path()`). `agent_start` takes `args: Vec<String>`. Frontend: the "Agents" section of `src/app/settings-view/`.
- `src-tauri/src/schemes.rs`: user color schemes (WezTerm TOML in `~/.config/poimen/themes/`); `get_color_schemes` command plus a polling watcher emitting `color-schemes`; frontend side is `core/user-schemes.ts`.
- `src-tauri/src/github.rs`: shared GitHub client over the `gh` CLI ([ADR 0005](docs/adr/0005-github-views-and-agent-harnesses.md)): `repo_of(dir)` (GitHub `origin` only), `Client::rest` (`gh api --include`, ETag revalidation, body cached 30 s per exact path in the app cache dir) and `Client::graphql` (30 s in-memory cache per query and variables); errors serialize as `GhError` (`gh-missing`, `not-logged-in`, `offline`, `rate-limited`, `not-found`, `other`). `gh` is resolved through `gui_path.rs`; a `Runner` trait fakes the child process in tests (no network). Never logs tokens or headers.
- `src-tauri/src/github.rs`: shared `gh` client (argv, login-shell `PATH`, 60 s timeout, REST with ETag disk cache, GraphQL in-memory cache of 30 s, `GhError`). `src-tauri/src/github_pulls.rs`: `github_pulls(dirs)` (one GraphQL query per repository from `git::repo_roots`, `viewer` once; fixture `fixtures/github-pulls.json`). Frontend: `src/app/github/` (`pulls.ts` service with filters and selection signal, `github-view`); tab kind `github` in `core/editor-tabs.ts`. `src-tauri/src/github_issues.rs`: `github_issues(dirs, closed)` (GraphQL `issues` paginated up to 300 per repository with `parent`, `subIssuesSummary` and `closedByPullRequestsReferences`, plus open pull requests matched by branch `<type>/<nr>-`; fixture `fixtures/github-issues.json`); frontend `issues.ts` (levels, tree, filters, service; collapsed nodes per repository in `core/ui-state.ts`) and `issues-section` (the Issues section of the tab). `src-tauri/src/github_milestones.rs`: `github_milestones(dirs)` (REST `repos/{o}/{r}/milestones?state=open` through `github::rest`, ordered by version, `current` = lowest versioned milestone with open issues: legacy `x.y.z` first, then `M<n>` / `M<n> (x.y.z)` by `n`; fixture `fixtures/github-milestones.json`; `github_issues::unique_repos` is shared); frontend `milestones.ts` (service; the selection filters the issue tree of its repository through `IssueFilter.milestone`) and `milestones-section`.
- `src-tauri/src/transcripts.rs`: read-only Claude Code transcripts (`~/.claude/projects`): path resolution, tolerant JSONL parsing (unknown entry types and fields are skipped), running/done detection, a `Tailer` per file and a `notify` watch (`watch_dir`) emitting `subagents` events; `subagents_watch`/`subagents_unwatch` commands (agent, session and cwd come from `herdr::parse_agent_session`). `src-tauri/src/copilot.rs` is the second transcript source: GitHub Copilot CLI's `~/.copilot/session-state/<session>/events.jsonl` (main session and subagents in one file, fixture `fixtures/copilot-events.jsonl`) mapped onto the same wire types (`task` as `Agent`, `skill` as `Skill`), so the frontend has no Copilot-specific code; which agents are followed is `supportsFlow`/`flowSession` in `core/herdr.ts`. Frontend side: `core/transcripts.ts` (wire types, `transcriptItems` model reusable by other panel tabs, `Subagents` service) and `src/app/bottom-panel/` (tabs, subagent dropdown, Output tab; state in `core/ui-state.ts`). The Flow tab: the tracker also emits a `main` update (Skill/Agent calls of the main transcript with results, count of other tool calls); `core/flow-graph.ts` (pure: nodes and edges from agents, their entries and the main snapshot; nesting by tool use id, else `spawnDepth`) and `core/flow-layout.ts` (`@dagrejs/dagre`) feed `bottom-panel/flow-view.ts` (`@foblex/flow`, lazy via `@defer`). Both libraries are pinned exactly. Watches are keyed by follower (`subagents_watch { key, paneId }`, events carry the `key`): the root `Subagents` follows the panel's pane, a flow editor tab (`poimen:flow:<paneId>`, `src/app/flow-tab/`) provides its own instance for its pane and stops the watch when it is destroyed.
- `src-tauri/src/updater.rs`: self-update through `tauri-plugin-updater` (`update_check`, `update_install`; a failed install keeps the update pending). Only on a user click, no other network call; frontend `core/updater.ts` and the status bar; signing and flow in `docs/updater.md`.
- `src-tauri/src/stream.rs`: live terminals by spawning `herdr terminal session observe|control`. Use this public CLI contract; do not reimplement herdr's internal binary client protocol.
- `site/`: the public site on GitHub Pages (`https://gravionlabs.github.io/poimen/`), VitePress, self-contained (own npm lockfile, excluded from the app's eslint and prettier). The ADRs of `docs/adr/` are not published there; a dead link fails `npm run build`. Download links are resolved client-side from the latest release (`site/downloads.ts`, tested). Workflow `.github/workflows/pages.yml`: dry-run build on pull requests touching `site/`, deploy on push to `main` while the repository variable `DEPLOY_PAGES` is `true`.
- `src/`: Angular 22 (standalone components, signals) on helix-ui, built with `@angular/build` (`angular.json`), tested with Vitest. `src/app/core/` is the Tauri bridge and state: `tauri.ts` (the only `invoke`/`listen` caller), `herdr.ts` (wire types, pure helpers), `herdr-store.ts` (snapshot signals, debounced re-read), `terminal-stream.ts` (opens a stream with a `Channel`; emulated streams deliver PTY bytes as `bytes` records, no early-frame buffering). `src/app/terminal-view/` wraps xterm.js for the active editor tab (`core/editor-tabs.ts` holds tabs, preview/pinned and mode; `src/app/ui/helix-candidates/tab-bar/` is the generic tab bar, a helix-ui candidate); `src/app/sidebar/` shows the spaces tree (`hx-tree`; `src-tauri/src/git.rs` answers the read-only `repo_info` command with branch and worktree per directory); `src/app/activity-bar/` is the view rail; `src/app/notifications/` is the notification center view over `core/notification-center.ts` (in-memory list fed by `Attention` status changes); `core/ui-state.ts` holds persisted UI state (sidebar width/collapsed), never pane state. `core/attention.ts` keeps in-memory UI marks derived from herdr statuses: a pane that turns blocked while not viewed rings on its tab and sidebar row, one that turns done while not viewed counts as unread (workspace rows sum their panes); viewing the tab (active tab of a group) clears both.

## Rules

- **herdr owns state.** poimen never stores pane state of its own; snapshots from herdr are authoritative and events only invalidate them.
- **Non-destructive.** Closing a view or the app releases controllers and kills only the CLI child processes, never herdr panes. Taking over a controller requires an explicit user action.
- **Tests stay read-only.** Live tests (`#[ignore]`) may list and observe, never control, send input or create panes in the user's session.
- **Protocol drift.** herdr's API protocol is versioned (22 at the time of the spike). Keep all wire shapes in `herdr.rs` and `stream.rs`, each with a parsing test.

## Decisions

- Frontend stack: Angular 22 and helix-ui, and when a component goes to helix-ui ([ADR 0001](docs/adr/0001-frontend-stack.md)).
- Color schemes: bundled and imported schemes, a derived chrome and the `colorSchema` setting ([ADR 0002](docs/adr/0002-color-schemes.md)).
- Own terminal backend `poimen-server` next to herdr, agent status from Claude Code and Copilot hooks (proposed, [ADR 0003](docs/adr/0003-own-terminal-backend-without-herdr.md)).
- GitHub views and agent harnesses native in poimen; the herdr plugin integration (ADR 0004) is removed (accepted, [ADR 0005](docs/adr/0005-github-views-and-agent-harnesses.md)).

## CI and releases

- `.github/workflows/ci.yml` checks the frontend and the Tauri crate (with the Linux system libraries) through GravionLabs/ci `@v1`; its always-running `ci` gate job (green when the checks passed or no app files changed) and `pr-checks / PR checks` (`pr-checks.yml`: readiness, Conventional Commit title) are the checks required on `main` and `release/**`.
- Reusable workflows and actions of GravionLabs/ci are referenced at `@v1`, never `@main` or a SHA.
- Work is integrated on `release/next`: every PBI branch is cut from it and its PR targets it (squash); `main` only receives the release PR (merge commit). `release.yml` versions with GitVersion, writes `CHANGELOG.md` with git-cliff and tags `v<version>`. README "Releases" has the rules.
