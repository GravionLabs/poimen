# AGENTS.md

Guidance for humans and coding agents working in this repository. Generated text (docs, issues, commits, code) is written in US English.

## Architecture

- Default backend: `poimen-server` (`backend` setting, default `poimen`); herdr stays the alternative (`backend: "herdr"`) until it is removed. The next bullets on `herdr.rs`, `backend.rs` and `watch.rs` describe that alternative.
- `src-tauri/src/herdr.rs`: socket API client (NDJSON over the Unix socket); `SUPPORTED_PROTOCOL` (the protocol poimen is written for) lives here. Requests use short-lived connections; subscriptions keep theirs.
- `src-tauri/src/backend.rs`: the `Backend` trait (spaces, terminals, create/close/rename, split, input, neutral stream records `reset/output/resized/controller/closed` with `emulated` per stream and `CloseCode::ControllerHeld`, events, `ensure_running`); every command goes through it (`Arc<dyn Backend>`), `backend_fake.rs` is the test fake. `HerdrBackend` implements it over `herdr.rs`, `stream.rs` (`FrameMapper` maps herdr frames) and `watch.rs`; start: ping the socket, else start a detached `herdr server` (own process group, stdio null, never waited on, never stopped by poimen) and wait for the socket and the supported protocol; behind the `herdr.autoStart` setting and the `ensure_backend` command. `gui_path.rs` is the login-shell `PATH` of a GUI app (used to find and start `herdr`). Tests use a fake `Runner`; never start or stop a server in a test.
- `src-tauri/crates/`: the Cargo workspace next to the app crate (`default-members` cover all, so plain `cargo test` in `src-tauri` runs everything). `poimen-protocol` (client-neutral wire types, socket path, parsing tests; the build-time channel `CHANNEL` (`POIMEN_CHANNEL`: `stable`, or `rc` for pre-release builds) names every path two installations could share (`Channel::named`: socket, `server.json`, `%LOCALAPPDATA%\poimen-server-rc`, `~/.config/poimen-rc`, server binary `poimen-server-rc`, hook marker and Copilot hook file), and `socket_path` ignores a `POIMEN_SOCKET` that is the other channel's default; the protocol and every request/event are documented in `docs/protocol.md`, version `PROTOCOL_VERSION`), `poimen-client` (blocking client: requests over short-lived connections, `subscribe` event stream; reused by the app, a later CLI and `poimen attach`; `transport.rs` is the local socket over `interprocess`: a Unix socket, on Windows a named pipe with a marker file and a DACL, no I/O timeouts or `shutdown` there) and `poimen-server` (daemon that owns the PTYs through `portable-pty` (ConPTY on Windows, created in pass-through mode by the vendored copy `src-tauri/vendor/portable-pty`, see its `POIMEN.md`), one per user on the socket under the runtime dir (Windows: `%LOCALAPPDATA%\poimen-server`, started from a per-version copy there; a Linux AppImage starts a per-version copy under `$XDG_DATA_HOME/poimen-server/bin` and its hooks call the stable link there, `poimen_server::stage_root`/`prepare`), flat model of spaces and terminals, spaces persist in `server.json`, terminals do not; never stopped by poimen, except a confirmed restart of an outdated server and a confirmed "Quit poimen and stop server", both through `server.shutdown`). Per terminal it keeps an `alacritty_terminal` grid (`emulator.rs`, scrollback `POIMEN_SCROLLBACK`) fed from the PTY after a short coalescing (`pty.rs`); `terminal.attach` (`stream.rs`, `Client::attach`) returns a snapshot (ANSI of screen, scrollback and modes) and then raw bytes with sequence numbers, under one lock per terminal so none is lost or repeated; a client has a bounded queue and is detached on overflow, never blocking the PTY; one controller (explicit take-over), many observers. Terminal queries (OSC 10/11/12/4, DSR, DA1/DA2) are answered from that grid by `TermStream::output` (`Emulator::take_replies`) only while no controller is attached (xterm.js answers otherwise); colors come from `server.set_colors`, sent by the app (`core/terminal-colors.ts`, command `set_terminal_colors`, `terminal_colors.rs` keeps the last scheme and pushes it after `ensure_backend`). `src-tauri/src/poimen_server.rs` starts it detached when absent (`ensure_running`, called by the backend through `ensure_backend`; fake `Runner` in tests). `ping` is classified against the bundled version: older server `Outdated`, other protocol `Incompatible` (reported as `outdated`/`incompatible` in `BackendStatus`, never a second server); `restart`/`stop` (commands `restart_server`, `quit_and_stop_server`) send `server.shutdown` and are called only after the frontend confirmation (`core/server-restart.ts`, `src/app/server-dialog/`); the `backend` setting and the `Backend` implementation are `poimen_backend.rs` below.
- `src-tauri/crates/poimen-core`: Tauri-free crate with the project-side logic, shared by the app and (later) the server and the console ([ADR 0006](docs/adr/0006-poimen-console-with-herdr-scope.md)). Holds `project.rs` (parsing, entries, teardown), `trust.rs`, `templates.rs`, `remote.rs`, the pure part of `layout.rs` (`Layout`, `PaneSpec`, `Split`, `SplitDirection`, `parse_layout*`, `resolve`, `resolve_origin`, `default_layout`), what these need (`tasks.rs`, `harness.rs`, `agent_actions.rs`, `gui_path.rs`) and `settings.rs` (`parse_tasks`, `parse_space_templates`, `parse_trusted_projects`, `trust_project`/`revoke_project` and the comment-keeping config editor). The app crate keeps what needs a `Backend` in thin modules that re-export core (`pub use poimen_core::...`): `layout::apply`, `project::{start_setup, start_tab, run_entry}`; the other moved modules are used as `crate::trust`, `crate::templates` etc. through `use poimen_core::...` in `lib.rs`. Tauri commands stay in the app crate. CI `rust-server` and `windows` jobs list the crate. Also holds `git.rs`, `worktree.rs` (the #190 rules: base detection, branch template, collision rules; callable without Tauri or `Backend`; `cleanup` closes spaces through the `Spaces` trait, which the app implements over its `Backend` in `src/worktree.rs`), `github.rs` (`Client`, `Runner`, `open_issues`, `level_of`; the cache dir of `Client::rest` is a parameter, the app passes its app cache dir; fixture `crates/poimen-core/fixtures/github-open-issues.json`) and `task_start.rs` (`plan`, `space_label`; `start_tab` stays in the app's `src/task_start.rs`). The app crate re-exports them (`pub use poimen_core::...`) so its paths stay.
- `src-tauri/src/hooks.rs`: agent hooks of the poimen backend: `hooks_status` / `hooks_install` run the bundled `poimen-server integration status|install claude|copilot` through an `Exec` trait (faked in tests; tests never run the binary or touch real settings). Frontend `core/hooks-offer.ts` (offer once the backend runs, "Not now" in `core/ui-state.ts`) and `src/app/hooks-dialog/`.
- `src-tauri/src/poimen_backend.rs`: `PoimenBackend`, the default `Backend` (setting `backend`, default `poimen`, read at start in `lib.rs::make_backend`, command `backend_kind`): server spaces become workspaces, each terminal a tab with one pane (`map_snapshot`; the herdr tree wire shape is kept; the frontend reads it through `toSnapshot` in `core/herdr.ts` into the backend-neutral `Snapshot` of `Terminal`s identified by `terminal_id`), splits are new terminals of the same space, streams are `terminal.attach` connections (`poimen_client::AttachmentWriter` sends input and resize on the attached connection; `Backend::emulated` is true). Records reach the webview through the `tauri::ipc::Channel` of `open_terminal` (`lib.rs::channel_messages`: PTY bytes raw, the rest JSON), for both backends; there is no global `terminal` event. Agent start, prompt and rename work (see `poimen-client/src/agent.rs`). Never started or stopped by poimen beyond `poimen_server::ensure_running` and the confirmed `restart`/`stop`.
- `src-tauri/crates/poimen-server/src/claude.rs`: Claude Code integration of poimen-server: `map_hook` (hook payload to status; subagent events ignored), `run_hook` (`poimen-server hook claude`, run by `hook.rs`: silent outside a poimen terminal, first JSON value of stdin without waiting for EOF, 1.5 s cap, always exit 0; a report that does not get through is a line in `hooks.log` next to `server.json` and on stderr; tests in `tests/hooks.rs`) and `install`/`uninstall`/`status` of `~/.claude/settings.json` (path is a parameter; entries marked `# poimen-agent-hook`, `# poimen-rc-agent-hook` on rc, so both channels coexist and each manages only its own; the hook is silent in a terminal of the other channel (`HookEnv.foreign`); tests use temp dirs only, never the real home). The server stores hook-reported status per terminal (`terminal.report_agent`, stale `seq` dropped, `agent.status_changed`); `poimen_backend.rs` maps it onto `agent_status` of panes, tabs and workspaces and the `pane.agent_status_changed` event. See `docs/protocol.md`.
- `src-tauri/crates/poimen-server/src/report.rs`: the `poimen-server report tokens|clear|agent` CLI (`plan` is pure: args plus `POIMEN_TERMINAL_ID` to a request or `Skip`; `run` never fails the caller, usage errors exit 2). The server keeps tokens per terminal (`terminal.report_tokens`, `terminal.clear_tokens`, herdr's name and TTL rules, owner = last source, a sweeper thread in `serve` expires TTLs, `terminal.tokens_changed` event, `Terminal.tokens`); `poimen_backend.rs` puts them in the pane's `tokens`, which is where the herdr backend's `$<name>` row tokens read them. Tests: `crates/poimen-server/tests/tokens.rs`.
- `src-tauri/crates/poimen-server/src/copilot.rs`: Copilot CLI integration, same pattern as `claude.rs`: `map_hook` accepts camelCase and PascalCase/snake_case payloads (event from the payload or the command line, `poimen-server hook copilot <event>`), the installer owns `~/.copilot/hooks/poimen-agent-state.json` (`poimen-rc-agent-state.json` on rc).
- `src-tauri/src/watch.rs`: one long-lived `events.subscribe`. `pane.agent_status_changed` needs a `pane_id`, and herdr rejects the whole subscription when a referenced pane is gone, so the watcher resubscribes on pane-set changes.
- `src-tauri/crates/poimen-client/src/agent.rs`: `Client::start_agent` (types the quoted command line, resolves on the `SessionStart` report, 30 s) and `prompt_agent` (types text and Enter, refused while the agent is working or blocked); `PoimenBackend::agent_start`/`agent_prompt`/`agent_rename` use them (agent name = terminal name). Tested end to end with a fake agent script that reports through `poimen-server hook claude` (`crates/poimen-server/tests/agent.rs`).
- `src-tauri/src/project.rs`: the project file `.poimen/config.json` (`layout`, `setup`, `teardown`, `commands[]`, `presets[]`; schema and doc in `docs/project-config.*`); tolerant `load(repo_root)` returning config plus warnings, `project_config` command. Layout precedence lives in `layout::resolve` (project file, deprecated `.agents/herdr-layout.json`, `spaces.layout`, default). `tasks` (modes and `worktreeDir`, merged over the user's in `tasks::for_project`, `get_task_modes(dir)`) is parsed with `settings::parse_tasks`; `start_setup` runs `setup` in a `setup` tab of a new space (only after `trust::gate` allowed it, from `create_space`); `run_teardown`/`teardown_plan` (trust gate, `$SHELL -lc`, 5 min timeout, 1 MB output, `ProcessRunner` faked in tests) run `teardown` before `worktree::cleanup` removes a worktree and from the `project_teardown` command (palette "Project: Run teardown", result dialog `src/app/result-dialog/`); `project_entries`/`project_run` serve the palette entries (`Project: <name>`, `Preset: <name>`; `run_entry` goes through `trust::gate`; an `agent` command is handed back and sent by the frontend `core/project-entries.ts`).
- `src-tauri/crates/poimen-core/src/worktree.rs` (cleanup wrapper in `src-tauri/src/worktree.rs`): `task_worktree(repo_dir, issue, mode)` creates or reuses the git worktree and branch of an issue (mode's `branch` template, `tasks.worktreeDir` relative to the main worktree, found through `--git-common-dir`). Reuses a worktree that has the branch, adds a worktree for an existing branch, else `git fetch origin` and `-b` from `origin/release/next` or the default branch of `origin`; a path that exists otherwise is an error. Never modifies an existing worktree; git via argv only; no herdr call. The same file holds "Clean up merged tasks" (`task_cleanup(dir, focusedSpace)`, `worktree::cleanup`): candidates are the linked worktrees whose branch is the head of a merged PR (`gh pr list --state merged --json headRefName,number` through `github::Runner`); the first task mode with a `cleanup` command runs it per worktree (expanded and shell-quoted, `{pr}` added to the placeholders, in the repository root) instead of the built-in removal (close the space, `git worktree remove`, then `git branch -d` only when every commit is on a remote branch). Invariants, each tested on temporary repositories: never a dirty (uncommitted or untracked) worktree, the main worktree or the focused space's; never `main`, `master`, `release/*` or the `origin` default branch; never `--force` or `-D`; a space with terminals outside the worktree is not closed. Frontend: `core/task-cleanup.ts` (`TaskCleanup`: notice `<n> removed, <m> left`), `core/task-log.ts` and the Log tab of the bottom panel list each left worktree with reason and the command to run by hand. Entry points: palette `cleanupTasks` and the space menu (repositories only). `pr_worktree(repo_dir, nr, head_ref)` (command `pr_worktree`) does the same for a pull request: fetches `refs/pull/<nr>/head` from `origin` into local `pr/<nr>` (the head branch itself when it exists on `origin` at that commit), path `../{repo}-pr{nr}`, a branch already checked out in a worktree returns that worktree, a local `pr/<nr>` is only fast-forwarded, a foreign existing path is an error; `worktree_branches(dir)` lists worktrees for the "Open space" / "Check out" buttons of the PR view (`github/pulls.ts`).
- `src-tauri/src/changes.rs`: read-only backend of the Changes view: `changes_list(dir, scope)` (`base`: working tree against `git merge-base HEAD <base>`; `uncommitted`: against `HEAD`; files with status, rename source, counts from `--numstat -z`, binary flag, untracked from `ls-files --others`) and `changes_file(dir, scope, path)` (old and new text for the merge view; `binary` / `too_large` over 1 MB without content). `git::base_ref(dir)` (`origin/release/next`, else `origin/HEAD`, never fetches) is shared with `worktree.rs`; without a base the comparison is against `HEAD`. `dir` is validated like `create_space` (`spaces::resolve_dir`, inside a repository).
- `src-tauri/src/git_sync.rs`: fetch and pull from the explorer menu: `git_fetch` (`git fetch --prune`), `git_pull` (fetch, then `pull_refusal` refuses a dirty tree, detached HEAD, no upstream or a diverged branch with the reason, else `git pull --ff-only`) and `git_fetch_all(dir)` (`discover`: `.git` directories up to `MAX_DEPTH`, skips `node_modules` and `.claude/worktrees`, linked worktrees not listed; `PARALLEL` threads; `git-sync-progress` events; `Summary` of updated/current/failed with reasons). Runs through `changes_git::run_git` (`GIT_TERMINAL_PROMPT=0`, timeout). Frontend `src/app/explorer/git-sync.ts` (`GitSync`: status bar lines through `SpaceActions.notify`, then `HerdrStore.refreshRepos` for the ahead/behind badges); menu: Fetch/Pull on a repository, Fetch all on other directories. Reusable for source roots (#318).
- `src-tauri/src/trust.rs`: trust in a project file: `Sources` reads `.poimen/config.json` and `.agents/herdr-layout.json` once (hash, listed commands and layout all come from that read), `gate` decides `Run`/`Strip`/`Ask` against `trustedProjects` of the user config (root to SHA-256). `create_space` asks before creating anything; any future runner of setup/teardown/commands/presets must go through `gate` and use the same `Sources`. Frontend: `src/app/trust-dialog/`, `SpaceActions.trust`, settings section "Trusted projects".
- Spaces after a server restart (#579): spaces persist with their `cwd`, terminals do not. `Space.cwd` comes from the snapshot (`toSnapshot`); `workspaceDirs`/`spaceContaining` use it first, then the pane directories, `spaceRepoDir` falls back to it (`SpaceNode.repo`), `readRepos` asks for it. `rebuild_space(workspaceId, decision, confirmed)` (`lib.rs::rebuild_space_with`, shares `layout_inputs`/`plan_layout`/`run_setup` with `create_space`): a space without terminals gets its layout again in its directory (project file > template > `spaces.layout` > default, nothing stored), through `trust::gate`; unconfirmed it builds only when no agent pane (`is_agent_command` against the harnesses), no setup and nothing to trust, else `consent` with reasons; `missing` for a directory that is gone; a space with terminals is `not_empty`. Frontend `core/space-rebuild.ts` (`SpaceRebuild`, started in `App`): one check per backend session (`HerdrStore.onSessionStart`: first snapshot at start, after `poimen.disconnected` and after a started server), marks per space shown in the sidebar ("Rebuild" button, "Rebuilding…", "Directory gone", "Not rebuilt"); a confirmed rebuild asks trust through `SpaceActions.askTrust(…, without = true)`. Moves to the server with #513.
- First start: `templates::seeded` (pure: the layout with an agent pane per installed `claude`/`copilot` and a `shell` pane, the default template's agent) and `seed_values`; `settings::seed_defaults` writes `spaces.layout` and `spaceTemplates` only when the config has neither key (`has_seeded_keys`, tolerant of comments); the `seed_space_defaults` command runs once from `app.ts`, the flag `defaultsSeeded` lives in the UI state (`core/ui-state.ts`), never in `config.json`. `default_spaces_layout` returns the seeded layout for the installed agents; the Spaces page's "Default" entry is the template without `match`. An existing installation whose config has neither `spaces.layout` nor `spaceTemplates` gets the seeded layout and default template on the first start of this version, so a new space then uses the seeded layout instead of the built-in default and gets the default template's agent.
- `src-tauri/src/templates.rs`: space templates (`spaceTemplates[]` of the user config, parsed by `settings::parse_space_templates`): pure `resolve(dir, remote, templates, home)` (precedence: `dir` and `remote` > `remote` only > `dir` only, then the longest path-segment prefix of `match.dir`; case-insensitive paths on Windows and macOS; `remote` is the parsed `origin` from `git::origin_url`). `src-tauri/src/remote.rs`: pure `parse(url)` of GitHub and Azure DevOps remote URLs into `Remote` (reusable) and `agent_command` (harness registry line, error naming the template). `create_space_with` layers layout order project > template > `spaces.layout` > default and passes the agent to `build_layout`; a task's `root_command` wins.
- `src-tauri/src/settings.rs`: user settings (`~/.config/poimen/config.json`, `poimen-rc` on rc through `config_dir`, optional Ghostty config); `get_settings` command plus a polling watcher emitting `settings`. Preferences only, never UI state; frontend side is `core/settings.ts`.
- `src-tauri/src/harness.rs`: agent harness registry (`harnesses` in `config.json`, defaults `claude` and `copilot`): argv templates (`{model}`, `{prompt}`) expand per element, never through a shell; `get_harnesses` adds availability (`resolve_program` on `child_path()`). `agent_start` takes `args: Vec<String>`. Frontend: the "Agents" section of `src/app/settings-view/`.
- `src-tauri/src/agent_actions.rs`: `github.agentActions[]` (ADR 0005): prompt templates per action (`id`, `label`, `on` issue/pr/milestone, `when`, `prompt`, `run`, `harness`, `model`, `batch`) so poimen starts agents without knowing a skill. Neutral defaults (Plan, Refine, Review, Fix checks, Address review comments), merged by `id` defaults, user (`Settings.agent_actions`, `settings::resolve_github`), project (`project.rs`, only when trusted, listed by `trust.rs`); `disabled: true` removes. Invalid entries warn and are skipped; `expand` fills `{nr}`, `{nrs}`, `{title}`, `{url}`, `{repo}`, `{branch}`, `{base}` in one pass into one argv element through `harness::build_argv`. Command `get_agent_actions(root)`; the Agents page of the settings lists them read-only with their source. Config file only. Running them (#346): command `agent_action_plan(root, id, repo, items, harness, model)` (`agent_actions::plan`: `expand` with the dialog's harness/model, split into `kind` and `args` for `agent_start`); frontend `github/agent-actions.ts` (`AgentActions`: pure `matches` of `when` against issue/PR rows, `offered`; `run: worktree` (#347) = `task_worktree`/`pr_worktree` per target, then `create_space` on it (label `#<nr> <title>` / `PR #<nr> <title>`, agent in the root pane, an existing space gets a new tab), errors name the step; `run: ask` always opens the dialog with a root/worktree choice, `run` = `create_space` on the root, then per launch in parallel `terminal_create` + `agent_start` named `<label> #<nr>`, summary notice of started and failed; `batch: once` is one agent), buttons in `issue-detail/` and `pull-detail/`, the `⋯`/context popup `agent-action-menu/`, the Shift+click dialog `agent-action-dialog/` (harnesses from `get_harnesses`) and palette entries "GitHub: <label> #<nr>" for the selection or open detail. Review (#237): the default `review` is `run: ask`; for it the dialog adds mode `worktree`/`diff only` (diff only = tab `review #<nr>` at the root) and "Post review on GitHub"; the fixed suffixes (`reviewSuffix`: `gh pr diff {nr}`, `gh pr review {nr} --comment`) go to `agent_action_plan` as `suffix` and are appended to the prompt by `agent_actions::plan`.
- `src-tauri/src/schemes.rs`: user color schemes (WezTerm TOML in `~/.config/poimen/themes/`); `get_color_schemes` command plus a polling watcher emitting `color-schemes`; frontend side is `core/user-schemes.ts`.
- `src-tauri/crates/poimen-core/src/github.rs`: shared GitHub client over the `gh` CLI ([ADR 0005](docs/adr/0005-github-views-and-agent-harnesses.md)): `repo_of(dir)` (GitHub `origin` only), `Client::rest` (`gh api --include`, ETag revalidation, body cached 30 s per exact path in the app cache dir) and `Client::graphql` (30 s in-memory cache per query and variables); errors serialize as `GhError` (`gh-missing`, `not-logged-in`, `offline`, `rate-limited`, `not-found`, `other`). `gh` is resolved through `gui_path.rs`; a `Runner` trait fakes the child process in tests (no network). Never logs tokens or headers.
- `src-tauri/crates/poimen-core/src/github.rs`: shared `gh` client (argv, login-shell `PATH`, 60 s timeout, REST with ETag disk cache, GraphQL in-memory cache of 30 s, `GhError`). `src-tauri/src/github_pulls.rs`: `github_pulls(dirs)` (one GraphQL query per repository from `git::repo_roots`, `viewer` once; fixture `fixtures/github-pulls.json`). Frontend: `src/app/github/` (`pulls.ts` service with filters and selection signal, `github-view`); tab kind `github` in `core/editor-tabs.ts`. `src-tauri/src/github_issues.rs`: `github_issues(dirs, closed)` (GraphQL `issues` paginated up to 300 per repository with `parent`, `subIssuesSummary` and `closedByPullRequestsReferences`, plus open pull requests matched by branch `<type>/<nr>-`; fixture `fixtures/github-issues.json`); frontend `issues.ts` (levels, tree, filters, service; collapsed nodes per repository in `core/ui-state.ts`) and `issues-section` (the Issues section of the tab). `github_issue_detail(root, number)` (`IssueDetail`: body, state and reason, labels, assignees, milestone, parent, sub-issues, closing pull requests, `viewerCanUpdate`; fixture `fixtures/github-issue-detail.json`); the issues tree has a keyboard cursor (Up/Down, Enter opens, Escape closes) and `issue-detail/` is the pane, sharing the shell stylesheet `detail-pane.css` (overlay under 1100 px) with `pull-detail/`; bodies go through `markdown.ts` (`marked` + DOMPurify, always sanitized). `src-tauri/src/github_milestones.rs`: `github_milestones(dirs)` (REST `repos/{o}/{r}/milestones?state=open` through `github::rest`, ordered by version, `current` = lowest versioned milestone with open issues: legacy `x.y.z` first, then `M<n>` / `M<n> (x.y.z)` by `n`; fixture `fixtures/github-milestones.json`; `github_issues::unique_repos` is shared); frontend `milestones.ts` (service; the selection filters the issue tree of its repository through `IssueFilter.milestone`) and `milestones-section`. The GitHub tab shows one sub-page at a time (`github-view`: left navigation Pull requests / Issues / Milestones with counts, `UiState.githubPage` persisted, palette "GitHub: Pull requests|Issues|Milestones"); the repository filter above the navigation is `github-filter.ts` (`GithubFilter.repo`, read by the three services); one Refresh reloads the active page; selecting a milestone switches to Issues. Pull request detail (#336): `github_pull_detail(root, number)` of `github_pulls.rs` (one GraphQL query: body, branches, mergeable, check contexts, reviews, `closingIssuesReferences`, `viewerCan*` flags; fixture `fixtures/github-pull-detail.json`); frontend `github/pull-detail/` (pane right of the list, overlay under 1100 px, empty action bar for later actions; state in `GithubPulls.openDetail`, a linked issue is selected through `GithubIssues.select`). Bodies are untrusted: `github/markdown.ts` (`marked` + `DOMPurify`, pinned exactly) is the only Markdown renderer and always sanitizes.
- `src-tauri/crates/poimen-core/src/github.rs` also holds the task picker's issue source: `open_issues` (REST `repos/{o}/{r}/issues?state=open&per_page=100`, up to 300 over three pages, pull requests dropped; fixture `crates/poimen-core/fixtures/github-open-issues.json`) and `level_of` (label `epic`/`feature`/`pbi`/`bug`, else `[Epic]`... title prefix; shared with the planner views); command `task_issues(dir)`. Frontend `src/app/task-dialog/`: `TaskPicker` (service: `open(dir)` resolves a `TaskChoice` or null, filters, keys, modes from `get_task_modes`; a failed list keeps typing a number usable) and `task-dialog`. It only returns the choice. `src/app/core/task-start.ts` (`TaskStarter`) starts the task: `task_plan` (`crates/poimen-core/src/task_start.rs`: expanded command, space label `#<nr> <title>`, tab name), then for a worktree mode `task_worktree` and `create_space` on the path with `command` (replaces the root pane command of the resolved layout; an existing space is only focused), else `create_space` on the repository and `task_tab`; a failed step is shown through `SpaceActions.notify` naming it. ## Rules

- **The backend owns state** (`poimen-server`, or herdr on the alternative backend). poimen never stores pane state of its own; snapshots from the backend are authoritative and events only invalidate them.
- **Non-destructive.** Closing a view or the app releases controllers and kills only the CLI child processes, never herdr panes. Taking over a controller requires an explicit user action.
- **Tests stay read-only.** Live tests (`#[ignore]`) may list and observe, never control, send input or create panes in the user's session.
- **Protocol drift.** herdr's API protocol is versioned (22 at the time of the spike). Keep all wire shapes in `herdr.rs`, `stream.rs` and the `poimen-protocol` crate, each with a parsing test.

## Decisions

- Frontend stack: Angular 22 and helix-ui, and when a component goes to helix-ui ([ADR 0001](docs/adr/0001-frontend-stack.md)).
- Color schemes: bundled and imported schemes, a derived chrome and the `colorSchema` setting ([ADR 0002](docs/adr/0002-color-schemes.md)).
- Own terminal backend `poimen-server`, the default; herdr is the alternative until removed; agent status from Claude Code and Copilot hooks (proposed, [ADR 0003](docs/adr/0003-own-terminal-backend-without-herdr.md)).
- GitHub views and agent harnesses native in poimen; the herdr plugin integration (ADR 0004) is removed (accepted, [ADR 0005](docs/adr/0005-github-views-and-agent-harnesses.md)).
- poimen console with herdr scope: one `poimen` binary (TUI and CLI), tabs and splits owned by poimen-server, shared code in `poimen-core`; supersedes ADR 0003's TUI/CLI exclusion and "the app owns layout" (proposed, [ADR 0006](docs/adr/0006-poimen-console-with-herdr-scope.md)).
- Plugin system with a sandboxed worker and view contexts; supersedes ADR 0005's "no plugin system now" in part (proposed, [ADR 0007](docs/adr/0007-plugin-system-with-sandboxed-worker-and-view-contexts.md)).
- Remote machines over `poimen-server stdio` through SSH, no open port and no stored secret (proposed, [ADR 0008](docs/adr/0008-remote-machines-over-ssh.md)).
- Terminals owned by a stable `poimen-pty-host` per terminal, so a server update or crash keeps them (accepted, [ADR 0009](docs/adr/0009-terminal-ownership-in-a-stable-pty-host-server-updates-without-losing-terminals.md)). Numbered 0007 until 2026-11-09, when it collided with the plugin ADR.

## CI and releases

- `.github/workflows/ci.yml`: the `changes` job outputs `frontend` (`src/`, Node/Angular config), `rust` (`src-tauri/`, `rust-toolchain.toml`) and `app` (either, because the app crate embeds the built frontend); a change of `ci.yml` sets all. Jobs of an untouched area are skipped: `frontend` (check, lint, format, test, build), `rust-server` (fmt of the workspace, clippy and test of `poimen-protocol`, `poimen-client`, `poimen-server`; no Tauri libraries, no frontend build), and on `app` the `rust` job (app crate `poimen`: clippy and test with the Tauri Linux libraries and the built frontend) and `windows` (tests of the server crates, clippy of the app crate), all through GravionLabs/ci `@v1`. Its always-running `ci` gate job (needs every job; green when the checks passed or were skipped) and `pr-checks / PR checks` (`pr-checks.yml`: readiness, Conventional Commit title) are the checks required on `main` and `release/**`.
- Reusable workflows and actions of GravionLabs/ci are referenced at `@v1`, never `@main` or a SHA.
- Manual acceptance: [`docs/manual-acceptance.md`](docs/manual-acceptance.md) is the checklist per OS and package (macOS `.dmg`; Windows `-setup.exe` and `.msi`; Linux `.deb`, `.rpm` and `.AppImage`) that CI cannot run. The RC test runs beside the release PR, not as a gate before it (owner decision 2026-11-07): the installers of the pre-release are checked with it, the results go to the milestone's `release-test` issue (template `.github/release-test.md`, `release.test` in `.agents/config.json`), and the release PR links it. A gap does not block the release PR; it becomes a bug.
- Work is integrated on `release/next`: every PBI branch is cut from it and its PR targets it (squash); `main` only receives the release PR (merge commit). `release.yml` versions with GitVersion, writes `CHANGELOG.md` with git-cliff and tags `v<version>`. README "Releases" has the rules.
- Release flow: release review -> pre-release (`release.yml` dispatched on `release/next`, the channel comes from the branch: `v<version>-rc<nnn>`, GitHub pre-release, installers without MSI and RPM, no commit, no changelog, no issue closing) built as **Poimen RC** (`POIMEN_CHANNEL=rc` and the overlay `src-tauri/tauri.rc.conf.json`: identifier `dev.gravionlabs.poimen.rc`, `mainBinaryName` `poimen-rc`, sidecar `poimen-server-rc` from `scripts/prepare-sidecar.sh`, no updater artifacts or endpoint), installed next to the stable app; `RC` in the window title (`lib.rs::window_title`, `core/herdr.ts::windowTitle`) and the status bar (`app_channel`) -> release PR open at once -> RC test on the milestone's `release-test` issue beside it (`docs/manual-acceptance.md`) -> bugs in the milestone while the release PR is open become a new RC, otherwise they go to the next milestone -> human merge of the release PR. GitVersion (`tag-prefix`) and git-cliff (`tag_pattern`) ignore `-rc` tags; `releases/latest` ignores pre-releases (`docs/updater.md`). A dispatch on any other branch builds `-beta<nnn>` installers as workflow artifacts (no tag, release or commit).
