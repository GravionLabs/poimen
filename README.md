# poimen

A desktop app for AI coding agent sessions: watch and steer your terminals and agents with editor tabs, menus and a status sidebar. poimen ships its own terminal server (`poimen-server`), so no other tool is needed. [herdr](https://herdr.dev) stays supported as an alternative backend (`backend: "herdr"`) until it is removed.

*Poimen* (ποιμήν) is Greek for shepherd. `poimen-server` keeps the herd; poimen is the window you watch it through.

Site, downloads and installation guide: <https://gravionlabs.github.io/poimen/>.

> **Status: spike.** This validates the architecture. Expect rough edges.

## How it works

```
┌──────────────── poimen (Tauri) ────────────────┐
│ sidebar: spaces / terminals / agent status     │ ◄── events.subscribe (server.sock)
│ tabs: one xterm.js for the active tab          │ ──► requests, terminal.attach
└───────────────┬────────────────────────────────┘
                │ one socket under the runtime dir
                ▼
          poimen-server  (owns the PTYs, one per user, started by poimen,
                          outlives the app; agent status from Claude Code
                          and Copilot hooks)
```

- **`poimen-server` is the default backend.** The release bundles it next to the app (`externalBin`), poimen starts it detached when nothing answers and never stops it. Closing poimen, or closing a tab, only closes the view; the terminal and its agent keep running. The protocol is in [docs/protocol.md](docs/protocol.md), the setting is `backend` (see "Settings").
- **Windows.** The Windows x64 installers run the same backend: `poimen-server.exe` listens on a named pipe instead of a Unix socket, terminals run through ConPTY (`pwsh`, else Windows PowerShell, else `cmd.exe` by default), and its state lives in `%LOCALAPPDATA%\poimen-server`. The hooks run through PowerShell there. Windows support is new and covered by CI (`windows-latest`); a hands-on check of a released build follows in [#417](https://github.com/GravionLabs/poimen/issues/417). Start poimen normally, not as administrator. Known limitations are in the [installation guide](https://gravionlabs.github.io/poimen/guide/installation#windows-x64).
- **Agent status needs hooks.** Claude Code and GitHub Copilot CLI report working, blocked and done through hooks (`Stop` / `agentStop` report done, which stays until the next prompt; `SessionStart` reports idle) that call `poimen-server hook`. On the first start with the poimen backend, poimen offers to install them when they are missing (an *Install hooks* button runs `poimen-server integration install` for the agents without them; *Not now* is remembered in the UI state). You can do it by hand any time: `poimen-server integration install|uninstall|status claude|copilot [--settings <path>]`. An agent reads its hooks when it starts, so one that already ran needs a restart. A hook that cannot report writes the reason to `hooks.log` next to the server's `server.json` (Windows: `%LOCALAPPDATA%\poimen-server\hooks.log`).
- **Tokens from scripts.** Tools inside a poimen terminal (the deliver loop, your scripts) can show their state in the sidebar rows with the same tokens as `herdr pane report-metadata`: `poimen-server report tokens [--terminal <id>] [--ttl <s>] [--source <s>] name=value ...` (names of 1 to 32 ASCII letters, digits, `_` or `-`, at most 16 per call; `name=` with an empty value removes the token; the TTL applies to that call; `--source` defaults to `cli`) and `poimen-server report clear --source <s>` (removes everything that source set). Without `--terminal` it uses `POIMEN_TERMINAL_ID`, which every poimen terminal sets; outside one, or with no server running, it does nothing and exits 0 (only a usage error exits 2). The tokens appear as `$<name>` in `sidebar.rows` (for example `$deliver_step`). For an agent without hooks: `poimen-server report agent --state working|blocked|idle --source <s> --agent <name>` sets its status.

### The herdr backend

With `"backend": "herdr"` in `~/.config/poimen/config.json` poimen is a window onto [herdr](https://herdr.dev) instead. This backend is removed in a later release.

```
┌──────────────── poimen (Tauri) ────────────────┐
│ sidebar: workspaces / panes / agent status     │ ◄── events.subscribe (herdr.sock)
│ tabs: one xterm.js for the active tab          │ ──► workspace/tab/pane.list
└───────────────┬────────────────────────────────┘
                │ spawns per visible tab
                ▼
  herdr terminal session observe|control <pane>   (NDJSON frames on stdout,
                                                   commands on stdin)
                │
                ▼
          herdr server  (persistence, agent detection, worktrees, remote)
```

- **herdr is the backend.** Closing poimen, or closing a tab, only closes the view; the pane and its agent keep running. The herdr TUI keeps working next to poimen.
- **Input by default.** A pane opens for input: poimen first tries `herdr terminal session control` without `--takeover` and, as the only controller, sets the terminal size itself so the output width follows the window. If another client already holds the controller (for example the herdr terminal UI), the tab falls back to an observer (read-only) and says why, with an explicit *Take over* button (never automatic). The flat mode button in the status bar (text `Input` or `Read-only` with a pencil or lock icon; the tab shows `RO` or `IN`) toggles between input and forced read-only per tab while it is open; it is dimmed and disabled while another client controls the terminal. If another client takes the controller later, the tab goes read-only with a banner and going back to input stays your action. `terminal.autoControl: false` opens all tabs read-only again. In input mode the mouse goes to the pane application; Cmd+click (macOS) or Ctrl+click (Linux, Windows) on a link opens it in the default browser (URLs found in plain text lose trailing `. , ; : ' "` and an unbalanced closing `)` or `]`, like the herdr link-trim plugin; `Foo_(bar)` stays whole), and Shift bypasses the forwarding for text selection (Shift+drag). A plain drag selects only when the pane application tracks the mouse (for example Claude Code dialogs highlight the dragged cells); otherwise, or to get xterm's own selection, hold Shift while dragging. Pointer cells follow the size of the last frame herdr sent, so they stay correct while the pane is a different size than the window (herdr terminal UI open, right after a resize). Copy the selection with Cmd+C (macOS) or Ctrl+Shift+C, in input and read-only tabs (read-only tabs select with a plain drag). Paste with Cmd+V or Ctrl+Shift+V in input mode, as bracketed paste when the pane application asked for it. The wheel scrolls the pane.
- **Editor tabs.** Opening a pane adds a tab to one tab bar above the terminal: a click opens a preview tab (italic, replaced by the next preview), a double click pins it, a second click on an open pane activates its tab. Tabs close with the x or a middle click and reorder by drag. Only the active tab of each group keeps a stream open; hidden tabs close theirs, the pane keeps running.
- **Split editor groups.** The tab context menu (right click) splits a tab right or down into a new group with its own tab bar; `Cmd+\` / `Ctrl+\` splits the active tab right, with Shift down. Drag a tab onto another group's tab bar to move it. Dividers resize by drag or with the arrow keys; each visible group streams its active tab and its terminal size is sent to herdr when it changes. Closing the last tab of a group removes the group. A pane is open in one group at a time.
- **Angular frontend.** The UI is Angular 22 with helix-ui (light and dark follow the system); `src/app/core` is the bridge to the Tauri commands and events, `src-tauri` stays a thin shell ([ADR 0001](docs/adr/0001-frontend-stack.md)).
- **Spaces tree.** The sidebar is a helix `hx-tree` of workspaces and their panes (the herdr tab is secondary text). A badge tells agents (by kind, e.g. `cl` for claude) from plain terminals (`>_`); each row shows the status dot, git branch (`wt` for a linked worktree), directory (`foreground_cwd`) and the status message, state label or integration tokens when present. The filter field matches name, agent, branch, tab, directory and text; arrow keys, Home/End and type-ahead navigate, Enter opens. Branch and worktree come from a read-only `git rev-parse` in the pane directory (herdr's pane list has none); dirty state and ahead/behind come from one `git status --porcelain=v2 --branch` (2 s limit), refreshed on window focus, when an agent finishes and every 60 s while the window is focused.
- **Layout.** An activity bar (Spaces, Explorer, Notifications, GitHub, Deliver) sits left of a sidebar you resize by dragging its edge (arrow keys work too) and toggle with `Cmd+B` (`Ctrl+B` elsewhere). Width and collapsed state persist in poimen's own UI state (webview local storage, not the user settings file), and so do the open tabs, active tab, editor groups and split sizes: poimen reopens as it was closed, and tabs whose pane or terminal no longer exists on the backend (poimen-server or herdr) are dropped with a notice; the layout works from 720 px window width. The Notifications view lists the last 100 agent status changes (blocked, done) of all spaces, newest first, with time, tab and message; a click opens the tab and marks the entry read, "Mark all read" clears the unread marks. The list lives in memory for the session only (herdr sends no separate notification message, so entries derive from status changes).
- **Toolbar.** A thin bar at the top has a flat theme button on the right (icon and text: auto, sun or moon for `system`, `light`, `dark`). A click cycles system → light → dark; the tooltip and accessible name read like `Theme: system (click for light)`. The choice is written to the `theme` entry of `config.json` (other keys and comments stay) and applies at once; `system` follows the OS appearance live, and an external edit of the file updates the button.
- **Status bar.** The bottom bar shows the herdr connection (connected, reconnecting when the event watcher lost herdr, unreachable when a snapshot read failed, each with the reason), the count of waiting (blocked) agents (a click opens the next one) and the active tab: pane id, the mode button (input, or read-only with the reason when another client controls the pane) and terminal size.
- **Events are invalidation signals.** Every herdr event triggers a debounced re-read of the workspace, tab and pane lists, as the herdr socket API docs recommend. `pane.agent_status_changed` is applied right away.

### Creating, splitting and closing panes

Panes are managed by the backend (poimen-server or herdr), so the result shows up through its events like any other change. The method names in parentheses are the herdr API calls; poimen-server uses its own equivalents ([docs/protocol.md](docs/protocol.md)).

- **New space**: the "+" button in the Spaces header opens a dialog with a directory field (completes directories as you type), a Browse button (native folder picker) and a label (default: the directory name). It creates a space on the backend (herdr: `workspace.create` with `cwd` and `label`; poimen-server: `space.create` with `name` and `cwd`) and focuses it. A space that already has a pane inside the directory, else one labelled with the directory name, is focused instead and nothing is created. A label that another space uses falls back to the path relative to the home directory. A missing directory or a failing backend call shows the error in the dialog.
- **Close space**: right click a space in the sidebar and pick "Close space", click the x icon left of the chevron on its row (shown on hover, keyboard focus and for the active space; Tab reaches it, Enter or Space triggers it, and it neither selects nor collapses the row), or run "Close Space" in the command palette (closes the space of the active tab). It closes the space on the backend (herdr: `workspace.close`; poimen-server: `space.close`) and ends every pane in the space, so a space with panes asks for confirmation (pane and agent count) and an empty one closes right away. The tabs of its panes close, and the neighboring space is focused. The backend's error is shown when the close fails and the space stays.
- **New terminal**: File > New Terminal (`CmdOrCtrl+T`), or right click a workspace in the sidebar. A dialog asks for the directory (the workspace's pane directories are suggested; empty uses the backend's default: the space directory on poimen-server). It creates a tab in the workspace (herdr: `tab.create`; poimen-server: `terminal.create`) and opens it.
- **Split**: right click a pane in the sidebar (Split right / Split down), or its tab (New pane to the right / below). The new shell starts in the pane's directory (`pane.split`).
- **Close pane**: right click a pane in the sidebar or its tab (Close pane). It always asks first and warns when an agent is working or waiting (`pane.close`). Closing a tab with the tab's own Close entry still only closes the view.
- **Start agent**: right click a pane in the sidebar or its tab (Start agent...). A dialog asks for the agent kind, an optional name (defaults to the kind) and optional arguments (split on spaces); the pane has to be at its shell prompt (`agent.start`).
- **Rename**: right click a pane (Rename... / Rename pane...). An agent pane renames the agent (`agent.rename`), a plain terminal its label (`pane.rename`); an empty name clears it.
- **Send a prompt**: a read-only agent tab has a one-line input above the terminal (it is hidden while the tab controls the terminal, where you type into the terminal directly; the typed text is kept). It uses `agent.prompt` and waits up to 10 s for the agent to start working (or block), so it needs no controller and works in a read-only tab. It reports a stalled agent (`agent_prompt_stalled`), a timeout and an agent that waits at an approval (`agent_blocked`, nothing is sent); the text is kept after a timeout or a block.

## Requirements

- Nothing else to run: the installers bundle `poimen-server`. Only with `"backend": "herdr"`: herdr 0.9.5 or newer, installed and on the `PATH` of your login shell (poimen starts the server itself, see "Auto start" below)
- Rust 1.99.1, Node.js 26, pnpm

## Auto start

On the default backend, poimen pings the `poimen-server` socket at start (and on Retry); when nothing answers it starts the `poimen-server` next to the app executable, else the one found on the login-shell `PATH`, detached (own process group, no terminal), and waits for it. A server that answers is never restarted or stopped, and `herdr.autoStart` (default `true`, the name is kept for both backends until herdr goes away in #174) turns the start off. The rest of this section describes the herdr backend.

A server that answers is never restarted or stopped by poimen (also one started by the herdr TUI), and closing poimen leaves the server, its panes and agents running. poimen only starts a server when nothing listens: the socket file is missing or the connection is refused. A socket that is bound but does not answer `ping` within 1.5 s (a server that is still starting or busy, or one just started by the herdr TUI or another poimen) is waited for up to 10 s (measured with a clock, slow probes included) and never gets a second server; a started server that exits right away fails at once; the socket is probed once more right before the spawn. A second poimen that starts at the very same instant can still pass that check before the first one spawns (the in-process lock only serializes one poimen); whether herdr itself refuses a second server on the same socket is not documented in https://herdr.dev/llms.txt and unverified.

What is assumed about the CLI, and not verified in a live run: the command is `herdr server`, found like the terminals' `herdr` (`HERDR_BIN_PATH` if set, else the login shell's `PATH` plus Homebrew, `~/.local/bin` and `~/.cargo/bin`, one resolution for the start and for the terminals; a macOS GUI app has only `/usr/bin:/bin:/usr/sbin:/sbin`), and it stays in the foreground until stopped. poimen spawns it detached (own process group, no terminal, output discarded; a helper thread waits on the child only to reap it) and polls the socket. It inherits `HERDR_SESSION` / `HERDR_SOCKET_PATH`, so it listens where poimen looks. The unit tests use a fake runner.

Manual check on a throwaway session (not your real one): in a terminal run `export HERDR_SESSION=poimen-try`, make sure no server runs for it, start `pnpm tauri dev` from that terminal and confirm that the sidebar connects and `herdr` processes show one `herdr server`. Quit poimen and confirm that server keeps running, then stop it with the herdr command for that session. With `herdr.autoStart` off the sidebar must show "not reachable (auto start is off)" with a Retry button.

Failures show in the sidebar as one message with the reason and a Retry button, which is there in every disconnected state (start failed, auto start off, unreachable, reconnecting); there is no automatic retry loop. Start failures: `herdr` not found on `PATH`, no answer within 10 s, or a started server whose protocol is older than the supported 22. The start sits behind a `Backend` trait (`ensure_running`, `src-tauri/src/backend.rs`) and `poimen-server` uses the same path.

The command palette is a compact popup (480px, no dimming, a click outside closes it) centered on the editor area rather than the whole window; without an open tab it is centered on the window. It follows a window resize, a sidebar toggle or a panel change (such as the output panel) while open, stays inside the window, and its top edge stays put while the list filters. It is styled after JetBrains "Find Action": each row shows the title (the characters your query matched are highlighted), and the shortcut as a key cap. With an empty query the list is grouped under "Recent" (the last 5 entries you ran, kept in the window layout UI state), and "Poimen"; with a query it is one ranked list. Arrow keys skip the headings; Enter runs, Esc closes.

While a terminal has focus, only shortcuts that use Cmd are captured; every other key (Ctrl combinations on Linux and Windows included) goes to the program in the pane. Use the menu, or bind a `Cmd+` (Super) shortcut, to reach an action from a focused terminal there.

### Output panel (subagent transcripts and flow)

A panel below the editor area (View > Toggle Output Panel, the Output button in the top bar, `CmdOrCtrl+J`) shows what the subagents of a Claude Code or GitHub Copilot CLI agent are doing. They do not write to the terminal, so poimen reads the agent's session transcripts, read-only. For Claude Code: the session id and directory come from the backend (on herdr `agent_session.value` and `cwd` of `pane.list`; on the poimen backend from the agent report of the server's hooks), the files from `~/.claude/projects/<directory with every non-alphanumeric character as "-">/<session>.jsonl` and `<session>/subagents/agent-<id>.jsonl` plus its `.meta.json` (type, description, tool use id). The panel follows the active tab's agent; its dropdown lists the subagents (description, type, running or done, duration) and the selected one streams its prompt, messages, collapsible tool calls with results and the final report. It scrolls along until you scroll up ("Resume auto-scroll" jumps back). A subagent is done when its meta says `finished` or the main transcript holds a final `tool_result` for its tool use id (the acknowledgement of a background launch does not count). For Copilot CLI, the session id comes from the backend the same way (`agent: "copilot"`) and the only file is `~/.copilot/session-state/<session>/events.jsonl`: one event per line, the subagents in the same file (their events carry an `agentId`). A `skill` call is shown as a skill, a `task` call as a subagent call (`subagent.started` links the subagent to it by `toolCallId`), and a subagent is done at `subagent.completed` or `subagent.failed` (the immediate result of a background `task` does not count); a subagent's messages come from its `user.message`, `assistant.message` (text, reasoning, tool requests) and `tool.execution_complete` events. The backend watches the files with `notify` and pushes `subagents` events (no polling); only an open panel watches. Other agents (`codex`, `gemini`, ...) and plain terminals show an empty state. Both transcript formats are internal to their agents: unknown entry or event types and fields are skipped. Visibility, height and tab are UI state (`core/ui-state.ts`); the panel has two tabs, Output and Flow. Not covered: Codex and other agents, Copilot sessions in VS Code, remote machines.

The **Flow** tab draws the run as a graph, laid out automatically (left to right, no manual placement): the main agent, every `Skill` call (skill name and arguments) and every subagent (description and type), with edges in call order from caller to callee. Subagents that overlap in time (parallel) sit side by side; a subagent that calls skills or further agents nests them under itself, found by the tool use id of the call (a subagent whose call is not known is placed by its `spawnDepth`; for Copilot CLI it is derived from the `task` call that spawned it). The main node is labeled with the agent (Claude Code or GitHub Copilot CLI). Each node shows its status (running nodes are highlighted, done, failed), its duration (live while running) and, for agents, how many plain tool calls (Bash, Edit, ...) it made; those calls are counted, not drawn. A skill counts as done once its call has a result, so its duration is the call, not the work that follows. Claude Code nodes also show their tokens: total input (input + cache read + cache creation) and output, compact (`12.3k`), from `message.usage` of the assistant records, live while the node runs. The main node adds the context fill at its latest message; a skill or subagent node adds the context fill when it started ("at that time"). The node tooltip lists the four counts and the model the transcript names. A skill's tokens are the main (or calling) agent's messages between its call and its result; a subagent's come from its own `agent-<id>.jsonl` and are not counted again in the parent; a message written in several lines counts once. A missing or malformed `usage` is unknown: without usage data (a Copilot CLI pane, whose log has none) the row is hidden, never zeros. No cost in currency. Clicking a subagent node opens its transcript in the Output tab. The canvas supports zoom (buttons, Ctrl+wheel), pan (drag), fit and a minimap, and keeps its view while new nodes appear; the graph is built by `@foblex/flow` and `@dagrejs/dagre`, loaded on first use of the tab.

Known limits of the Flow tab: skill nodes show no plain-tool count (the transcript cannot attribute tool calls to a skill); a skill's duration is only call to `tool_result`, so skills are rarely "running"; the main node has no duration; subagents whose call is unknown are placed by `spawnDepth`; "failed" comes from an error result of a skill call or an agent call (in the main transcript or nested in a subagent). The Flow tab (live updates without zoom/pan reset, click-to-open, minimap, fit) is unit tested but still needs a manual check in the running app.

### GitHub pull requests

The GitHub item of the activity bar (or "Open GitHub" in the palette) opens a "Pull requests" tab (ADR 0005, `src-tauri/src/github_pulls.rs`, `src/app/github/`). It lists the open pull requests of the GitHub repositories behind the spaces and the explorer roots, read with `gh` (one GraphQL query per repository, answers cached for 30 s): repository, number, title, author, draft, checks (passed / failed / pending), review state, size (+/-) and age. Filters: Review requested (me), Mine, All; a repository filter; a text filter over title and number. Rows are selected with the checkbox, Shift+click (range) or the keyboard (Up/Down, Space). "Open in browser" opens GitHub links only. It refreshes with the Refresh button and when the window regains focus, never faster than every 30 s. A repository that cannot be read (for example "Run `gh auth login`") shows its own message; the others are still listed. Needs the GitHub CLI.

The tab's **Issues** section (`src-tauri/src/github_issues.rs`, `src/app/github/issues*.ts`) shows the open issues per repository as a tree over GitHub's native sub-issues (`parent`): up to 300 issues per repository, newest updated first. The level comes from the label `epic`, `feature`, `pbi` or `bug`, else from a `[Epic]`, `[Feature]`, `[PBI]` or `[Bug]` title prefix. An issue whose parent is closed, not read or in another repository is a root; parent cycles are ignored (the issues on one become roots). Each row shows the level, number, title, `[needs-refinement]` and `[needs-decision]` markers, `[@assignee]`, sub-issue progress and the linked pull requests (closing references plus open pull requests on a branch `<type>/<nr>-...`) with their check counts; "Open" and the PR number open GitHub links in the browser. Filters: state (open or closed, which reads again), level, label, assignee and text; a match keeps its ancestors visible. Collapsed nodes are remembered per repository in the UI state.

The **Milestones** section (`src-tauri/src/github_milestones.rs`, `src/app/github/milestones*.ts`) lists the open milestones per repository, read through REST with the ETag cache. They are ordered by version: legacy `x.y.z` titles (an optional leading `v`) first, then `M<n>` and `M<n> (x.y.z)` by `n`, each numerically (1.10.0 follows 1.2.0, M10 follows M2); names that are no version come last. The current milestone is the lowest one that still has open issues. Each row shows the due date, the open and closed counts and a progress bar. Selecting a milestone filters the issue tree of that repository to it (select it again to clear the filter).

### Deliver

The Deliver item of the activity bar (or "Open Deliver" in the palette) opens a "Deliver" tab with the running deliver loops of the repositories behind the open spaces (`src-tauri/src/deliver.rs`, `src/app/deliver/`). A loop (GravionLabs/skills `deliver-loop`) writes `.agents/deliver-loop/status.json` in its repository, atomically and against the schema `deliver-loop-status.schema.json` of GravionLabs/skills (`schemaVersion: 1`, raw URL `https://raw.githubusercontent.com/GravionLabs/skills/main/skills/delivery/deliver/schema/deliver-loop-status.schema.json`). poimen watches that file with `notify` for the git toplevel of every directory a pane is in (`deliver_watch`, events `deliver`; no polling and no GitHub call), so a change shows within a second. Read-only: poimen never writes the file.

One card per repository that has a status file: the milestone (title, link) with a progress bar and `closed/total`; the current PBI (title, link) with `step n/7`, the step text and its pull request; "Needs you", "Blocked" and "Paused" items with their reasons; the delivered PBIs with their pull requests; the release (review round, release pull request); the harness and model; and the state with its age ("running, updated 2 min ago", "finished 12 min ago"). A run whose `result` is `running` but whose `updatedAt` is older than 1 hour is shown as stale (the loop probably died). Buttons: open the milestone, issue or pull request in the browser (GitHub links only), "Focus terminal" (the agent pane of the loop inside the repository, preferring the loop's harness) and "Start loop" (shown when the loop is not running).

"Start loop" runs the task mode named `deliver-loop` (see `tasks`, a mode with `"worktree": false` and a `command` such as `["claude", "/deliver-loop", "{title}"]`) in a tab of the repository's space; `{nr}` is the milestone number (`M5` is 5), `{title}` its title and `{url}` its URL. Without such a mode the start fails with a notice naming the step.

The status bar shows `▶ M5 7/19` per running loop (`▶ 2 runs` for several; click opens the tab). A blocked item, a paused item, a needs-you item or a blocked result turns it into a warning (`⚠`). System notifications (and the click opens the tab) go out when a run becomes blocked or needs a decision (setting `notifications.blocked`) and when it opens the release pull request or ends (`notifications.done`). A status file with another `schemaVersion` shows a hint to update poimen instead of the run; an unreadable or invalid file shows its error. Both backends (poimen-server and herdr) work the same, since only the pane directories are read from them.

## Settings

Optional `~/.config/poimen/config.json`, watched and applied without a restart. Invalid entries log a warning and fall back to the default. It holds preferences only; UI state (sidebar width, open tabs) is kept by the app.

```json
{
  "theme": "system",
  "terminal": { "fontFamily": "JetBrains Mono", "fontSize": 13, "ghostty": false, "autoControl": true },
  "shortcuts": { "toggleSidebar": "Ctrl+Alt+B", "refresh": "" },
  "spaces": { "layout": { "panes": [{ "name": "editor", "command": "nvim" }, { "name": "shell", "split": { "from": "editor", "direction": "down", "ratio": 0.7 } }] } },
  "explorer": { "roots": ["~", "/srv/projects"], "showHidden": false },
  "sidebar": {
    "rows": {
      "agent": [["state_icon", { "token": "name", "bold": true }, "state_text"], ["agent", "$deliver_step", "branch", "dir"]]
    }
  }
}
```

- `theme`: `light`, `dark` or `system` (default). The toolbar button writes this entry; poimen writes only the entries its settings view and toggles change, never the rest of the file.
- `colorSchema`: the name of a bundled color scheme, `"herdr"` (the scheme named in `[theme] name` of `~/.config/herdr/config.toml`, watched like `config.json`; it fixes light or dark like a single scheme and disables the toolbar button, and `terminal`, a missing file or an unknown name warns and uses `poimen`), or a pair `{ "light": "<name>", "dark": "<name>" }` that `theme` picks from (`system` follows the OS appearance, light when it cannot be read) and that keeps the toolbar theme button working; a single scheme fixes light or dark from its background and disables that button (tooltip "Theme fixed by color schema <name>"), and a pair needs both names or it warns and uses `poimen`. Names: `poimen` (default, follows `theme`), or one of herdr's `catppuccin`, `tokyo-night`, `tokyo-night-day`, `dracula`, `gruvbox`, `gruvbox-light`, `one-dark`, `one-light`, `solarized`, `solarized-light`, `kanagawa`, `kanagawa-lotus`, `rose-pine`, `rose-pine-dawn`, `vesper`. The scheme colors the terminal and the chrome (surfaces, accent, status colors, derived from its palette) and decides light or dark from its background, so `theme` is ignored while one is set. A wrong type or an unknown name logs a warning and uses `poimen`. The values and licenses are in `src/app/themes/`.
- The settings view (the gear at the bottom of the activity bar, opens a Settings tab) has two panes like the JetBrains settings: a category tree on the left (*Appearance & Behavior*: Appearance with the color scheme below it, Notifications; *Workspace*: Explorer, New space layout, Trusted projects; *Backend*: Server, Agents) and the selected page on the right under a `Group › Page` breadcrumb. The search field above the tree (`Cmd+F` / `Ctrl+F` in the tab, Escape clears it) keeps the pages whose title or setting label matches, with their group, and highlights the matching setting on the page. The tree works with the arrow keys (Left/Right collapse and expand, Enter or Space opens a page); the selected page and the collapsed groups are UI state and survive a restart. Every control still saves immediately, without a Save button. It sets the appearance and the color scheme without editing the file: schemes are listed as dark and light with swatches, hovering or focusing one previews it live, a click or Enter saves it (leaving the list restores the saved one), and a single scheme or a light/dark pair can be chosen. Saving writes only `theme` or `colorSchema` in `config.json` and keeps your comments.
- Your own color schemes: drop WezTerm color scheme files (`.toml` with a `[colors]` table: `ansi` and `brights` of 8 colors each, `foreground`, `background`, optional `cursor_bg`, `selection_bg`, `selection_fg`, and an optional `[metadata] name`) into `~/.config/poimen/themes/` and use the name in `colorSchema`, alone or in a pair. The name is `metadata.name`, else the file name in kebab-case (`Tokyo Night.toml` is `tokyo-night`). Sources: the `colors/` directory of WezTerm or the `wezterm/` folder of [iTerm2-Color-Schemes](https://github.com/mbadolato/iTerm2-Color-Schemes) (MIT). The directory is watched and changes apply without a restart. A user scheme with a bundled name replaces the bundled one; an invalid file (or a repeated name) logs a warning naming the file and is skipped.
- `terminal.fontFamily` / `terminal.fontSize` (6 to 72, default 13).
- `backend`: `"poimen"` (default) or `"herdr"`. An existing explicit value is kept. Read at start; **a change needs a restart**. With `poimen` (the default) the app talks to `poimen-server` ([docs/protocol.md](docs/protocol.md)) instead of herdr: spaces are server spaces, every terminal is a tab, new terminals and splits are server terminals (the layout of groups and tabs stays in the app), and closing the app leaves the server and all terminals running. `herdr.autoStart` then applies to `poimen-server`. Live terminals are emulated: xterm.js tracks the mouse modes and keeps its own scrollback (`terminal.scrollback`); an observer renders at the size of the controller and is clipped. The agent of a terminal (`claude`, `copilot`) and its session come from the hooks, so icons, the Output panel and the Flow tab work as on herdr. The status bar shows the backend and the server version. Any other value warns and uses `poimen`.
- `terminal.scrollback` (default `10000`, 0 to 1000000): lines of scrollback xterm.js keeps on the poimen backend (herdr owns scrollback on its backend).
- `terminal.autoControl`: `true` (default) opens panes for input when no other client controls them; `false` opens every tab read-only.
- `shortcuts`: accelerator per action (keys in the table above), such as `Cmd+Shift+K`, `CmdOrCtrl+Alt+Left` or `F5`. It needs Cmd, Ctrl or Alt (or is an F key); an empty string unbinds the action. Unknown actions, invalid accelerators and ones already used by another action log a warning and keep the default.
- `spaces.layout`: the pane layout of a **new** space (a focused existing space is not changed). It uses the schema of the herdr-plugins `layout-bootstrap`: `panes[]` with `name`, optional `command` (typed into the pane, then Enter) and, from the second pane on, `split.from` (an earlier pane, default the previous one), `split.direction` (`right` or `down`) and `split.ratio` (0 to 1, default 0.5, the share the split pane keeps); the first pane is the root pane of the space. Each pane starts in the space directory and is renamed to its `name`. The layout is chosen automatically: `layout` of `.poimen/config.json` at the repository root ([docs/project-config.md](docs/project-config.md)), else the deprecated `.agents/herdr-layout.json` (read until 1.0, with a warning), else `spaces.layout`, else the built-in default (`agent` left 60 % running `claude`, `tests` right top, `shell` right bottom). An invalid project file shows a warning in the status bar naming the file and the problem, and the space gets a single pane; an invalid `spaces.layout` logs a warning and uses the default. The **New space layout** section of the settings view edits it without touching the file by hand: it shows `spaces.layout` or the built-in default (marked "Default"), and per pane its name, command (empty = shell) and, from the second pane on, split from / direction / the share the split pane keeps (0.1 to 0.9); panes can be added, removed and moved, problems show inline, and only a valid layout can be saved. "Save" writes only `spaces.layout` (comments kept), "Reset to default" removes it.
- `spaceTemplates`: directory-matched templates for a **new** space, an array of `{ "name", "match": { "dir"?, "remote"? }, "agent", "model"?, "layout"? }`. `name` is required and unique; `match.dir` is an absolute directory or starts with `~`; `match.remote` is `{ "provider": "github", "owner" }` or `{ "provider": "azure-devops", "organization", "project" }` and is compared with the `origin` of the repository (GitHub HTTPS/SSH, `dev.azure.com`, `<org>.visualstudio.com`, `ssh.dev.azure.com`; URL-encoded names are decoded; owner, organization and project compare case-insensitively); at least one of `dir` and `remote` is required, and with both set both must match; `agent` is a harness id from `harnesses`; `model` is optional; `layout` uses the schema of `spaces.layout`. One template applies: a match on both `dir` and `remote` beats `remote` only, which beats `dir` only; among equals the longest `match.dir` (path-segment prefix: `~/src/a` does not match `~/src/ab`; case-insensitive on Windows and macOS) wins. A directory without a repository or without `origin` matches by `dir` only. Layout order: project `layout`, then the template `layout`, then `spaces.layout`, then the built-in default. The template's agent (and model) is typed into the root pane of the layout when that pane has no command of its own (the built-in default's `claude` counts as none); a task's command still wins. An unknown harness or one whose program is not on the `PATH` creates the space without the agent and shows a warning naming the template. Invalid entries warn and are skipped. Templates are user config and need no trust. The **Spaces** page of the settings view edits them without touching the file by hand: it lists name, match and agent, and a form edits one template (name, directory with a folder picker, remote, agent from the configured harnesses with unavailable ones marked, model from the harness's `models`, and a layout that starts from none, the built-in default, `spaces.layout` or a project preset, with the panes editable as name and command). The form checks what the backend checks (unique name, a directory or a remote, a known harness, a valid layout), the backend's `spaceTemplates` warnings show on the page, and a save writes only `spaceTemplates`. The new-space dialog shows `Template: <name> · <agent>` for the typed directory, or `Template: default`.
- `trustedProjects`: repository root to the SHA-256 of the project file (`.poimen/config.json`, else the deprecated `.agents/herdr-layout.json`) you trusted. The commands of a project file (layout panes, setup, teardown, commands, presets) run only while its hash matches; otherwise a dialog lists every command and offers "Trust and run", "Run without project commands" (panes are built but nothing is typed) and "Cancel". A changed file revokes the trust. The **Trusted projects** section of the settings view lists the roots with a "Revoke" button; `spaces.layout` needs no trust. See [docs/project-config.md](docs/project-config.md#trust).
- `tasks`: how an issue becomes work (the modes are read by the task start; there is no settings view yet). `modes[]` with `name` (unique), optional `worktree` (default `true`), `branch` (template, default `{type}/{nr}-{slug}`) and `cleanup`; `worktreeDir` (template relative to the repository root, default `../{repo}-{nr}`). A mode starts an agent or runs a command. Agent mode: `harness` (an id of `harnesses`, default the first one, `claude`), optional `model` and `prompt` (template, default `Work on GitHub issue #{nr}: {title} ({url})`); the argv comes from the harness (see `harnesses`). Command mode: `command` as an argv array, e.g. `["pwsh", "Invoke-DeliverLoop.ps1", "-Target", "{nr}"]`; `command` excludes `harness`, `model` and `prompt`. `cleanup` is an argv array too. Placeholders expand per array element and no shell is involved, so a title with quotes, `$()`, `;` or spaces stays one argument. Without `modes` there is one mode `agent`: worktree, the default harness and prompt. Placeholders: `{nr}`, `{title}`, `{url}`, `{repo}`, `{slug}` (title without `[Level]`, type and scope, lowercase, `-` for other characters, at most 40), `{type}` (`feat`, `fix`, `refactor`, `docs`, `build`, `chore`, `test`, `perf`, `ci`, else `issue`), and in `command`, `cleanup` and `prompt` also `{branch}`; in `command` and `cleanup` also `{prompt}` (the default prompt), in `cleanup` also `{pr}` (the merged pull request). Deprecated, accepted for one release with a warning (`tasks.modes.<name>: string command is deprecated, use harness + prompt or an argv list`): `command` and `cleanup` as a shell string, whose values are single-quoted. An invalid entry (unknown placeholder, `command` with `harness`, malformed `command`, duplicate `name`) logs a warning and is skipped.
- `harnesses`: the agent CLIs poimen can start, as a map from id to `command` (argv array), `modelArgs` (argv template with `{model}`, appended only when a model is chosen), `promptArgs` (argv template with `{prompt}`), `models[]` and an optional `defaultModel`. Templates expand per argv element and never go through a shell, so a prompt with spaces, quotes or newlines stays one argument. Defaults: `claude` (`--model {model}`, prompt as the argument; models `opus`, `sonnet`, `haiku`) and `copilot` (`--model {model}`, `-i {prompt}`; models `auto`, `gpt-5.4`). The Settings view lists them under "Agents" with availability (read-only; edit `config.json`). An invalid entry becomes a settings warning and is skipped.
- `herdr.autoStart` (default `true`): at start, and on Retry in the sidebar, poimen pings the socket of the backend in use; when nothing answers it starts `poimen-server` (default backend) or, with `"backend": "herdr"`, runs `herdr server` (socket from `HERDR_SOCKET_PATH`, `HERDR_SESSION`) in the background and waits up to 10 s for it. See "Auto start" above. Off: poimen never starts a server and just shows that the backend is unreachable. A wrong type warns and keeps `true`. The **Server** page of the settings view has the checkbox (it applies to the backend in use); it writes only `herdr.autoStart` and keeps your comments.
- `notifications.blocked` / `notifications.done` (default `true` each): a system notification (macOS and Linux) when an agent turns blocked (waits for you) or done, unless its tab is visible and the poimen window is focused. The first one asks for the notification permission. Clicking a notification brings the poimen window to the front (shown, restored, focused) and opens the pane's tab. On macOS the notification backend only reports a click on a notification that has a button, so every notification carries an extra "Open" button (clicking it does the same). A done notification goes out only after the agent stayed done for 5 seconds (an agent can report done for a moment between tool calls, seen with herdr) and only once per pane until you have looked at its tab. A wrong type warns and keeps `true`. Both switches are also in the settings view (section Notifications).
  - **Dock badge:** the dock icon shows how many agents wait for you (blocked) and clears at 0; it follows the agent status events of the backend. Platforms without dock badges ignore it (a console warning).
  - **Using the herdr `agent-notify` plugin instead:** it notifies from herdr itself, so with both on you get two notifications per event. Use one: either keep poimen's (and disable `agent-notify`), or keep `agent-notify` and set `"notifications": { "blocked": false, "done": false }`. `agent-notify` runs even when poimen is closed; poimen's notification knows which tab is visible and jumps to it.
- `explorer.roots`: the roots of the Explorer view (second item of the activity bar), a non-empty list of absolute paths; a leading `~` is the home directory (default `["~"]`). The tree shows directories only, sorted by name, and lists a folder when it expands; an unreadable folder shows no children. `explorer.showHidden` (default `false`) shows directories that start with a dot. The active view and the expanded folders are UI state and survive a restart. Double-clicking a folder, or "Create space here" in its context menu, creates a space for it (with the configured layout) or focuses the existing one; folders that are the working directory of a pane of a space carry a dot. The filter field in the head ("Filter folders"; `Cmd+F` / `Ctrl+F` in the explorer focuses it, Escape clears it) keeps the folders whose name contains the text (case-insensitive, match highlighted) together with their ancestors, which show expanded; it only looks at folders that are already loaded (roots and expanded folders) and never changes the remembered expanded folders. A wrong type logs a warning and keeps the default. The **Explorer** section of the settings view manages the roots without editing the file: "Add folder…" (native folder picker), remove (not the last one), move up/down, and "Show hidden folders"; it writes only `explorer.roots` / `explorer.showHidden` (paths under the home directory as `~/…`) and keeps your comments.
- `sidebar.layout`: `"tree"` (default) shows workspaces with their panes below; `"split"` shows two lists as in the herdr sidebar: **Spaces** (the workspaces, the selected one lists its terminal panes) and **Agents** (every agent pane across the workspaces in herdr order, with its workspace name, rendered with `sidebar.rows.agent`), stacked with a divider line between them: drag the divider (or focus it and use the arrow keys, Shift for bigger steps) to resize the two lists, each keeps at least 15 % and scrolls on its own, and the ratio survives a restart (UI state, default 50/50). The toggle button next to the title "Spaces" switches it and writes this entry; the selected workspace of `split` is UI state, not a setting. Anything else logs a warning and uses `tree`.
- `sidebar.rows.workspace` / `sidebar.rows.agent` / `sidebar.rows.terminal`: what a row of the Spaces tree shows, a list of lines, each a list of tokens (a name, or `{ "token": "<name>", "bold": true, "dim": true }`). Tokens: `state_icon` (status dot), `name`, `state_text`, `agent`, `title` (the `deliver_step` token, else the terminal title), `branch`, `dirty` (`●3`: changed plus untracked files, empty when clean), `sync` (`↑2 ↓1` against the upstream, empty when even or without one), `pr` (the open or merged pull request of the branch: `#123` plus ✓ passed, ✗ failed or … pending checks, `merged` for a merged one, dimmed for a draft; tooltip with title and check counts; a click opens it in the browser; read through `gh` with the 30 s cache, empty without `gh`, a login or a GitHub `origin`, and for `main`, `master`, `release/*` and detached HEADs; not in the default layout), `notification` (latest notification text of the agent, e.g. the permission question, from the Claude Code and Copilot CLI hooks; one line with an ellipsis, the full text in the tooltip; on a workspace row the newest of its agents; cleared when the agent works again; empty on the herdr backend; not in the default layout), `dir` (short path), `tab`, and `$<name>` (the herdr token `<name>` of the pane). On a workspace row `branch`, `dirty`, `sync` and `dir` are the values all its panes share; on a pane row they show only when they differ from the workspace. Empty values and values equal to an earlier one on the row are skipped. The filter matches the shown values. The default is `workspace`: `[["state_icon","name","state_text","branch","dirty","sync","dir"]]`, `agent` and `terminal`: `[["state_icon","name","state_text"],["agent","title","branch","dir"]]`. An unknown token, a wrong type or an empty list logs a warning and keeps the default of that row type.
- `terminal.ghostty`: `true` takes font family, size, `background`, `foreground`, `cursor-color`, `selection-background`, `selection-foreground` and `palette = N=#rrggbb` (0 to 15) from `~/.config/ghostty/config`. The colors lie over the terminal colors of the color scheme (the chrome stays from the scheme); explicit entries above win. A Ghostty `theme = <name>` is not read.

## Releases

- Work branches are cut from `release/next` and merge into it; the `Release branch` workflow keeps the release PR `release/next` → `main` open and current (`github-release` skill).
- Work PRs into `release/**` are **squash** merged; their PR title must be a Conventional Commit (`pr-checks` title job) and becomes the one commit of the change. The `release` ruleset also allows `merge`, but only for the back-merge of `main` into `release/next` after a release (a squash drops the ancestry, `github-release` skill); never merge a work PR that way.
- A release is made by merging that release PR into `main` with a **merge commit, never squash** (the `main` ruleset allows only merge commits), so GitVersion sees every commit. A hotfix PR into `main` is merged the same way, and every commit of it must be a Conventional Commit.
- The version comes from Conventional Commits (`versioning/determine-version` of GravionLabs/ci, `GitVersion.yml`): `fix:`/`perf:`/`revert:` → patch, `feat:` → minor, `type!:` or `BREAKING CHANGE:` → major. A release with only fixes is a patch, one with a `feat:` a minor.
- While the version is 0.x, use **no** `!` and no `BREAKING CHANGE:` until 1.0 is intended: either one jumps the version to 1.0.0.
- On the push to `main`, `.github/workflows/release.yml` runs the CI checks, determines the version, commits `CHANGELOG.md` (git-cliff, `cliff.toml`) to `main`, tags `v<version>`, creates the GitHub Release and closes the issues the release delivered. The changelog commit is pushed with the `GH_PAT` secret (a repository admin, bypass actor of the `main` ruleset).
- `release.yml` writes the released version into `package.json`, `src-tauri/Cargo.toml`, `Cargo.lock` and `src-tauri/tauri.conf.json` and commits it (`chore(release): set version <v> [skip ci]`) before the changelog commit, so the tag points at manifests carrying the released version. Between releases they hold the previous release's version.
- The status bar shows `frontend poimen <version>` (the Tauri app version from `tauri.conf.json`) and `backend poimen <version>` (poimen-server) or, on the herdr backend, `backend herdr <version>` (socket `ping`; `backend herdr ?` when unreachable or too old; warning colour and tooltip when the protocol differs from the supported 22). The `tauri.conf.json` version, set by `release.yml`, is the source of truth; `backend herdr <version>` is shown without a protocol check when herdr reports no protocol. The app and the `poimen-*` crates inherit one workspace version, so both labels agree after a release (`src-tauri/tests/versions.rs` guards it). Local builds show the last released version.
- The same run builds the installers after the release is created and attaches them to the GitHub release `v<version>`: Linux x64 (`.deb`, `.rpm`, `.AppImage`), macOS arm64 (`.dmg`; no Intel build) and Windows x64 (`.msi`, `.exe`). Their names and the status bar carry the released version. They are **not code-signed** yet ([#45](https://github.com/GravionLabs/poimen/issues/45)): macOS Gatekeeper and Windows SmartScreen warn on first start. They come from the `GravionLabs/ci/tauri/installers@v1` action (the building block of `tauri-app.yml`; the workflow itself assumes a root Cargo workspace and does its own versioning and release). A manual `workflow_dispatch` run of `release.yml` on a branch (without the input `prerelease`) builds the same matrix with the version `0.0.<run number>` and creates no tag or release; pull requests never build installers.
- **Pre-release for the manual acceptance.** Run `release.yml` with `workflow_dispatch` on `release/next` and `prerelease: true`. GitVersion gives `<next stable>-rc.<n>` (`n` = commits since the last stable tag, so each commit has its own number), the run tags `v<version>` on `release/next`, creates a GitHub **pre-release** and attaches the installers: Linux `.deb`, `.AppImage`, macOS `.dmg`, Windows `-setup.exe`; no `.msi` (WiX needs a numeric version) and no `.rpm` (an RPM version allows no `-`). It commits nothing to `main` or `release/next`, does not touch `CHANGELOG.md` and closes no issues. GitVersion (`tag-prefix` in `GitVersion.yml`) and git-cliff (`tag_pattern` in `cliff.toml`) ignore `-rc` tags, so the next stable version and its changelog are the same with and without pre-releases. Stable installs never get a pre-release as an update, see [docs/updater.md](docs/updater.md).
- **Release flow:** release review of `release/next` -> pre-release (above) -> manual acceptance on its installers ([`docs/manual-acceptance.md`](docs/manual-acceptance.md), #432) -> gaps become bugs on `release/next` and a new pre-release -> `github-release finish` -> merge of the release PR (the stable release).
- The installers also carry signed update packages and `latest.json` (secrets `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, `src-tauri/tauri.bundle.conf.json`); the status bar offers **Check for updates**, see [docs/updater.md](docs/updater.md).
- Tags are `v<major>.<minor>.<patch>`, as in the other GravionLabs repositories; milestones are named `M<n>` while open and get the version when the release is tagged (`M<n> (x.y.z)`); the milestones up to `v0.7.1` were renumbered in release order (`M1 (0.2.0)` to `M7 (0.7.1)`).
- The public site (`site/`, VitePress, published to GitHub Pages by `.github/workflows/pages.yml`) is described in "Site" below.
- The rulesets `main` and `release` are created by `scripts/setup-rulesets.sh`.

## Site

<https://gravionlabs.github.io/poimen/>: landing page, download links of the latest release (resolved from the GitHub API when the page opens, falling back to the release page), installation guide and feature overview; the decision records of `docs/adr/` stay in the repository and are not published.
